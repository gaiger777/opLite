진단: `2026-11-27-ux-audit.md`(화면 3천여 장·코드 근거, 화면별 문제·용어 사전·그림 안). 이 설계는 그 진단의 §6 단계를 받아 결정만 적는다 — 세부 근거·문구 예는 진단 문서를 본다.

## 사용자 요청 (2026-11-27, 우선순위 가장 높음)

- "각 기능 별 설정하는 부분이 설명도 없고 뭐 하는 기능인지 어떻게 동작하는 지.. 사용자관점 UI/UX가 너무 형편없음."
- "활동 작업 오류 내용은 어떤 오류인지 실패 원인은 뭔지 내용이 짤리고 작업 들어가서 봐도 선언 묶음이 뭐하는건지 모르겠음."
- "뭐든 메뉴가 다 어려움. 최대한 그림으로 그리든 쉽게 설명을 해주던 대대적인 UI/UX 개편이 필요해 보임."
- "화면 해상도에 따른 라인 줄바꿈 현상도 나오고."
- "가상 머신 만들기. 드래그앤 드랍도 뭔가 그림으로 표현되던가 좀 더 뭔가 쉽게 표현되어야 하며 최대한 마우스 스크롤 없이 처리되어야 함."
- 앞서: 메뉴는 탭 말고 2단 구조, 인프라 지도 고도화·노드당 VM 100개 이상, VM 만들기 획기적으로, 기능을 연관관계로 묶기, 이미지 업로드 스트리밍 + 진행 정보.

## 목표와 수용 기준

1. **오류가 다 보이고 왜 실패했는지·어떻게 고치는지 안다.** 작업 목록·알림 센터에서 오류가 잘리지 않는다(2줄 + 펼침). 작업을 누르면 상세 서랍(원문 전체·복사·대상 이름·노드·요청자·시각·단계·원인·해결). 주요 실패 20경로는 코드별 원인·해결 문구.
2. **메뉴는 2단 사이드바 하나.** 영역 탭·보기 전환 없음(상세 화면 안 탭만). 묶음 9개(진단 §1.3), 옛 경로는 모두 새 위치로 넘김(즐겨찾기·문서 링크 안 깨짐), ⌘K 찾기.
3. **모든 설정 칸에 설명.** 칸마다 한 줄 설명(오류가 나도 유지) + ⓘ 도움말 패널(무엇·어떻게 동작·언제 쓰나·그림/예). 화면마다 "이 화면은?" 소개. 전문 용어는 쉬운 말(진단 §2.15 사전) — 원어는 괄호나 도움말에.
4. **VM 만들기는 그림 한 화면.** 용도 카드 → VM 그림(본체에 CPU·메모리·디스크·NIC·ISO를 클릭이나 끌어 붙임) + 오른쪽 고정 요약·검사(노드 여유 막대)·만들기. **1440×900에서 문서 높이 ≤ 900(스크롤 0)**, 1280×720에서는 왼쪽 부품 목록만 스크롤. 폼과 빌더를 하나로.
5. **해상도에서 안 깨짐.** 1024·1280·1440·휴대폰 390에서 문서 가로 넘침 0, 표 넘침은 핵심 열 + 펼침 행, 행 단추는 1개 + ⋯, 탭 낱말 잘림 없음.
6. **선언 묶음·변경 기록·감사가 사람 말.** "코드로 관리(YAML)" 이름·그림 설명·파일↔실제 비교, 감사는 "POST /…" 대신 동작 이름.
7. **지도 VM 100개 이상 + 업로드 진행.** 지도 LOD(상태 막대 → 격자 → 이름), 꺼진 VM 접기, 칸 예산 다시 24 KiB 안. 업로드는 조각 업로드(이어 올리기)·속도·남은 시간·단계, 작업 센터 항목.

시험: 단계마다 `ux77/shoot2.cjs`(또는 `ui-shots/shoot.cjs`)로 폭 4 × 언어 2 × 테마 2 판을 다시 찍어 진단의 측정(`docOverflowX`, `scrollers.dx`, `covered`, `docH`)이 기준을 지키는지, 그리고 vitest·axe.

## 결정

- **단계 순서**(진단 §6 권고 그대로): 77-1 오류가 보이게 → 77-3 2단 사이드바 → 77-4 도움말·쉬운 말 → 77-5 VM 만들기 한 화면 → 77-2 실패 원인·해결(서버) → 77-6 해상도·밀도 → 77-7 선언 묶음·기록 → 77-8 지도 100+·업로드.
  단계마다 리뷰·스크린샷 비교를 하고 main에 합친다(한 번에 큰 가지로 오래 두지 않음 — 사용자가 빨리 보게).
- **2단 사이드바**: 진단 §1.3 묶음 9개 + 관리. 펼침 상태 사용자별 기억(localStorage, 실패해도 기본 펼침). <1280은 아이콘 레일 + 펼침 창, 휴대폰은 서랍. 2FA·API 토큰은 사용자 메뉴. 경로는 지금 URL을 되도록 유지하고 바뀌는 것만 넘김(`nav.ts` 한 곳의 대응표, 진단 §1.4).
- **도움말 부품**: `Field`에 `help`(늘 보이는 한 줄)·`info`(ⓘ → 오른쪽 도움말 패널 — 제목·설명·그림(SVG 작은 도식)·"자세히(문서)") 키. 문구는 i18n에 `help.<화면>.<칸>` 키로(ko·en). 그림은 손 SVG 몇 가지(HA 펜싱, 백업 증분 사슬, 복제·DR, SDN 라우터·SNAT, 배치 규칙, 선언 적용) — 늦게 읽기.
- **Task 실패 원인(77-2)**: 서버 `TaskStatus.failure?: {code, params, step?, retryable}`(옛 `error` 문자열 그대로 둠 — 호환), `started_at`·`finished_at`·`requested_by`(이름)·`target_name`. 웹은 `taskErrors.<code>.{title,cause,fix}` 사전, 없으면 원문. 이벤트 로그는 범위 밖(다음).
- **요청자 이름은 그 Task를 읽는 사람에게 보인다**(77-1 리뷰 I4): Task 레이블 `requested-by-name`을 사용자 목록 권한과 상관없이 보인다. vSphere 최근 작업 창처럼 "누가 했는지"는 운영 추적에 필요하고, Task를 읽을 수 있으면 그 대상도 이미 보는 사람이다. 사용자 목록·역할은 지금처럼 `user` 읽기 권한이 있어야 보인다.
- **VM 만들기(77-5)**: 진단 §4.3 그림을 따름. 서버에 배치 미리보기(dry-run — 기존 `vm-checks`/스케줄러 점수 재사용) 하나. 프리셋 리소스는 만들지 않고 템플릿·이미지 + 용도 카드(웹 고정 목록)로.
- **업로드(77-8)**: 조각 업로드 API(`POST /uploads` → `PUT /uploads/{id}?offset=` → `complete`), raw·ISO는 대상에 바로 씀, qcow2·vmdk는 임시 후 변환 진행을 Task 진행으로. 옛 한 번 올리기 API는 남김.
