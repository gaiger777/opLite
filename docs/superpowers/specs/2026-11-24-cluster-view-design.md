## 1. 목적

노드 표(인프라 › 노드)는 정확하지만 **한눈에** 보이지 않는다. 당직자가 알고 싶은 것은 "어느 노드가 뜨거운가, 어디가 꺼졌나, 무엇이 지금 옮겨 가나, 이 랙이 죽으면 무엇이 서나"이고, 지금은 노드 표·VM 표·최적 배치·경보를 오가며 머리로 합친다. 계획 70은 이것을 **2.5D 클러스터 지도** 한 장으로 보인다:

- **노드는 아이소메트릭 블록**, 장애 영역(노드 레이블 `zone`, 있으면 `rack`)마다 **바닥 판**에 모은다. 블록의 윗면 색이 부하(CPU·메모리 중 높은 것), 옆면이 채움 막대(왼쪽 메모리·오른쪽 CPU)다.
- **VM은 노드 위에 쌓인 타일**, 상태 색(켜짐·꺼짐·실패·바뀌는 중·옮기는 중)과 HA 표시. 배치되지 않은 VM은 옆의 "배치 안 됨" 판.
- **상태가 모양으로 보인다**: 오프라인(빛 바램·빨간 테두리·꼬리표), 유지보수(줄무늬 띠), 비우는 중, 얼림, 증인 노드(좁은 기둥), 리더, 경보 수.
- **라이브 마이그레이션은 원본에서 대상으로 가는 휜 화살표**가 움직이고(동작 줄이기면 멈춘 화살표), 진행률을 적는다. 최적 배치 추천은 옅은 점선 화살표로(레이어).
- **스토리지·네트워크·HA·추천은 켜고 끄는 레이어**다. 기본 그림은 조용하게.
- **가리키기·초점**은 작은 카드(이름·상태·CPU·메모리·VM 수·경보), **누르기**는 지금 있는 미리 보기 서랍(`NodePeek`·`VmPeek`)과 그 자리의 동작(VM 전원·옮기기, 노드 유지보수·비우기), 서랍의 "열기"가 상세 화면.

**진짜 3D가 아니다**: WebGL·three.js·react-three-fiber·캔버스 3D 엔진을 쓰지 않는다. 계획 67이 만든 **SVG 아이소메트릭 그림 조각**(`web/src/components/iso/` — 투영·면 밝기·깊이 정렬·끌기/확대)을 그대로 쓰고, 계획 67 §18이 미룬 "VM 블록을 한 경로로 그리는 최적화"를 여기서 한다.

원칙: **서버는 바뀌지 않는다**(새 API·리소스·Raft 칸·기능 플래그 없음 — §5). 지도는 이미 있는 목록·watch·`/placement`·`/cluster`·`/alerts`를 읽는다. 첫 화면 묶음(eager bundle)에는 i18n 문구와 보기 하나만 더해지고 그림 코드는 늦게 읽는 조각이다.

## 3. 지금 있는 것 (계획 69 끝)

## 4. 확인한 사실 (브라우저·SVG)

- **원소 수가 비용이다**: SVG는 원소마다 스타일·히트 영역·레이아웃 객체가 생긴다. 토폴로지 기록(원소 11,400개)에서 끌기는 견딜 만하나 첫 그리기·테마 바꾸기가 눈에 띄게 느렸다. 같은 색의 다각형 여럿은 `<path d="M…Z M…Z">` 하나로 그릴 수 있고(채움 규칙 `nonzero` — 겹치지 않는 면이라 같은 결과), 이러면 노드마다 "색 × 면" 수만큼만 원소가 생긴다.
- **깊이 차례**: 합친 경로 안에서는 그리는 차례가 경로 순서다 — 한 노드 위의 타일 묶음은 아래 층 → 위 층, 뒤 → 앞으로 경로 조각을 늘어놓으면 된다. 같은 색끼리 합치면 서로 다른 색 타일 사이 겹침 순서가 깨지므로, **면마다 층별로** 합친다(층 안에서는 타일이 겹치지 않는다 — 간격이 있다). 층 수 × 색 수 × 면 3 = 노드마다 많아야 4 × 5 × 3 = 60, 실제로는 색이 둘셋이라 20 안팎.
- **누르기 적중**: 합친 경로는 원소 하나라 어느 타일인지 모른다. 배치가 순수 셈이므로 화면 좌표 → 세계 좌표(`iso`의 역)로 바꾸어 노드·층·칸을 셈으로 찾는다(위 층부터 — 보이는 것이 위). 키보드 초점과 가리킨 타일만 따로 원소(테두리 하나)로 덧그린다.
- **움직임**: SVG `stroke-dashoffset` CSS 애니메이션은 레이아웃을 다시 하지 않는다(그리기만). 화살표 수는 진행 중인 마이그레이션 수(보통 몇 개)다. `@media (prefers-reduced-motion: reduce)`에서 애니메이션을 끄고 멈춘 점선 화살표 + 진행률 글만 남긴다(계획 61 §6 움직임 토큰과 같은 규칙).
- **CSS 묶음**: Tailwind는 모든 파일을 훑어 한 CSS에 넣으므로 늦게 읽는 조각의 새 유틸 클래스도 첫 화면 CSS에 들어간다. 그래서 지도 전용 모양(애니메이션 키프레임·무늬)은 조각 안 SVG `<style>`과 `<defs>`(무늬 `pattern`)에 두고 새 Tailwind 클래스는 지금 쓰는 것만 쓴다.
- **휴대폰**: 390px 폭에서 100 노드 그림은 맞추기 배율이 작아 타일이 1~2px이다 — 자세히 보기 단계가 "요약"으로 내려가야 읽힌다. 손가락으로 끌기·두 손가락 확대는 `useIsoViewport`가 이미 한다(`touch-action: none`은 그림 영역에만).

## 5. 전체 구조

```
인프라 › 노드 탭   [노드 /nodes] [지도 /cluster/map] [클러스터 /cluster]     ← nav.ts 보기 하나 더함
                         │ (늦게 읽는 조각 web/src/clusterMap/)
   ┌─────────────────────┴──────────────────────────────────────────────┐
   │ useClusterMapData():  useList(node·vm·storage-pool)  watch          │
   │                       GET /placement (15초, PLACEMENT_KEY 함께 씀)   │
   │                       GET /cluster (30초, 403이면 리더 없이)          │
   │                       useAlerts() (30초) · useTaskIndex()            │
   │         └→ toModel() — 순수: ClusterModel {groups, nodes, vms, moves} │
   │ layoutCluster(model, opts) — 순수: MapScene {nodes, tiles, slabs,     │
   │         links, bounds, grid}                                         │
   │ lodFor(scale, scene) — 순수: "summary" | "tiles" | "detail"           │
   │ scenePaths(scene, lod) — 순수: 합친 경로(층·색·면)                       │
   │ hitTest(scene, lod, point) / neighbor(scene, key, dir) — 순수          │
   ├──────────────────────────────────────────────────────────────────────┤
   │ ClusterMapPage: 도구 띠(그림|목록, 묶기, 레이어, 거르기) · MapScene SVG  │
   │   · 가리키기 카드(떠 있는 div) · 미리 보기 서랍(NodePeek/VmPeek + 동작)  │
   │   · MapList(나무 목록 — 화면 읽기·인쇄·휴대폰)                          │
   └──────────────────────────────────────────────────────────────────────┘
```

- **서버 변경 없음.** 필요한 것을 모두 읽을 수 있다: 노드 상태·레이블·풀·인터페이스(Node 목록), VM 자리·상태·마이그레이션 대상(VM 목록), 부하·추천(`/placement`), 리더(`/cluster`), 경보(`/alerts`), 진행률(Task). 새 엔드포인트를 만들지 않는 대가: 화면이 다섯 질의를 합친다(§9.1 — 첫 그림은 노드·VM 목록만 있으면 그리고 나머지는 오는 대로 얹는다). 서버 묶음 응답(`GET /cluster-map`)은 §15에서 견주고 버렸다.
- **권한**: 지도 보기는 노드 탭과 같은 `node` 읽기(`kind: "node"`). VM 타일은 `useList("vm")`이 주는 읽을 수 있는 VM만이다. 노드에 놓였지만 읽을 수 없는 VM은 `/placement`의 `vms`에서 보이는 수를 뺀 **수만**(회색 "+N 볼 수 없음" 타일) 보인다 — 이미 노드 읽기 권한자에게 `/placement`가 주는 수다. 동작 단추는 지금 화면과 같은 권한 판정(`usePermissions`, `availability`)을 쓴다.
- **파일**: `web/src/clusterMap/`(`data.ts` 질의·모델, `model.ts` 타입과 `toModel`, `layout.ts`, `lod.ts`, `paths.ts`, `hit.ts`, `keys.ts`(이웃), `labels.ts`(화면 읽기 이름), `ClusterMapPage.tsx`, `MapScene.tsx`, `MapCard.tsx`(가리키기 카드), `MapSheet.tsx`(서랍), `MapList.tsx`, `Legend.tsx`), 그림 조각에 더하는 것은 `web/src/components/iso/`(`boxesPath`·`facesPath` 합친 경로, `screenToWorld` 역투영, `IsoGauge` 채움 면) — 토폴로지도 쓸 수 있게 일반 함수로.

## 6. 배치 (`layoutCluster`, 순수)

### 6.1 묶기

- **묶기 열쇠**(도구 띠 "묶기", 사용자별 기억 `clusterMap.group`): `zone`(기본) → 노드 레이블 `zone` 값마다 판 하나, 그 안에서 레이블 `rack`이 있으면 랙마다 한 줄; `rack` → 랙마다 판; **고른 레이블 키**(노드들에 있는 레이블 키 목록에서) → 그 값마다 판; `none` → 클러스터 판 하나(이름은 `/cluster`의 클러스터 이름, 못 읽으면 "클러스터").
- 열쇠 값이 없는 노드는 **"영역 없음" 판**(맨 끝). 어느 노드에도 그 레이블이 없으면 묶지 않은 것과 같다(판 하나, 빈 "영역 없음" 판을 만들지 않음).
- 차례: 판은 값의 자연 순서(`localeCompare` `numeric`), 판 안 노드는 랙 → 이름. **같은 입력이면 같은 그림**이고 VM 상태가 바뀌어도 자리가 움직이지 않는다(타일도 이름 순으로 자리 고정 — 색만 바뀜).
- **증인 노드**(`spec.witness`)는 그 판의 뒤쪽 가장자리에 좁고 낮은 기둥(`IsoPrism` 네모)으로 — VM 자리가 없다. **"배치 안 됨" 판**: `spec.node`·`status.node` 모두 없거나 알 수 없는 노드를 가리키는 VM(꺼진 새 VM, 지운 노드의 VM)을 판들 앞 왼쪽에 작은 판 하나로.
- 템플릿 VM(`spec.template`)은 타일로 그리지 않는다(켤 수 없고 자리를 차지하지 않는다) — 노드 카드에 수만.

### 6.2 크기(세계 단위)

| 것 | 크기 | 뜻 |
|---|---|---|
| 노드 블록 | 바닥 120 × 120, 높이 44 | 모든 노드 같은 크기(코어·메모리 차이는 카드와 채움 막대로) |
| 노드 사이 | x·y 간격 64(뒤 노드의 VM 쌓임이 앞 블록 윗면을 가리지 않게 y 간격은 쌓인 층에 맞춰 늘림 — 판 안 줄마다 그 줄 최대 층 수 × 10) | |
| VM 타일 | 22 × 22, 높이 8, 간격 4 — 윗면에 4 × 4 = 16칸, 많아야 **4층(64칸)** | 64를 넘으면 마지막 칸이 "+N" 타일(누르면 서랍에 그 노드 VM 목록) |
| 판 | 노드 격자 + 여백 40, 두께 6, 앞 가장자리에 이름 글·노드 수 | 판 안 열 수 = 랙이 있으면 랙 길이, 없으면 `min(8, ceil(√n))` |

### 6.3 장면

`MapScene { nodes: NodeItem[], tiles: TileGrid[], slabs: SlabItem[], links: MapLink[], bounds, rows }` — `NodeItem { key: "node:<id>", id, box, group, row, col, tone, heat, load?, tags[] }`, `TileGrid { node, origin, cells: TileCell[] }`(칸마다 `{vm, layer, col, row, tone, ha, warn}`), `links`는 마이그레이션·추천 화살표(§8). 깊이 차례는 `byDepth`(판 → 받침 → 블록 → 타일 → 꼬리표 → 화살표 층).

## 7. 모양 — 상태와 부하

### 7.1 노드 블록

- **부하 열 색(윗면)**: `heat = max(cpu, mem)`(`/placement`의 0.1% 단위를 %로). 70% 밑은 중립(`--card`와 `--brand` 섞음 — 조용함), 70~90% `--warning`, 90% 이상 `--danger`. 두 문턱은 지도 위 범례와 같다(경보 규칙과 따로 — 경보는 경보 수로 따로 보임). `age_secs`가 없거나 `/placement`가 503이면 **"부하 모름"** 빗금 무늬(대체값을 부하처럼 보이지 않는다).
- **채움 막대(옆면)**: 왼쪽 면 아래부터 메모리 사용률, 오른쪽 면 CPU 사용률(`IsoGauge` — 면을 아래·위 둘로 나눈 다각형 둘). **과다 할당**(`mem_allocated_mib > mem_total_mib`)이면 왼쪽 면 위 가장자리에 빨간 띠와 카드에 "할당 112%".
- **상태 꼬리표**(`IsoTag`, 블록 위 앞쪽): 오프라인(블록 색을 `--muted`로 바래고 빨간 테두리, VM 타일은 빗금 "마지막으로 알려진 자리"), 유지보수(윗면 앞 가장자리 경고 줄무늬 띠), 비우는 중(유지보수 + 이 노드에서 나가는 마이그레이션 수), 얼림(`isFrozen` — 파란 꼬리표), 리더(작은 별 꼬리표 — `/cluster`를 읽을 수 있을 때만), 펜스 확인 실패(`fence_check` 나쁨 — HA 레이어에서), **경보 수**(firing 경보 중 그 노드가 주제이거나 주제의 `node`가 그 노드인 것, 가장 높은 심각도 색의 숫자 동그라미).
- **색만으로 알리지 않는다**(계획 61 §7): 상태마다 모양이 다르다(빗금·줄무늬·테두리·꼬리표 글). 자세히 단계에서는 윗면에 "CPU 72% · 메모리 64%" 글.

### 7.2 VM 타일

| 상태(`status.phase`) | 색 | 덧 |
|---|---|---|
| running | `--success` | |
| stopped | 옅은 회색(`--muted-foreground` 섞음) | |
| starting·stopping | `--info` | 동작 줄이기가 아니면 느린 맥박(불투명도 0.6↔1, 2초) |
| failed | `--danger` | 윗면에 × 무늬 |
| migrating | `--info` | 원본 자리는 테두리만(유령), 대상 노드 위 맨 위 층 끝 칸에 같은 VM의 점선 타일(§8) |

- HA가 켜진 VM(`spec.ha`)은 윗면 테두리를 밝게(HA 레이어가 켜지면 방패 무늬), 배치 규칙을 어긴 VM(`status.rule_violations`)은 윗면 모서리에 경고 삼각형(자세히 단계).
- "+N"(64칸 넘음)·"+N 볼 수 없음"(권한)은 회색 타일과 숫자.

### 7.3 레이어(도구 띠 "레이어", 켜고 끄기 기억 `clusterMap.layers`)

- **부하**(기본 켬): 위 §7.1 열 색·채움. 끄면 블록이 중립 색.
- **스토리지**: 노드 블록 밑의 얇은 **받침 판**을 노드 로컬 풀(공유 아닌 풀)마다 한 조각씩(사용률 색 — 같은 문턱, 준비 안 됨은 빨간 빗금 + 카드에 `error`). **공유 풀**(`shared` — NFS·RBD·공유 LVM)은 판 앞에 긴 띠 하나(풀 이름들)이고, 어느 노드에서 그 풀이 준비 안 됨이면 그 노드 받침 앞에 경고 눈금.
- **네트워크**: 블록 아래 가장자리 띠 — 물리·본딩 인터페이스가 모두 `up`·`carrier`면 초록, 본딩 포트 일부 끊김·일부 `down`이면 주황, 업링크가 하나도 안 되면 빨강, 인터페이스 정보 없음(옛 노드·macOS)이면 그리지 않음. SDN 게이트웨이 노드(`spec.sdn`의 게이트웨이)는 "GW" 꼬리표. 노드 사이 선은 그리지 않는다 — 카드에 "네트워크 토폴로지에서 보기" 링크.
- **HA**: 펜싱이 없는 노드(`status.ha` 없음)는 블록 둘레 회색 점선("HA VM을 돌리지 않음"), 펜스 확인 실패는 경고 꼬리표, HA VM 타일은 방패 무늬.
- **추천**: 최적 배치 추천(`recommendations` 중 `task` 없는 것)을 옅은 점선 화살표와 VM 이름 꼬리표로(§8). 균형 조정기가 `off`면 레이어 단추를 막고 까닭.
- 레이어가 많이 켜져도 그림이 시끄럽지 않게, 레이어마다 원소는 노드당 많아야 서넛이다(§9.2 예산에 넣음).

### 7.4 테마와 대비

- 색은 모두 지금 디자인 토큰(`--success`·`--warning`·`--danger`·`--info`·`--brand`·`--card`·`--muted-foreground`)에서 `color-mix`로 셈하고 면 밝기는 `shade()` — 밝음·어둠 테마가 같은 코드다. 어둠 테마에서 그림자는 옅은 테두리로(`IsoShadow`가 이미).
- 빗금·줄무늬는 `<defs>`의 `pattern`(테마 토큰 색) — 조각 안에만.
- **대비 시험**: 상태 색과 꼬리표 글이 `--card` 위에서 3:1(그림 원소)·4.5:1(글) 이상인지 `test/contrast.ts`로 두 테마 모두 본다.

## 8. 움직임 — 라이브 마이그레이션·비우기·추천

- **화살표**: `status.migration`이 있는 VM마다 원본 노드(`status.node`) 윗면 가운데에서 대상(`migration.node`) 윗면 가운데로 휜 선(`IsoLink`, `lift` = 두 점 거리의 0.3배 — 판을 넘는 화살표는 더 높이). 진행 중이면 점선이 원본 → 대상으로 흐른다(`stroke-dashoffset` 키프레임 1.2초, 조각 안 `<style>`). 선 가운데 꼬리표: "web → n3 · 62%"(Task `progress.done_bytes / total_bytes`, 모르면 단계 이름).
- **유령 타일**: 원본 자리는 테두리만, 대상 노드 맨 위 층 끝 칸에 점선 타일(대상 노드의 자리를 미리 보인다). 끝나면(watch로 `status.node`가 바뀜) 화살표가 사라지고 타일은 대상 노드의 이름 순 자리에 들어간다 — 그 순간 0.2초 흐려짐에서 나타남(동작 줄이기면 바로).
- **비우기**: 유지보수 노드에서 나가는 화살표가 여럿이면 그 노드 꼬리표에 "비우는 중 3/12"(나간 수/켜 둔 VM 수 — `runningCount`와 같은 기준).
- **추천**(추천 레이어): 회색 점선, 흐르지 않음. 누르면 서랍에 추천(옮길 메모리·줄어드는 불균형·까닭)과 **"적용"**(`vm.migrate`가 있을 때 — 최적 배치 화면과 같은 요청·Task 추적). auto 모드가 만든 Task는 진행 중 마이그레이션 화살표로 보인다(같은 VM에 둘 그리지 않음).
- **동작 줄이기**(`prefers-reduced-motion: reduce`): 흐름·맥박·나타남을 모두 끈다 — 점선은 멈추고 진행률 글은 남는다. 탭이 숨겨지면(`document.hidden`) 키프레임도 브라우저가 멈춘다.
- **끌어 놓아 옮기기는 하지 않는다**(§15·§16): 옮기기는 VM 서랍의 "옮기기…"가 지금 `VmMigrateDialog`(대상 고르기·로컬 디스크 복사·배치 규칙·확인)를 연다. 그림 끌기는 이미 보기 움직이기(pan)이고, 터치에서 둘을 가르면 실수로 옮기기가 생긴다. 계획 71(끌어 놓기 VM 만들기)이 끌어 놓기 틀(키보드 대체 포함)을 만들 때 지도에 "타일을 노드로 끌기 → 같은 대화상자"를 더한다.

## 9. 큰 클러스터 — 자세히 보기 단계와 성능

### 9.1 자료 흐름

- 첫 그림은 노드·VM 목록만 있으면 그린다(이미 캐시에 있으면 바로 — 노드 표에서 넘어온 경우). `/placement`·`/cluster`·`/alerts`·Task는 오는 대로 얹는다(그 전에는 "부하 모름", 리더 없음, 경보 없음).
- watch 사건(노드·VM)은 목록 캐시를 고치고, 지도는 **모델을 1초 모아** 다시 만든다(`useDeferredValue` + 1초 묶기 — 토폴로지 `REFRESH_ON`과 같은 뜻). 배치는 `useMemo`로 모델이 바뀔 때만.
- `/placement`는 최적 배치 화면과 **같은 질의 열쇠**(`PLACEMENT_KEY`)로 15초 — 두 화면이 캐시를 함께 쓴다. 503이면 다시 묻되 그림은 "부하 모름"으로.

### 9.2 세 단계

| 단계 | 언제 | 노드 | VM |
|---|---|---|---|
| **요약**(summary) | 타일 한 칸이 화면에서 6px 밑(맞추기 배율 × 22), 또는 보이는 VM이 3000 넘음 | 블록 + 윗면 열 색 + 꼬리표 | 노드 위 **상태별 막대 하나씩**(켜짐·꺼짐·실패·바뀌는 중 — 높이 ∝ 수, 많아야 4개) |
| **타일**(tiles) | 6~18px | 위 + 채움 막대 | 타일을 **층·색·면마다 합친 경로**로(§4), 초점·가리킨 타일만 따로 테두리 |
| **자세히**(detail) | 18px 이상이고 화면 안 타일 300개 밑 | 위 + 윗면 글(CPU·메모리 %) | 타일 위 VM 이름(앞 8자), 규칙 어김 삼각형, 경보 점 |

- 확대·축소로 배율이 바뀌면 단계가 바뀐다 — 문턱 둘레 15% 이력(hysteresis)으로 깜박이지 않게. 단계는 도구 띠에 작은 글("요약 보기 — 확대하면 VM 타일")로 알린다.
- **원소 예산**(시험으로 지킴): 100 노드 × 50 VM(5000 VM, 판 10개)에서 요약 단계 1,500개 밑, 타일 단계 **3,000개 밑**, 레이어 모두 켜도 4,000개 밑. 노드 20 × VM 20(400 VM) 자세히 단계 2,500개 밑. 견줌: 토폴로지 방식(타일마다 `<g>` + 다각형 셋)이면 5000 VM에서 약 20,000개.
- **배치 시간**: 100 × 50 모델 → 장면 + 경로가 이 Mac에서 **30 ms 밑**(vitest 성능 시험 — 토폴로지 VM 2000 13 ms 기록과 같은 틀).
- **다시 그리지 않기**: 가리키기·초점·끌기·확대는 블록·경로를 다시 그리지 않는다(블록은 `memo`, 밝히기는 `<style>` 한 줄, 가리킨 타일 테두리는 원소 하나). 단계가 바뀔 때만 경로를 다시 만든다. 시험이 "가리키기 열 번 → 블록 다시 그린 수 0"을 본다.
- **거르기**(도구 띠): 묶음 판 하나만 보기(판 고르기), "꺼진 VM 감추기", "문제만"(오프라인·유지보수·부하 90%↑·경보 있는 노드와 실패 VM만 진하게, 나머지 흐리게 — 원소는 그대로). 노드 200을 넘으면 "판 하나만 보기를 권함" 띠(토폴로지의 큰 그림 띠와 같은 꼴).

## 10. 다루기

### 10.1 가리키기·초점 — 작은 카드

- 노드·타일·화살표를 가리키거나(마우스) 초점이 가면(키보드) 그림 위에 **떠 있는 카드**(`MapCard`, `pointer-events: none`, 화면 밖으로 나가지 않게 자리 맞춤): 노드 — 이름·상태 칩(온라인·유지보수·얼림·리더)·CPU·메모리 막대와 %·할당 메모리·VM 수(켜짐/전체, 볼 수 없음 n)·경보 수·로컬 풀 사용; VM — 이름·상태 칩·vCPU·메모리·노드·HA·마이그레이션 진행. 카드는 꾸밈이고 같은 글이 그 원소의 `aria-label`이다(§10.3).
- 가리킨 노드와 이어진 것(그 노드의 타일·드나드는 화살표·같은 판)을 밝히고 나머지를 흐린다(토폴로지 `related`와 같은 꼴).
- 터치에서는 가리키기가 없으므로 한 번 누르면 바로 서랍(§10.2).

### 10.2 누르기 — 서랍과 그 자리의 동작

- **노드**: 오른쪽(휴대폰은 아래) 서랍에 `NodePeek`(상태·주소·버전·CPU·메모리·VM 수) + **이 노드의 VM 목록**(상태 칩·링크, 실패 먼저) + 노드 동작(`useNodeActions`의 유지보수 시작/끝·비우기·레이블 — 권한이 없으면 숨김, 지금 메뉴와 같은 대화상자·확인) + "상세 열기"(`/nodes/<이름>`) + "네트워크 토폴로지에서 보기".
- **VM**: `VmPeek` + 주된 동작 단추 둘(전원: 시작 또는 정지 확인, **옮기기…** → `VmMigrateDialog`) + `VmMenu`(나머지 동작) + "상세 열기"(`/vms/<이름>`). 막힌 동작은 `availability()`의 까닭을 그대로 보인다.
- **화살표**: 마이그레이션이면 그 Task 줄(작업 센터 링크·진행), 추천이면 §8의 "적용".
- **"+N"**: 그 노드의 VM 전체 목록 서랍(이름 거르기).
- 더블클릭·Ctrl/⌘+클릭은 바로 상세 화면(서랍 없이).
- 서랍을 닫으면 그림의 그 원소로 초점이 돌아온다(지금 `focusBack` 규약).
- **주소로 가리키기**: `/cluster/map?focus=node:<이름>` 또는 `?focus=vm:<이름>`이면 그 원소로 맞추고 초점을 준다(서랍은 열지 않음). 이번 계획에서는 지도 안에서만 쓰고(목록 보기 ↔ 그림 전환이 초점을 지킴), 다른 화면의 "지도에서 보기" 링크는 §16.

### 10.3 키보드와 화면 읽기

- 그림은 **탭 차례 하나**(토폴로지와 같음 — `Tab`은 그림을 떠난다). 초점은 **두 단계**다: 노드 단계(화살표가 화면 방향의 이웃 노드로 — 같은 판 안 격자, 판 경계를 넘으면 옆 판의 가장 가까운 노드)와 VM 단계(한 노드 위 타일 사이). 화살표를 두 단계에 함께 쓰면 "노드 위 타일"과 "옆 노드"가 같은 키를 다투므로, 들어가고 나오는 키를 따로 둔다(`]`·`[` — 나무 목록의 펼치기·접기와 같은 뜻, 한 손으로 닿음):

| 키 | 노드에서 | VM 타일에서 |
|---|---|---|
| `←` `→` `↑` `↓` | 이웃 노드 | 같은 노드 안 이웃 타일(층 안 격자, 맨 위 층에서 `↑`는 멈춤) |
| `Enter` | 서랍 열기 | 서랍 열기 |
| `Shift+Enter` | 상세 화면 | 상세 화면 |
| `]` | 그 노드의 첫 VM 타일로 들어가기(요약 단계면 그 노드 VM 목록 서랍) | — |
| `[` 또는 `Esc` | — | 그 노드로 나오기 |
| `Home` `End` | 첫·끝 노드 | 그 노드의 첫·끝 타일 |
| `+` `-` `0` | 확대·축소·맞추기(초점 원소를 화면 안에 둠 — `reveal`) | 같음 |

  `[`는 전역 단축키(사이드바 접기)와 겹치므로 **그림에 초점이 있을 때만** 그림이 받고 `stopPropagation`한다(전역 단축키 표 `SHORTCUTS`에 "지도 안에서"를 적고 `?` 도움말에도). 단축키 시험이 그림 밖에서는 `[`가 사이드바를 접는지 본다.
- **화면 읽기 이름**(`labels.ts`, 장면마다 한 번 셈): 노드 "노드 n3, 판 rack-a, 온라인, 유지보수, CPU 72%, 메모리 64%, VM 14개(켜짐 12, 실패 1), 경보 2", VM "VM web, 켜짐, 노드 n3, HA, n5로 옮기는 중 62%". 초점이 옮겨 가면 `aria-live="polite"` 줄이 같은 이름을 읽는다(SVG `role="button"` 이름만으로 읽지 않는 화면 읽기 프로그램이 있어서). 그림 `<svg role="group" aria-label="클러스터 지도" aria-describedby="키 안내">`.
- **"목록으로 보기"**(도구 띠 그림 | 목록, 기억 `clusterMap.mode`): 같은 모델의 **나무 목록**(`MapList` — 판 → 노드(상태·부하 글) → VM(상태), `<ul role="tree">`가 아닌 평범한 중첩 목록과 머리글 — 화면 읽기 프로그램이 이미 잘 읽는 꼴, 인쇄용). 노드 단위 정렬·숫자 비교는 지금 **노드 표**(보기 "노드")가 맡는다 — 목록 보기는 묶음·VM 자리를 보이는 것만.
- 표 ↔ 지도 오가기는 **보기 전환**(노드 | 지도 | 클러스터)이고 영역이 마지막 보기를 기억하므로, 지도를 즐겨 쓰는 사람은 인프라를 누르면 지도로 온다.

### 10.4 보기 움직이기와 휴대폰

- 노드가 하나뿐인 클러스터·VM이 없는 클러스터도 그린다(빈 판과 "VM 없음" 글). 노드를 하나도 읽지 못하면 지금 노드 표의 빈 상태와 같은 글.

## 11. 화면 자리와 주소

- `nav.ts` 인프라 › 노드 탭의 `views`에 `{ to: "/cluster/map", key: "nav.clusterMap" }`를 `/nodes`와 `/cluster` 사이에 더한다(보기 차례: 노드 | 지도 | 클러스터). 탭의 `kind: "node"`가 그대로 문이다. 사이드바·영역은 그대로.
- **주소를 `/nodes/map`으로 하지 않는 까닭**: `/nodes/:name` 상세와 겹친다(노드 이름 `map`이 될 수 있음). `/cluster`에는 하위 경로가 없어 `/cluster/map`이 안전하고, `areaOf`는 가장 긴 접두사로 지도 보기를 고른다. 이동 경로: `인프라 › 지도`.
- `App.tsx`에 `{ path: "cluster/map", lazy: page(() => import("@/clusterMap/ClusterMapPage"), "ClusterMapPage") }`. 팔레트 이동 항목은 nav 표에서 저절로 생긴다(별칭 en "map, topology, 3d"·ko "지도, 클러스터 보기, 3d").
- i18n: `nav.clusterMap`(en "Map", ko "지도"), `clusterMap.*`(도구 띠·범례·꼬리표·카드·화면 읽기 이름·빈 상태·단계 안내·키 안내) en·ko. 첫 화면 묶음에 들어가는 것은 이 문구와 nav 한 줄뿐.
- 기억(`writeUserPref` 사용자별): `clusterMap.mode`(그림·목록), `clusterMap.group`(묶기 열쇠), `clusterMap.layers`(켠 레이어), `clusterMap.filter`. 휴대폰과 넓은 화면이 같은 기억을 쓴다.

## 12. 번들과 늦게 읽기

- 그림 코드(`web/src/clusterMap/`)는 늦게 읽는 조각이다. 그림 조각(`components/iso/`)은 토폴로지와 함께 쓰므로 Vite가 따로 나눈 공유 조각이 된다(둘 중 먼저 연 화면이 받음). 서랍이 쓰는 `NodePeek`·`VmPeek`·`VmMenu`·`VmMigrateDialog`·`useNodeActions`는 노드·VM 화면 조각에 이미 있어 공유된다.
- **목표**: 지도 조각 gzip **20 KB 밑**(토폴로지 10.9 KB), **첫 화면 묶음 증가 3 KB 밑**(i18n·nav — 계획 69는 +4.4 KB). 새 의존성 없음(lucide 아이콘 몇 개는 이미 있는 꾸러미). 스테이지 3이 `eager.sh`로 앞뒤를 재 §18에 적는다.

## 13. 권한·버전 섞임·다른 기능과의 관계

| 것 | 권한 | 없을 때 |
|---|---|---|
| 지도 보기(노드 탭의 보기) | `node` 읽기 | 탭·보기 숨김(지금 규칙) |
| VM 타일 | 그 VM 읽기 | "+N 볼 수 없음" 수만 |
| 부하·추천(`/placement`) | `node` 읽기 | 403/503 → "부하 모름", 추천 레이어 막힘 + 까닭 |
| 리더 꼬리표(`/cluster`) | `cluster` 읽기 | 꼬리표 없음 |
| 경보 수 | 경보 읽기(`/alerts`가 주는 것만) | 없음 |
| VM 동작·옮기기·추천 적용 | 지금 화면과 같음(`vm.power`·`vm.migrate` 등) | 단추 숨김·막힘 까닭 |
| 노드 동작 | 지금 노드 메뉴와 같음 | 숨김 |

- **버전 섞임**: 서버 변경이 없으므로 옛 노드도 그대로다. 옛 노드가 비우는 칸(`interfaces`·`ha`·`fence_check` 없음)은 그 레이어 표시를 그리지 않는다(빈 칸을 "나쁨"으로 보이지 않음).
- **폴더 권한만 있는 사용자**: 노드 읽기가 없으면 노드 탭이 없으므로 지도도 없다(VM만 보는 사용자에게 노드 배치는 지금도 숨김).
- **토폴로지와의 관계**: 토폴로지는 네트워크 층(VM ↔ 네트워크 ↔ 라우터), 지도는 물리 층(VM ↔ 노드 ↔ 영역). 둘이 같은 그림 조각·다루기 규칙(탭 차례 하나, 화살표, 밝히기, 그림 | 목록)을 쓴다. 지도 카드에서 토폴로지로 링크만 건다(계획 61 §4.1 규칙 5 — 한 리소스의 집은 한 곳).
- **최적 배치·HA**: 지도는 읽어 보이기만 하고 규칙·설정은 보호 영역 화면에 그대로 있다. 추천 적용은 최적 배치 화면과 같은 요청이다.

## 14. 시험과 CI

- **순수(vitest)**: `toModel`(템플릿 뺌, 배치 안 됨, 알 수 없는 노드, 증인, 마이그레이션 원본·대상, 볼 수 없는 VM 수, `/placement` 0.1% 단위 → %, `age_secs` 없음 → 부하 모름), `layoutCluster`(같은 입력 같은 장면, 묶기 `zone`·`rack`·레이블·`none`, "영역 없음", 레이블이 하나도 없으면 판 하나, 타일 이름 순 자리 고정 — 상태가 바뀌어도 칸이 같음, 64칸 넘으면 "+N", 줄마다 y 간격이 쌓인 층에 맞음, 깊이 차례), `lodFor`(문턱·이력), `scenePaths`(층·색·면마다 경로 하나, 경로 조각 수 = 칸 수), `hitTest`(모든 칸의 윗면 가운데 → 그 칸 왕복, 위 층이 이김, 빈 곳 → 없음), `neighbor`(노드 격자·판 넘기·`]`·`[`·`Home`·`End`), `heatTone` 문턱, `migrationLinks`(진행률 글, 추천과 진행 중이 겹치면 하나), `labels`(두 언어).
- **성능(vitest, `ClusterMapScene.perf.test.tsx`)**: 100 노드 × 50 VM 배치 + 경로 30 ms 밑(이 Mac 기록), 단계마다 원소 수 예산(§9.2), 가리키기·끌기·초점 이동 열 번에 블록 다시 그린 수 0(토폴로지 시험과 같은 `vi.mock` 세기).

- **번들**: `pnpm build` 뒤 `eager.sh` 앞뒤, 지도 조각 gzip 크기를 §18에.
- **할 수 없는 것과 대신**: 실제 화면 읽기 프로그램(VoiceOver) 확인은 이 Mac에서 손으로(스테이지 2 §18에 적음), 실제 두 노드 라이브 마이그레이션 움직임은 svc01·svc02 배포 확인에서 손으로(공유 풀이 없으면 로컬 디스크 복사 마이그레이션 — TCG라 느려 움직임을 보기 좋다).
- **svc01**: 일반 시험 묶음(웹 묶음 포함 빌드). GitHub: 웹만 바뀌므로 `check`·`web` 작업이 통과하면 된다(`linux-kvm`·`ldap`·`package`는 바뀐 것이 없어 탐침하지 않음 — 도는 그대로 통과 확인만).

## 15. 견준 길

- **그리기: SVG + 합친 경로(채택) / 타일마다 `<g>`(토폴로지 방식) / Canvas 2D / WebGL.** 사용자가 진짜 3D·WebGL을 막았다. 타일마다 원소면 5000 VM에서 2만 원소. Canvas 2D는 빠르지만 원소마다 초점·`aria-label`·CSS 테마·`color-mix`를 잃고 고해상도 화면 다시 그리기를 우리가 해야 한다. 합친 경로는 원소를 노드당 수십 개로 줄이고 적중은 순수 셈으로 한다. 대가: 타일 하나하나에 DOM 초점이 없어 초점 테두리를 따로 그린다.
- **배치: 장애 영역 판 + 격자(채택) / 힘 배치 그래프 / 트리맵 평면 히트맵.** 힘 배치는 새로 고칠 때마다 흔들린다. 트리맵(Aria·Prism 히트맵)은 정확하지만 "어느 랙 어느 노드 위에 무엇이" 공간 감각이 없다. 판 + 격자는 결정적이고 장애 영역(HA·배치 규칙이 쓰는 `zone`)이 그대로 보인다.
- **부하 자료: `/placement` 요약(채택) / `/metrics/nodes` / `/metrics/cluster` 범위 평균.** `/placement`는 리더가 리스로 이미 모은 노드마다 한 줄이라 질의 한 번이고 최적 배치 화면과 캐시를 나눈다. `/metrics/nodes`는 모든 노드에 퍼져 묻는다(노드 100이면 요청 100). 범위 평균은 "지금"이 아니다. 대가: 리더에 못 물으면 부하가 없다("부하 모름"으로 숨기지 않음).
- **서버 묶음 응답 `GET /cluster-map`(버림) / 지금 질의 합치기(채택).** 묶음 응답은 첫 그림을 빠르게 하나 OpenAPI·권한·감추기·버전 섞임 규칙을 하나 더 만들고, 이미 watch로 살아 있는 노드·VM 목록을 따로 다시 읽어야 한다. 화면이 노드·VM 목록으로 먼저 그리고 나머지를 얹으면 충분하다.
- **자리: 노드 탭의 보기(채택) / 홈 위젯 / 새 탭 / 클러스터 보기 대체.** 계획 61 규칙(새 사이드바 항목 없음, 하위 화면은 탭·보기). 노드 표와 같은 탭이라 "표 ↔ 지도" 전환이 보기 전환 그 자체다. 홈 위젯은 휴대폰·작은 화면에서 무겁다(§16에 작은 미리 보기로).
- **끌어 놓아 옮기기: 계획 71로 미룸(채택) / 이번에 넣음.** 끌기가 보기 움직이기와 겹치고(특히 터치), 키보드 대체·놓을 자리 판정(배치 규칙·아키텍처·풀)·확인 대화상자를 계획 71의 끌어 놓기 틀과 한 번에 만드는 것이 낫다. 그때도 같은 `VmMigrateDialog`와 같은 API다.
- **VM 크기를 타일 크기로(버림) / 같은 크기(채택).** 크기를 다르게 하면 칸 격자가 깨져 자리 고정·적중 셈·합친 경로가 어려워지고, 큰 VM 몇 개가 노드를 가린다. 크기는 카드·노드 채움 막대가 말한다.

## 16. 나중 할 일

- **끌어 놓아 옮기기**(계획 71과 함께): 타일을 노드로 끌면 놓을 수 있는 노드만 밝히고(`migrationTargets`와 배치 규칙), 놓으면 대상을 고른 `VmMigrateDialog`. 키보드는 `m` → 화살표로 노드 → `Enter`.
- 다른 화면의 "지도에서 보기"(노드·VM 상세 머리, 경보 대상 링크 — `?focus=`), 홈의 작은 지도 미리 보기 위젯.
- 시간 되감기(지난 1시간의 상태·마이그레이션 다시 보기 — 지표 기록·Task 기록으로), 노드 사이 네트워크 선(VXLAN 터널·Ceph 클러스터 망).
- 랙 안 자리(U)·전원 영역 레이블, 사진·평면도 배경.
- 여러 클러스터(원격 클러스터) 지도, 그림에서 여러 개 고르기와 일괄 동작.
- 노드 500 넘는 클러스터: Web Worker 배치, 화면 밖 판 그리지 않기(culling).
