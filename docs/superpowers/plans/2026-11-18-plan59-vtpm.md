# Orbivisor 계획 59: vTPM·Secure Boot·게스트 에이전트 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** UEFI VM에 VM마다 swtpm 하나로 TPM 2.0을, QEMU 펌웨어 descriptor로 찾은 MS 키 등록 펌웨어로 Secure Boot를 달고, TPM 상태가 노드 로컬 파일인 채로 VM을 따라다니게(받아 오기·사본·해시 기록·엄격한 켜기 규칙) 하며, QEMU 게스트 에이전트로 게스트 정보·에이전트 끄기·fs-freeze·비밀번호 설정을 하고, CLI·웹에 Windows 11 미리 채우기를 둔다.

**Architecture:**
- **TPM 상태는 노드 로컬 + Raft의 해시와 위치:** `{state_dir}/vm/{id}/tpm/tpm2-00.permall`, `VmStatus.tpm_node`·`tpm_sha256`·`firmware_copies`·`firmware_epoch`. UEFI 변수의 `firmware_node`·`FirmwareFetcher`·peer `UefiVars` 길을 넓힌 것이고, 새 peer RPC `TpmState`·`PushFirmware`·`PurgeFirmware`·`GuestAgent`. 지금 TPM 상태를 얻지 못하면 켜지 않는다(`tpm_source`의 `Unavailable`).
- **swtpm은 떼어 낸 데몬:** `QemuHypervisor::launch`가 QEMU보다 먼저 `--daemon --terminate`로 띄우고(systemd면 `opl-tpm-{id}.scope`), 주인 확인(pid 파일 + 명령줄의 제어 소켓) 뒤에만 끝낸다. 회차 파일 `firmware.epoch`로 초기화 전의 낡은 변수·TPM을 지운다(`adopt_firmware_epoch` 한 길).
- **Secure Boot:** `opl_qemu::firmware::discover`가 `secure-boot`+`enrolled-keys` descriptor를 고르고(`HostProfile.secure_boot`), q35는 `smm=on`과 secure pflash. 변수가 있는 VM의 전환은 409 `firmware_reset_required`이고 `POST /vms/{key}/firmware/reset {uefi_vars, secure_boot}` Task(`vm-firmware-reset`)로 함께 바꾼다.
- **게스트 에이전트:** `opl_qemu::qga::Session`(guest-sync-delimited, 1 MiB 상한, VM마다 잠금), `StopMode::Agent`, `guest_info`, 시점을 찍는 드라이버 메서드 넷의 `quiesce`와 `Quiesced` 경고, 노드 메모리 `GuestInfoStore`(60초 수집, 5초 refresh).
- **기능 둘:** `vtpm`(TPM·Secure Boot·초기화 Task·TPM RPC·TPM 백업)과 `guest-agent`(`VmSpec.guest_agent`·`GuestAgent` RPC). 새 칸은 기본값이면 쓰지 않아 기존 VM의 JSON·명령줄은 바이트까지 같다.

**Tech Stack:** Rust 2024(MSRV 1.88), swtpm·swtpm_setup, QEMU `tpm-crb`·`tpm-tis-device`·`-tpmdev emulator`, OVMF/AAVMF firmware descriptor, QEMU guest agent 프로토콜, tonic peer RPC, axum·utoipa, React. 새로 받는 크레이트는 없다.

**설계 문서:** `docs/superpowers/specs/2026-11-18-vtpm-secure-boot-guest-agent-design.md`

## 설계 결정

- **TPM은 엄격, 변수는 너그럽게:** 변수를 잃으면 부팅 항목만 잃지만 TPM을 잃으면 BitLocker·LUKS 봉인 키를 잃는다. 그래서 TPM은 지금 해시의 파일이 없으면 켜지 않고(HA도 사본 노드만), 새 TPM은 기록된 상태가 없을 때나 명시적 초기화 뒤에만 만든다.
- **상태는 Raft 밖:** Raft에는 해시·위치·회차만 두고 비밀은 노드 파일(0700/0600)에만 둔다. 공유 풀 볼륨 대신 이미 있는 변수 경로를 넓혔다(RBD krbd·swtpm 잠금 넘기기가 필요 없음).
- **복제·배포는 새 TPM:** EK가 같은 VM이 생기지 않게. 복사가 필요하면 백업 → 복원.
- **Secure Boot 전환은 초기화와 한 요청:** 부팅 항목을 몰래 지우지 않고, TPM VM의 변수만 초기화 뒤에도 PUT이 막히는 문제를 피한다.
- **게스트 정보는 노드 메모리:** 지표와 같은 읽기 길, Raft 쓰기 없음. `guest-exec`는 위험이 커서 넣지 않는다.
- **얼리기 실패는 경고:** Task를 실패시키지 않고 crash-consistent라고 알린다. 블록 스냅샷 디스크는 VM을 멈추고 찍으므로 얼리지 않는다.

## 완료 기준 (계획 59)

- `orbivisorctl vm create --tpm on --secure-boot on`(또는 `--preset windows11`)으로 만든 VM이 swtpm과 Secure Boot 펌웨어로 켜지고, 게스트에서 `/dev/tpm0`·`SecureBoot` 변수 1·EK가 보이며, 다시 켜도 EK가 같고, `vm clone`한 VM의 EK는 다르다(GitHub `install-media`).
- TPM VM을 다른 노드로 라이브 마이그레이션하거나 꺼진 채 다른 노드에서 켜면 같은 TPM 상태(해시)로 켜지고, `tpm_node`가 죽으면 HA가 사본 노드에서 복구하며, 지금 상태를 얻을 수 없으면 켜지 않는다(GitHub `linux-kvm`, API 시험).
- `vm firmware reset --tpm`이 새 TPM을, `vm set --secure-boot on --reset-uefi-vars`가 새 변수와 Secure Boot를 만들고, 변수가 있는 VM의 `PUT`만으로 바꾸기는 409 `firmware_reset_required`다.
- `vm guest`가 OS·호스트 이름·IP·파일 시스템을 보이고, 실행 중 디스크 스냅샷에 얼리기 경고가 없으며, `vm stop`이 에이전트로 빨리 꺼진다(GitHub `install-media`).
- swtpm이 없거나 AppArmor가 막는 노드는 `TPM no`를 알리고(이유는 로그), 스케줄러가 TPM VM을 그 노드에 놓지 않는다.
- 웹에서 보안·게스트 에이전트 카드, 게스트 탭, 초기화·비밀번호 창, Windows 11 미리 채우기, 노드 능력을 쓸 수 있다.
- `cargo fmt`, `clippy -D warnings`(모든 기능), `cargo test --workspace`, 웹 시험이 이 Mac과 svc01에서, linux-kvm·install-media·ceph·ldap·package가 GitHub에서 통과한다.

## 알고 받아들인 제한

- TPM 사본은 마지막 밀어 두기(60초 주기) 시점이다. 그 사이 TPM에 쓴 것(NV 카운터, 그때 만든 키)은 HA 복구나 사본으로 켜기에서 없어질 수 있다. 첫 해시 기록 전에 노드가 죽으면 다른 노드는 새 TPM으로 켠다.
- HA도 복제도 없는 TPM VM은 사본이 없어 `tpm_node`가 꺼져 있으면 켜지 못한다.
- 노드 능력은 orbivisord가 시작할 때만 본다(swtpm 설치·AppArmor 규칙 수정 뒤 재시작 필요). 노드가 정해진 VM의 `vm start`는 능력 없는 노드에서 409 대신 켜다 실패한다.
- 패키지의 AppArmor 규칙은 기본 `data_dir`·`run_dir`(`/var/lib/opl`·`/run/opl`)만이다. 다른 경로는 관리자가 `/etc/apparmor.d/local/usr.bin.swtpm`에 더한다.
- macOS 노드는 swtpm이 없고(Homebrew) Homebrew의 secure descriptor에 `enrolled-keys`가 없어 TPM·Secure Boot를 못 한다.
- TPM 상태와 백업의 `tpm2-00.permall`은 암호화하지 않는다(백업 저장소를 읽을 수 있으면 읽힌다).
- 블록 스냅샷 디스크(LVM-thin·ZFS·RBD·공유 LVM)의 스냅샷은 얼리지 않는다(crash-consistent 경고).
