# Orbivisor 계획 67: SDN(OVN) 3 — 부하 분산, QoS, 2.5D 네트워크 토폴로지, 단순 → SDN 옮기기 도구, OVN 접근 잠금, SDN 경보 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 계획 65·66으로 SDN 네트워크는 서브넷·IPAM·DHCP, 분산 라우터, 게이트웨이 HA, SNAT·유동 IP, IPv6, 보안 그룹까지 갖췄다. 이 계획은 "OpenStack OVN 기능처럼"의 **서비스와 운영**을 넣는다: OVN 내장 **부하 분산**(VIP·리스너·멤버·건강 검사·출발지 고정·라우터 바깥의 **바깥 VIP**), NIC마다 **QoS**(SDN은 OVN `QoS` 행, 단순 NIC는 tap의 tc 속도 — 같은 폴리싱 뜻), 네트워크·라우터·게이트웨이·유동 IP·VM·LB를 한 그림으로 보는 **2.5D 토폴로지**(아이소메트릭 SVG — 그림 조각을 계획 70과 나눔), 단순 네트워크의 VM NIC를 SDN으로 옮기는 **옮기기 도구**(미리 보기 계획, 주소 가져가기, VM마다 꺼진 채·다시 켬·라이브 tap 옮기기, `l2gateway` 다리, 되돌리기, 끝내기), 지운 노드를 끊는 **OVN 접근 잠금**(SB RBAC 역할 포트, northd 전용 포트, Raft 멤버십을 따르는 nftables 주소 허용 목록), **SDN 경보** 여덟. 계획 66이 넘긴 여러 chassis 보안 그룹 시험, 라우터·유동 IP watch, 네트워크 주인의 라우터 떼기 단추, VM 주인의 유동 IP 떼기, 네트워크 폴더 할당량 `networks`도 넣는다.

**Architecture:**
- **계획 65·66 그대로**: 원하는 상태는 Raft에만 있고 리더 `OvnSync`만 NB에 쓴다(다른 것만, 펜싱 토큰). API는 OVN을 부르지 않는다. 노드 `SdnAgent`는 자기 OVS·veth·OVN 단위·nftables 표만 만진다.
- **새 리소스 `LoadBalancer`·`NetworkMigration`**(네트워크 폴더, 할당량 `load_balancers`·`networks`, 바깥 VIP는 `floating_ips`도), NIC `qos`, `SdnSpec.lockdown`, `AlertCondition` 여덟. Raft 겹침 키 `ip`(VM·라우터·유동 IP·LB 넷이 한 공간)·`lb-listener`·`migration-source`·`migration-vm`.
- **NB**: 프로토콜마다 `Load_Balancer`(라우터와 **그 모든 인터페이스 스위치**에 붙임)·`Load_Balancer_Health_Check`·`ip_port_mappings`, 포트마다 `QoS` 행, 옮기기 다리 `l2gateway` LSP. 트랜잭션 차례 목록 PG → **LB** → 네트워크 → 라우터 → 지우기(…→ 지울 LB).
- **옮기기는 Task 하나가 VM마다 한 걸음씩**(스펙·전원·도는 NIC를 보고) — opld가 다시 떠도 이어 간다. 라이브는 새 핫플러그 단계 `RelinkNic`(tap만 브리지 ↔ `br-int`, `ovn-installed` 기다림, QMP `set_link`).
- **잠금은 각 중앙의 에이전트가 자기 차례에** SB를 `sb.json`(역할 포트 6642·특권 포트 6645)으로 바꾸고, 모든 중앙이 끝난 뒤 노드마다 nftables `inet opl_ovn_<태그>`를 건다. 지운 노드의 SB chassis 청소는 SB 리더인 중앙의 에이전트로 옮긴다.
- **경보는 리더가** Raft와 리더 OvnSync의 10초 관찰(게이트웨이 주인·LB 멤버 건강)로 평가한다.
- **이 기능을 쓰지 않는 클러스터는 바이트까지 지금과 같다**(NB 행, QoS 없는 tap 명령, nftables 글, cloud-init 씨앗, 잠금을 켜지 않은 OVN 단위). 기능 하나 **`sdn-services`**가 새 칸·리소스를 가린다(섞인 클러스터는 409 `cluster_upgrading`).

**Tech Stack:** Rust(opl-types·opl-cluster·opl-driver·opl-reconciler·opl-qemu·opl-api·oplctl·opld), OVN 24.03·Open vSwitch 3.3(Ubuntu 24.04 꾸러미), OVSDB JSON-RPC, tc(`clsact`·matchall `police`), nftables, iperf3(CI), Docker(CI 여러 노드), React 19·TanStack Query, SVG(아이소메트릭 — WebGL 없음), Vitest·msw·axe, Playwright. 새 의존성 없음.

## 설계 결정

- **LB는 서비스 VM(Octavia Amphora·NSX ALB) 대신 OVN 내장 `Load_Balancer`:** NB 행뿐이고 분산 DNAT·건강 검사·HA(게이트웨이 HA)를 이미 한다 — "NB에 쓰기만"과 같은 길. L7은 사용자가 LB 뒤에 HAProxy VM.
- **LB 붙이기는 VIP 스위치만·게이트웨이 라우터 대신 라우터 + 모든 인터페이스 스위치:** 라우터가 VIP ARP에 답해 같은 서브넷 클라이언트도 닿고(탐침으로 확인), 분산 라우터 모양을 바꾸지 않는다(Octavia OVN 공급자와 같은 모양).
- **바깥 VIP는 유동 IP를 VIP에 붙이기(Neutron) 대신 LB의 칸:** OVN에서는 어차피 LB `vips` 줄이고, 같은 유동 IP 범위·`floating_ips` 할당량을 쓴다.
- **건강 검사 출발 주소는 LB·네트워크마다:** 라우터 포트 주소는 northd의 `svc_monitor_mac` ARP와 다투고, 네트워크마다 나누는 포트는 주인 리소스가 따로 필요하다.
- **QoS는 정책 리소스 대신 NIC 칸, 집행은 `qos_max_rate`(셰이핑) 대신 OVN `QoS` 행:** 보안 그룹·MAC과 같은 자리, VM 권한으로 끝남. 두 방향·DSCP를 한 행에. **단순 NIC도 tc 폴리싱으로 같은 뜻**(Proxmox와 견줄 때 빠지면 안 되고, 옮기기 앞뒤가 같은 뜻).
- **옮기기 단위는 네트워크 통째 대신 VM NIC, 라이브는 NIC 빼고 꽂기 대신 tap 옮기기:** VM마다 실패·되돌림이 되고 게스트에 NIC가 사라지지 않는다. 대가는 `host_mtu` — MTU가 줄면 `restart`.
- **다리는 `localnet`(모든 chassis — 고리) 대신 `l2gateway`:** 한 chassis에 묶이고 계획 66 physnet 길을 그대로 쓴다.
- **잠금은 CA 바꾸기 대신 SB RBAC + 특권 포트 + 주소 허용 목록, 설정 자리는 SB `Connection` 행 대신 `--config-file`:** CA 바꾸기는 모든 노드 인증서를 바꾸는 큰 일이고 OVS에는 CRL이 없다. 허용 목록은 Raft 멤버십을 1초 안에 따른다. 설정 파일은 서버마다 자기 주소다.
- **경보는 노드마다 대신 리더:** SDN 상태는 클러스터 전체의 것이고 관찰은 리더 OvnSync에만 있다.
- **토폴로지는 힘 배치 그래프·WebGL 대신 2.5D SVG 층 배치:** 사용자가 정한 모양(3D처럼 보이는 2D), 결정적이고 계획 70과 그림 조각을 나눈다.

## 완료 기준 (계획 67)

- 옛 JSON(`NicSpec`·`SdnSpec`·`SdnStatus`·`NodeStatus`·`NodeSdn`·`FolderQuota`·`FolderUsage`)이 바이트 그대로이고, LB·QoS·옮기기를 쓰지 않는 클러스터의 NB 행(계획 66 고정물에 연산 0개), QoS 없는 VM의 tap 명령, nftables 규칙 글, cloud-init 씨앗, 잠금을 켜지 않은 OVN 단위가 계획 66과 같다. 업그레이드 중 새 쓰기는 409 `cluster_upgrading`이고 노드는 `status.qos`·잠금 상태를 쓰지 않는다.
- 부하 분산기가 같은 서브넷·다른 서브넷 클라이언트의 연결을 멤버 둘에 나누고(바깥을 뗀 라우터도), 출발지 고정이면 같은 멤버로, 건강 검사가 죽은 멤버를 상한(30초) 안에 빼고 되살리면 넣으며, 모두 죽으면 곧바로 거절한다. 바깥 VIP가 물리 망에서 닿고 멤버는 바깥 주소를 보며, 게이트웨이 넘김 뒤 GARP로 다시 닿는다.
- SDN NIC QoS가 보내기·받기·실행 중 바꿈에서 ±15% 안이고 DSCP가 받는 쪽에 보이며, 단순 NIC tc가 같은 측정을 내고 남의 tc 필터를 두며 같은 값은 다시 넣지 않는다. Geneve 너머도 같다.

## 알고 받아들인 제한

- **여러 노드 시험은 컨테이너다:** 커널 하나, 물리 망은 호스트 Linux 브리지다. 실제 하드웨어 장애의 넘김 시간, 물리 스위치의 DSCP 처리, 높은 속도의 QoS 정확도(veth), 게스트 OS의 링크 다시 보기·DHCP 다시 묻기(게스트 없는 VM)는 보지 않았다. **`sdn_quorum_lost`는 순수 시험으로만** 보았다(중앙 둘을 죽이면 같은 컨테이너의 Orbivisor Raft도 정족수를 잃는다).
- **LB:** VIP·건강 검사는 IPv4만, UDP 검사는 "ICMP가 오지 않으면 online"이라 약하다. 죽은 멤버는 새 연결에서만 빠진다. VIP 네트워크는 라우터 인터페이스여야 한다. 넘김 시간은 간격 2초·`fall` 2로 쟀고 기본값(5초·3번)은 재지 않았다. LB는 복제·원격 복제를 따라가지 않는다.
- **QoS는 폴리싱이다:** UDP는 넘는 만큼 잃고, 기본 버스트(속도의 0.8초분)가 짧은 측정을 부풀린다(5초 57.7 Mbit/s — 시험은 `-O 3`). **단순 NIC tc는 opld 재시작 뒤 다시 맞추지 않는다**(커널이 들고 있음 — 어긋나면 `vm hotplug`).
- **옮기기:** **cloud-init이 있는 VM은 instance-id가 바뀌어** 다음 부팅에 인스턴스마다 하는 일(SSH 호스트 키 따위)을 다시 한다(고정하려면 옛 씨앗 바이트가 바뀌어 하지 않음 — 계획과 화면이 경고). 방식은 옮기기 하나에 하나다(웹도). 켜진 VM이 chassis가 아닌 노드에 있으면 `restart`도 막힌다. 브리지·VLAN 원본의 MTU는 1500으로 본다. 다리는 노드 하나를 지나고 넘김이 없으며, **살아 있는 다리 노드는 바꿀 수 없다**(409 `migration_bridge_laid` — 모두 되돌린 뒤 `--bridge-node`로 다시, 지운 노드만 `resume --bridge-node`).
- **잠금:** OVN 24.03 RBAC는 `Port_Binding`·`MAC_Binding`·`FDB`에 id를 보지 않는다(가로채기를 막지 못하고 탐지 경보도 아직 없음). NB는 모든 멤버 노드가 쓴다. 루프백은 `127.0.0.1`·`::1`만 받는다. 미리 확인은 집합 밖 상대 하나라도 막는다(`force`). 계획 65·66으로 세운 클러스터는 관리자가 켤 때까지 잠기지 않는다.
- **토폴로지:** 네트워크 200·VM 2000에서 SVG 원소 약 11,400개로 설계 목표 5000을 넘는다(VM이 판마다 열 개라 접히지 않음 — 띠가 거르기를 권함, VM 블록을 한 경로로 그리는 최적화는 계획 70).
- **웹:** 유동 IP를 읽을 수 없는 VM 주인은 화면에서 그 유동 IP를 찾을 길이 없다(`vm get`·VM 보기에 NIC 유동 IP가 없음 — CLI·API로 키를 알아야).
