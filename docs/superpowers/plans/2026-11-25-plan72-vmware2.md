# Orbivisor 계획 72: VMware 이전 2 — vCenter 일괄 가져오기, CBT로 내리는 시간을 줄인 따뜻한 이전, OVA/OVF 내보내기 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 계획 29·30의 "한 대씩, 꺼진 채로" 가져오기를 VMware 이탈 회사의 실제 일에 맞춘다. **vCenter 일괄 가져오기**: 저장한 vCenter·ESXi 연결로 인벤토리 나무에서 VM 여러 대를 고르고, 매핑 규칙(네트워크·데이터스토어 → 풀·폴더·노드·장치·MAC) 한 번으로 VM마다 미리 확인(계획 71 만들기 검사 + VMware 쪽 검사)을 보고, 동시 수를 지키며 VM마다 이어 가는 Task로 옮긴다. **따뜻한 이전**: 원본이 켜진 채 스냅샷 위에서 전체 복사, CBT `QueryChangedDiskAreas`로 바뀐 블록만 반복 동기화, 전환 때만 원본을 끄고 마지막 델타 → VM 만들기 → 켜기, 실패하면 원본을 다시 켜는 자동 되돌림, 켠 뒤 손 되돌리기와 마무리. 원본은 절대 지우지 않는다. **OVA/OVF 내보내기**: 꺼진 VM을 streamOptimized VMDK + OVF + SHA-256 매니페스트로 dir·NFS 풀에 쓰고, 하나의 OVA로 흘려 내려받는다.

**Architecture:**
- **새 리소스 넷**(`opl-types/src/{vmware,vm_export}.rs`): `vmware-source`(연결 — 비밀번호는 Raft에, 보기·watch·감사·`Debug`에서 뺌, 지문 고정), `vmware-migration`(계획 — 규칙·한도·동기화 주기·전환 정책, 요약 상태), `vmware-vm`(VM 하나의 이전 — 디스크마다 changeId·복사량·볼륨, 우리 스냅샷 moref, 바꾼 원본 설정의 옛 값, 전환 걸음), `vm-export`. 기능 `vmware-migrate`·`vm-export`(섞인 클러스터는 409 `cluster_upgrading`), 권한 `vm.export`(operator에 없음). `VmImport`·`ImportRun`은 바이트 그대로.
- **vSphere SOAP 손 XML 클라이언트**(`opl-api/src/vmware/`, 새 의존성 없음): 계획 30의 지문 고정 TLS를 `http.rs`로 꺼내 keep-alive·POST·Range·쿠키를 더하고, 스무 메서드 남짓(세션·`PropertyCollector` 인벤토리·`ReconfigVM`·스냅샷·`QueryChangedDiskAreas`·전원·`AcquireGenericServiceTicket`·`SearchDatastore`)을 `roxmltree`로 읽는다. vCenter면 호스트 티켓으로 VM이 있는 ESXi에 바로 붙어 flat extent를 범위 읽기(호스트 인증서는 vCenter가 알려 준 PEM으로 고정), 안 되면 vCenter `/folder`. 선택 길 `VddkReader`(운영자가 깐 nbdkit-vddk → 우리 NBD 클라이언트, vSAN·vVols).
- **회차 알고리즘**: 첫 회차 CBT 켜기 → S1 → `"*"` 할당 구역 → 기반 flat 읽기. 다음 회차 S(n+1) 만들기 → S(n) 지우기(합치기 — 기반이 늘 최신 스냅샷 시점) → changeId 이후 바뀐 구역 → 기반에서 읽기. 회차는 다시 해도 같다(기반이 얼어 있음) — 체크포인트로 이어 간다. 쓰기는 대상 볼륨(`Pending`, 어느 풀이든)을 `qemu-nbd` 쓰기 대상으로 열고 그 자리에(`opl-store` NBD `write`·`write_zeroes`·`flush`) — 업로드 디렉터리를 거치지 않는다.
- **리더 `VmwareScheduler`(15초)**가 계획마다 동시 수·ESXi 호스트당·대상 노드당 한도와 대역을 지키며 `vmware-sync`(전체·델타)·`vmware-cutover` Task를 만든다(델타·전환이 먼저). 전환은 걸음(`Preparing → StoppingSource → FinalSync → CreatingVm → StartingVm`)을 Raft에 먼저 적고 하는 이어 가는 Task이고, `StoppingSource` 뒤 실패는 대상 VM 지움 → 원본 다시 켬 → NIC·설명 되돌림(`RolledBack`).
- **내보내기**: `qemu-img convert -O vmdk -o subformat=streamOptimized`(`export_vmdk`) → SHA-256 → OVF 1.0 + `vmw` 서술자(`ovf_write.rs` — 계획 29 읽개로 왕복 시험) → `.mf`. 내려받기는 토큰 링크로 ustar를 그 자리에서 흘림(크기를 알아 정확한 `Content-Length`).
- **시험**: 의미는 **가짜 vSphere**(기능 `fake-vsphere` — 기반+델타 체인·합치기·CBT 블록 기록·게스트 쓰기·결함 주입, 실행 파일 `fake-vsphere`), 꼴은 GitHub **`vmware-sim`**(govmomi `vcsim` 컨테이너 — 실제 WSDL 타입으로 만든 상대, `govc import.ova`로 우리 OVA 받기, nbdkit으로 VDDK 배선). 실제 vCenter·ESXi·VDDK는 가이드의 손 확인 절차.

**Tech Stack:** Rust(axum·utoipa·serde·hyper 1·rustls·roxmltree·sha2, `opl-api`·`opl-types`·`opl-store`·`opl-driver`·`oplctl`·`opld`), `qemu-nbd`·`qemu-img`, 선택 `nbdkit`(+ VDDK), React 19·TypeScript·Vite(늦게 읽는 경로), TanStack Query·watch, react-i18next(늦게 받는 문구), vitest + msw + axe-core, Playwright(opld `web-it`), GitHub Actions(`vmware/vcsim`·`govc`). 새 Rust·npm 의존성 없음.

## 설계 결정

- **SOAP vim25를 손 XML로:** REST에는 CBT·티켓·ESXi 단독이 없고, WSDL 생성은 쓰는 스무 메서드에 비해 너무 크다. 꼴 실수는 vcsim(govmomi가 실제 WSDL로 만든 상대) 시험이 잡는다.
- **"S(n+1) 만들고 S(n) 지우기"로 기반 flat을 늘 최신 일관 상태로:** VDDK(독점·재배포 금지) 없이, 델타 체인 형식(seSparse) 해석 없이 바뀐 구역을 기반 파일에서 범위 읽기로 얻는다. 대가: 회차마다 합치기 I/O, 사용자 스냅샷 VM 거절, 켜진 VM의 기반 읽기는 실제 vCenter 손 확인이 남음(안 되면 선택 VDDK 길).
- **중간 회차는 crash-consistent, 마지막 회차는 원본을 끈 뒤:** 정지(quiesce)를 쓰지 않아 stun이 짧고 Tools·VSS가 필요 없으며, 전환 결과는 깨끗이 끈 디스크와 같다.
- **대상 볼륨에 그 자리 쓰기(`qemu-nbd` 쓰기 대상):** 델타가 같은 볼륨에 덮어써야 하고, 계획 30의 "디스크 크기만큼 업로드 디렉터리" 한계가 사라진다. 모든 풀 형식을 계획 68이 이미 `qemu-nbd`로 연다.
- **VM마다 리소스 + 리더 스케줄러의 짧은 회차 Task:** 한 리소스 목록은 동시 Task가 revision을 다투고, VM마다 며칠 도는 Task는 동시 수 자리를 붙잡는다. 회차 Task는 짧고 다시 해도 같아 리더 바뀜·다시 시작에 강하다.
- **자격 증명은 Raft에(가림):** 따뜻한 이전은 며칠 가고 어느 노드에서든 회차가 돈다. 원격 토큰·S3 비밀과 같은 자리·같은 가림, 원본 관리는 `cluster.admin`만.
- **원본 안전은 규칙이자 시험:** 원본에 하는 호출은 정한 표뿐, 지우기는 Raft에 적은 우리 스냅샷에만, 끄기는 전환 걸음에서만, 바꾼 설정은 옛 값을 먼저 적고 되돌림. 가짜 vSphere 시험마다 끝에 원본 디스크·사용자 스냅샷이 그대로인지 본다.
- **게스트는 고치지 않는다:** 안전한 장치 기본값(지금 규칙) + 따뜻한 이전이 주는 "원본에서 고치면 다음 델타가 옮긴다" + 드라이버 ISO. virt-v2v·게스트 안 명령은 의존성과 위험이 크다(나중).
- **내보내기는 풀에 OVF 폴더, 내려받기는 흘리는 OVA:** OVA 파일을 쓰면 공간이 두 배이고, 폴더는 NFS로 ESXi가 바로 쓴다. VMDK는 이미 쓰는 `qemu-img`가 만든다.
- **화면은 가져오기 탭 안 보기:** 계획 61 규칙 — 사이드바·탭을 늘리지 않는다.

## 알고 받아들인 제한

- **실제 vCenter·ESXi에서 시험하지 않았다:** 가짜 vSphere(의미)와 govmomi vcsim v0.56.2(SOAP 꼴)뿐이다. vcsim은 `QueryChangedDiskAreas`가 없어(`MethodNotFound`) CBT는 가짜로만 보았다. 켜진 VM 기반 flat의 `/folder` 범위 읽기·호스트 티켓 한 번 쓰기·합치기 시간·무료 ESXi 거절 문구는 가정이고, 가이드(`backup.md` "실제 vCenter에서 손으로 확인하기")에 손 확인 절차를 두었다.
- **사용자 스냅샷·독립 디스크·RDM·FT·멀티라이터 VM:** 미리 확인이 따뜻한 이전을 막는다(`vmware_rdm`·`vmware_ft`·`vmware_multi_writer`·`vmware_independent_disk`, 사용자 스냅샷은 회차를 건너뛰고 경고 — 차가운 이전은 거절). 차가운 이전은 꺼진 VM의 flat 디스크만.
- **vSAN·vVols는 VDDK 길만:** vSAN·vVols는 `vmware_needs_vddk`로 막히고 `--vddk`면 운영자가 깐 nbdkit-vddk로 읽는다. VDDK는 독점이라 넣지 않고, CI는 nbdkit `file` 플러그인으로 배선만 본다.
- **회차마다 합치기 I/O:** 회차마다 스냅샷 지우기(합치기)가 원본 데이터스토어에 델타 크기만큼 쓴다. VMware 백업 도구의 스냅샷이 있으면 그 회차를 건너뛰고 경고한다.
- **게스트를 고치지 않음:** 게스트 안에서 명령을 돌리지 않는다. RHEL 계열 initramfs(`dracut`)는 원본에서 미리(다음 델타가 옮김), Windows는 SATA·e1000e + 선택 virtio-win ISO, NIC 이름 바뀜은 켠 뒤 고친다. 실제 게스트 부팅은 확인하지 못했다(aarch64 TCG, VMware 게스트 없음 — 시험은 바이트 같음).
- **켠 뒤 revert는 대상 쓰기를 버림:** `revert`는 대상 VM을 끄고 원본을 켠다 — 전환 뒤 대상에서 쓴 데이터는 원본으로 가지 않는다(확인 이름을 적어야 하고 웹·가이드가 알림).
- **내보내기는 꺼진 VM만:** 켜진 VM·백업에서 내보내기는 없다. vTPM·CD·cloud-init·NUMA·SDN 주소 등은 경고로 빠지고, `addressType=manual`의 MAC 지킴·실제 vSphere·ovftool·VirtualBox 받기는 손 확인이다(vcsim `govc import.ova`만). VMware 이전으로 만든 VM의 guestId는 아직 원본 값을 쓰지 않는다(§18 스테이지 8).
- **속도:** 가짜 vSphere 루프백 + 가짜 스토리지 디버그 빌드에서 전체 복사 107 MiB/s, 64 KiB 블록 16개 델타 0.28초뿐이다. 실제 망·ESXi `/folder`·VDDK 처리량은 모른다.
