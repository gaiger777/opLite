# Orbivisor 계획 74: 이름 맞추기 2 — 서비스·경로·환경 변수·쿠키·크레이트를 orbivisor로 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 운영자가 노드에서 만나는 이름을 제품 이름에 맞춘다 — `orbivisord.service`, `orbivisor-ovn-*`, `/etc/orbivisor/orbivisord.toml`,
`/var/lib/orbivisor`·`/run/orbivisor`·`/var/log/orbivisor`, `ORBIVISOR_*`, `orbivisor_session`, 크레이트 `orbivisor-*`. 업그레이드는
`apt-get dist-upgrade` 한 번, VM은 멈추지 않고, 옛 이름은 링크·별칭(영구) 또는 경고와 함께 한 릴리스 동안 받는다.

**Architecture:** 1단계는 크레이트 이름만 기계적으로(동작 같음). 2단계 `orbivisor-types::legacy::env`로 실행 환경 변수 두 이름. 3단계
데몬 시작 때 `layout::migrate`(`renameat2` 맞바꿈)로 디렉터리를 옮기고 옛 이름을 링크로, 패키지 유닛을 `orbivisord.service` + 별칭
`opld.service`로, postinst가 enable 링크·덮어쓰기를 옮김, OVN 유닛은 별칭 링크로 바꿔 끊김 없이, 일시 유닛 두 접두사, 섞인 동안 저장
경로는 기능 `orbivisor-layout`. 4단계 쿠키 두 이름·문서·이름 시험.

**Tech Stack:** Rust(libc `renameat2`), bash(postinst·패키징 시험), Go(Terraform 공급자 환경 변수), React(번역 문장만). 새 의존성 없음.

**설계 문서:** `docs/superpowers/specs/2026-11-26-naming-orbivisor-design.md`(상위: `2026-11-10-rename-orbivisor-design.md`)
**선행 계획:** 계획 1~73 (완료)
