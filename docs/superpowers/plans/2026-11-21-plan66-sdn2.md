# Orbivisor 계획 66: SDN(OVN) 2 — 외부(공급자) 네트워크, 라우터, 게이트웨이 HA, SNAT·유동 IP, DHCPv6·RA, OVN 보안 그룹 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 계획 65의 SDN 네트워크는 고립된 L2였다(밖으로 나가지 못하고, SDN NIC에 보안 그룹은 400). 이 계획은 "OpenStack OVN 기능처럼"의 나머지 핵심을 넣는다: 노드의 물리 망에 붙는 **외부(공급자) 네트워크**(`localnet`)와 노드 **physnet**(관리자 Linux 브리지에 veth), SDN 네트워크를 잇는 **분산 라우터**와 정적 경로, 라우터마다 **게이트웨이 HA**(`HA_Chassis_Group`, BFD), **SNAT**와 **유동 IP**(VM 노드에 physnet이 있으면 저절로 분산), 라우터에 붙은 서브넷만의 **DHCP 기본 경로**, IPv6 **SLAAC·DHCPv6·RA**(EUI-64 IPAM), 그리고 **SDN NIC의 보안 그룹**을 단순 NIC와 같은 리소스·같은 뜻(순서대로 처음 맞는 규칙)으로 OVN `Port_Group`·`ACL`에 건다. 부하 분산·QoS·토폴로지 화면·옮기기 도구·SB RBAC·알림은 계획 67이다.

**Architecture:**
- **계획 65 그대로**: 원하는 상태는 Raft에만 있고 리더 `OvnSync`만 NB에 쓴다(다른 것만, 펜싱 토큰). API는 OVN을 부르지 않는다. 노드 `SdnAgent`는 자기 OVS·veth만 만진다.
- **새 리소스 `Router`·`FloatingIp`**(네트워크 폴더에 삶, 할당량 `routers`·`floating_ips`), `NetworkSpec.sdn.provider { physnet, vlan }`, 서브넷 `floating_pools`·`ipv6_mode`, `NodeSpec.sdn { physnets, gateway }`. Raft 겹침 키 `ip`(VM·라우터·유동 IP가 한 공간)·`router-net`·`fip-nic`·`physnet`.
- **NB**: `localnet` LSP, `Logical_Router` + 라우터 포트 + 분산 게이트웨이 포트(DGP), 정적 경로, `NAT`(`snat`·`dnat_and_snat`), 라우터마다 `HA_Chassis_Group`(관리자 우선순위 + HRW 순위, 앞 5개), RA·DHCPv6, **그룹 목록마다 `Port_Group`** + 우선순위 띠 ACL. 트랜잭션 차례 PG → 네트워크 → 라우터 → 지우기로 **실패하면 닫힘**(PG가 없으면 포트가 생기지 않음).
- **이 기능을 쓰지 않는 클러스터는 바이트까지 지금과 같다**(Raft JSON, NB 행, nftables 규칙 글, cloud-init 씨앗). 기능 하나 **`sdn-routing`**이 새 칸·리소스를 가린다(섞인 클러스터는 409 `cluster_upgrading`).
- **여러 노드 시험은 한 러너의 privileged systemd 컨테이너 셋**(`ci/sdn-node/Dockerfile`, 새 CI `sdn-multinode`)이 Orbivisor 노드 셋 — 진짜 chassis 셋·OVN Raft 셋·Geneve.

**Tech Stack:** Rust(opl-types·opl-cluster·opl-driver·opl-reconciler·opl-api·oplctl·opld), OVN 24.03·Open vSwitch 3.3(Ubuntu 24.04 꾸러미), OVSDB JSON-RPC, systemd, Docker(CI 여러 노드), React 19·TanStack Query, Vitest·msw, Playwright. 새 의존성 없음.

## 설계 결정

- **라우터는 L3 에이전트(이름공간·iptables·keepalived) 대신 OVN 고유**(분산 라우터 + DGP): 계획 65의 "NB에 쓰기만"과 같은 길이고 ML2/OVN이 L3 에이전트를 없앤 까닭과 같다.
- **게이트웨이 그룹은 라우터마다 + HRW:** 외부 네트워크마다 그룹 하나면 모든 라우터의 주인이 한 노드다. Neutron의 "가장 덜 쓴 chassis"는 상태가 필요하다. HRW는 상태 없이 고르게 흩고 노드를 더하고 빼도 조금만 움직인다.
- **유동 IP 분산은 전역 스위치 대신 저절로:** VM의 노드(마이그레이션이면 둘)가 모두 바깥 physnet을 준비했으면 분산, 아니면 중앙 — 외부 망이 없는 계산 노드에서 끊기지 않는다.
- **유동 IP는 NIC 칸 대신 리소스:** 공인 주소는 VM보다 오래 살고 권한·할당량이 주소에 붙는다.
- **physnet은 NIC 옮기기 대신 관리자 Linux 브리지에 veth:** 관리자의 망 설정을 빼앗지 않고 되돌리기 쉽다(veth 한 단의 대가). 설정은 노드 파일 대신 Raft `NodeSpec.sdn`(스케줄러·게이트웨이 순위·분산 유동 IP가 써야 함).
- **보안 그룹 뜻은 Neutron식(허용만) 대신 지금 뜻 그대로, 그룹 목록마다 Port_Group:** 단순 NIC의 그룹이 한 글자도 바뀌지 않고 같은 그룹은 어디서나 같은 뜻이다. 그룹마다 PG로는 "처음 맞는 것"을 그릴 수 없고, NIC마다 PG는 최악이 같다.
- **IPv6는 NAT66 대신 라우팅 + 윗단 정적 경로**(보기가 그 줄을 보임). **공급자 DHCP 기본은 끔**(물리 망 DHCP와 다툼).
- **여러 노드 시험은 러너 둘·VM 셋 대신 한 러너의 systemd 컨테이너 셋:** OVN의 `ovn-fake-multinode`와 같은 꼴이고 설치 Task·에이전트가 systemctl·apt를 그대로 써 시험 전용 코드 길이 없다.

## 완료 기준 (계획 66)

- 옛 JSON(`NetworkSpec`·`Subnet`·`NodeSpec`·`NodeStatus`·`FolderQuota`·`FolderUsage`)이 바이트 그대로이고, 라우터·공급자·`ipv6_mode`·SDN NIC 그룹을 쓰지 않는 클러스터의 NB 행(계획 65 고정물에 연산 0개), nftables 규칙 글(`the_ruleset_text_is_unchanged`), cloud-init 씨앗이 계획 65와 같다. 업그레이드 중 새 쓰기는 409 `cluster_upgrading`이고 노드는 새 상태 칸을 쓰지 않는다.
- 노드 physnet이 관리자 브리지에 veth 하나만 더하고 남의 매핑·옵션을 두며, 재부팅 흉내(veth 지우기) 뒤 되살아나고, 빼면 내 것만 사라진다. 공급자 네트워크의 `localnet`으로 물리 망 이름공간과 ping이 된다.
- 라우터가 동서를 분산 라우팅하고(여러 노드: 게이트웨이 노드의 Geneve에 0개), DHCP로 기본 경로를 주며, SNAT가 주인 게이트웨이의 물리 포트로만 나가고, 유동 IP가 밖에서 닿고 나가는 주소가 유동 IP다. 분산 유동 IP는 VM 노드의 물리 포트로만 드나들고 physnet을 빼면 중앙으로, 다시 넣으면 분산으로 돌아간다. 두 chassis 라이브 마이그레이션 뒤 유동 IP가 새 노드로 옮겨 간다.
- 게이트웨이 넘김(점잖은 멈춤·`kill -9`·노드 통째)과 되돌아감이 상한(15초) 안이고, 노드를 잃어도 Orbivisor Raft·OVN 정족수로 새 유동 IP가 닿으며, 죽은 중앙을 `sdn central remove`가 실제 `cluster/kick`으로 내쫓는다.
- RA로 EUI-64 주소와 기본 경로, 상태 있는 DHCPv6로 할당 범위 주소를 받고, Ubuntu 클라우드 이미지 게스트가 cloud-init `ipv6_slaac`로 EUI-64 주소에서 답한다.
- 같은 보안 그룹을 건 nftables 이름공간과 OVN 이름공간의 탐침 표가 같고, 순서를 바꾸면 처음 맞는 규칙이 이기며, 목록을 바꾸는 동안 열린 순간이 없고, 다른 것은 설계 §11.4 표의 것뿐이다. PG 쓰기가 실패하면 포트가 생기지 않는다(가짜 NB).
- API: 권한 행렬(공급자·노드 `sdn`은 루트, 라우터·유동 IP는 네트워크 폴더), 409들(`router_in_use`·`network_in_use`·`fip_in_use`·`fip_not_routable`·`physnet_in_use`·`physnet_conflict`·`ip_in_use`·`subnet_in_use`·`quota_exceeded`), 할당량, VM 지우기의 유동 IP 떼기, EUI-64·유동 IP 풀 IPAM이 맞다.
- 웹: 라우터 서랍·게이트웨이 표·경고, 유동 IP 붙이기의 막힘 까닭, 공급자 네트워크 만들기, 노드 physnet 편집, SDN NIC 그룹이 vitest로, SDN 설정 전 빈 상태와 막힌 만들기가 브라우저 E2E로 보인다.

## 알고 받아들인 제한

- **여러 노드 시험은 컨테이너다:** 커널이 하나이고 물리 망은 호스트 Linux 브리지다. 실제 하드웨어 장애의 넘김 시간, 물리 VLAN 스위치, 게스트 OS의 응답(게스트 없는 VM), 컨테이너 안 QEMU가 KVM으로 돌았는지는 보지 않았다. **여러 chassis에 걸친 보안 그룹**(설계 §14 보는 것 10번)은 시험하지 않았다 — 같은 뜻은 노드 하나의 `ovn` 작업이 nftables와 견줘 본다.
- **바깥 → 안의 큰 DF 패킷은 ICMP 없이 버려진다**(OVN 24.03의 `gateway_mtu`는 DGP로 나가는 방향만 잰다). 가이드가 underlay MTU 올리기·공급자 MTU 줄이기·MSS 고정을 적는다.
- **되돌아감은 늘 일어난다**(OVN에 막기가 없다). 넘김 때 맺은 SNAT 연결은 끊긴다. 고친 노드는 유지보수로 둔 채 돌려놓는다.
- **기본 경로는 DHCP 갱신 때 받는다.** 라우터를 붙여도 instance-id가 그대로라 부팅한 고정 주소 게스트는 cloud-init 게이트웨이를 다시 적용하지 않는다. SDN NIC 둘 이상이 라우터 있는 네트워크면 기본 경로가 둘이다.
- **SLAAC 계열은 EUI-64만:** 게스트의 임시·안정 불투명 주소는 포트 보안이 막는다.
- **라우터·유동 IP는 watch가 아니다**(웹은 10초마다 다시 읽음). 게이트웨이 표에 chassis 상태가 없다(`sdn status`).
- **CLI 빈틈:** `folder quota set`에 `routers`·`floating_ips`가 없고 `folder members move`·`grant`가 `router/…`·`floating-ip/…`를 받지 않는다(API·웹). `vm get`의 NIC 줄에 유동 IP가 없다. 웹 폴더 내용 탭·끌어 놓기는 네트워크만이라 라우터·유동 IP 옮기기는 API뿐이다(스테이지 7 보고의 "옮기기는 API·CLI"는 CLI가 아니었다 — 스테이지 8 확인).
- **웹은 SDN NIC 그룹 고르기를 기능 판정 없이 연다**(섞인 클러스터는 저장 때 409). 유동 IP 붙이기·떼기는 유동 IP 보기에만 있다.
- 공급자 네트워크의 라이브 마이그레이션 동안(두 chassis 바인딩) 터널을 쓰므로 1442보다 큰 패킷이 몇 초 버려진다. 재부팅 뒤 orbivisord가 뜰 때까지 그 노드의 공급자 트래픽은 끊긴다. VLAN 인식 브리지의 트렁크는 veth를 매달 때만 연다.
