## 메뉴(2단 사이드바)

**왼쪽 사이드바 하나가 메뉴의 전부다(계획 77).** 연관된 기능끼리 묶은 **묶음 9개**(아이콘+이름)가 위에, **관리**가 맨 아래에
있다. 묶음 제목을 누르면 그 아래 **항목**(둘째 단계)이 펼쳐지고 접힌다. 예전의 영역 탭과 보기 전환은 없다. 맨 위
**찾기·명령 ⌘K**는 [명령 팔레트](#명령-팔레트)를 연다.

| 묶음 | 항목 → 주소 |
|---|---|
| 개요 | 대시보드 `/` · 인프라 지도 `/cluster/map`(계획 70) · 경보 `/alerts`(규칙·보낸 알림은 화면 안 탭) |
| 가상 머신 | 모든 VM `/vms`(폴더로 보기 `/vm-folders`) · 템플릿 `/templates` · VM 만들기 `/vms/-new`(옛 빌더 주소 `/vms/-new/builder`는 넘김, 어디든 VM 만들기 권한) |
| 이미지·이전 | OS 이미지 `/images` · ISO 파일 `/isos` · 가져오기(OVA·ESXi) `/imports` · VMware 이전(켠 채 복사) — 화면 안 탭: 이전 계획 `/vmware-migrations` \| 원본 연결 `/vmware-sources`(계획 72) · 내보내기 `/vm-exports` |
| 스토리지 | 스토리지 풀 `/storage-pools`(폴더로 보기 `/storage-folders`) · 디스크(볼륨) `/volumes` · Ceph `/ceph` |
| 네트워크 | 네트워크 `/networks`(폴더로 보기 `/network-folders`) · 방화벽(보안 그룹) `/security-groups` · 라우터·유동 IP(화면 안 탭: 라우터 `/routers` \| 유동 IP `/floating-ips`) · 부하 분산 `/load-balancers` · SDN(가상 네트워크) `/sdn` · 토폴로지 그림 `/networks/topology` |
| 클러스터·가용성 | 노드 `/nodes` · 클러스터(멤버·CA) `/cluster`(CA 지문·내려받기 — 공인 인증서는 관리 › 보안·인증서, 두 화면이 서로 링크) · 자동 복구(HA) `/ha-groups` · 장애 감지(HA 검사) `/ha-checks` · 배치 규칙·자동 균형(화면 안 탭: 배치 규칙 `/placement-rules` \| 최적 배치 `/placement`) |
| 백업·복구 | 백업 `/backups`(파일 찾아보기 `/backups/<id>/files` — 계획 69) · 백업 일정 `/backup-jobs` · 백업 저장소 `/backup-stores`(계획 68) · 원격 클러스터·복제(화면 안 탭: 원격 복제 `/remotes` \| 원격 클러스터 관리 `/remotes/-manage`(admin)) · DR(재해 복구) `/dr-plans`(실행 `/dr-runs/<id>`도 — 계획 76) |
| 기록 | 작업 기록 `/tasks` · 변경 기록 `/history` · 코드로 관리(YAML) `/apply-sets`(루트 `system.read` — 계획 73) · 감사 로그 `/audit`(admin) |
| 관리 (맨 아래) | 일반·업데이트 `/settings` · 사용자·그룹(화면 안 탭: 사용자 `/settings/users` \| 그룹 `/settings/groups`) · 역할·권한(화면 안 탭: 역할 `/settings/roles` \| 권한 `/settings/permissions`, admin) · 로그인 방식(인증 영역) `/settings/realms` · 보안·인증서(화면 안 탭: 보안 `/settings/security`(admin, 2단계 인증 정책) \| 인증서 `/settings/certificates`(루트 `cluster.read`, ACME)) · 알림 보낼 곳 `/settings/notifications`(admin) · 구독 `/settings/subscription` |

- **내 것은 사용자 메뉴에.** 내 API 토큰(`/settings/tokens`)과 내 2단계 인증(`/settings/account`)은 누구나 자기 것을 다루므로
  사이드바가 아니라 오른쪽 위 사용자 메뉴에 있다. 이동 경로는 "내 계정 › …"이다.
- **펼침 기억.** 펼친 묶음은 사용자별로 브라우저에 기억한다(`opl.<사용자>.nav.open`). 기억이 없으면(처음 로그인, 저장소를 못 씀) 모든 묶음을 펼친다. 접은 묶음을 기억하고, 데스크톱 사이드바와 ☰ 서랍이 같은 상태다.
  다른 묶음의 화면으로 가면(링크·팔레트·단축키) 그 묶음이 펼쳐진다. 저장소를 쓸 수 없는 브라우저에서도 메뉴는 그대로 동작한다.
  주소·검색어는 기억하지 않는다 — 항목 링크는 늘 그 화면의 목록 주소다.
- **숫자.** 개요 › 경보 옆에 울리는 경보(critical·warning) 수, 기록 › 작업 기록 옆에 24시간 안에 실패한 작업 수가 보인다(끝 시각이
  없는 옛 노드의 작업은 세지 않는다). 새 요청 없이 머리줄 종이 받는 목록에서 센다.
- **폭.** 1280px 이상은 펼친 2단 사이드바(240px)로 시작한다. 그보다 좁으면 **아이콘 레일**(56px)이고, 묶음 아이콘을 누르거나
  `Enter`·`Space`·`↓`로 그 묶음의 **펼침 창**(메뉴)을 연다(`↑`·`↓` 고르기, `Esc`면 아이콘으로 돌아감). 아이콘에 마우스를
  올리거나 키보드로 오면 묶음 이름이 툴팁으로 보이고, 화면 읽기 프로그램은 지금 화면의 묶음인지와 경보·실패 수를 설명으로 읽는다.
  아래 `《`·`[`로 언제든 접고 펴며 고른 것은 사용자별로 기억한다. 768px보다 좁으면 머리줄 ☰가 같은 2단 메뉴를 서랍으로 연다.
- **화면 안 탭.** 한 항목에 화면이 둘 이상이면(라우터 | 유동 IP 등) 그 목록 화면 위에 탭이 보인다. 상세 화면(VM·노드·풀 등)
  안의 탭은 그대로다.
- **목록 | 폴더.** 모든 VM·스토리지 풀·네트워크 목록의 오른쪽 위 아이콘 두 개(목록으로 보기 | 폴더로 보기)가 같은 목록을
  왼쪽 트리와 그 폴더의 표("하위 포함" 칩)로 바꾼다. 폴더 상세(`/vm-folders/:id` 등)는 `내용 | 할당량 | 권한` 탭이다. 행을 트리로
  끌어 놓거나 일괄 막대의 "폴더로 옮기기…"로 옮긴다. VM 상세에는 "권한" 탭이, 풀·네트워크 행에는 같은 내용을 서랍으로 여는
  방패 단추가 있다([폴더와 권한](folders.md#웹-화면)).
- **권한.** 화면은 `/permissions/mine`(전역 역할과 폴더·객체 grant를 합친 내 권한)으로 **객체마다** 할 수 있는 동작만 보인다.
  루트에서 읽을 수 없는 종류의 항목(노드·Ceph·보안 그룹·백업 일정·HA·배치·관리 › 일반·구독 등)은 숨기고, 보이는 항목이 하나도
  없는 묶음도 숨긴다. 숨긴 화면의 주소를 바로 열면 "이 화면을 볼 권한이 없습니다"다. 폴더 권한만 있는 사용자는 목록·트리·팔레트에
  자기 폴더의 것만 본다. 서버가 실제로 막는 것은 그대로다([폴더와 권한](folders.md)).
- **상세 화면은 그 항목에 속한다.** `/vms/web`·`/vms/web/edit`은 모든 VM, `/vms/-new`는 VM 만들기,
  `/nodes/node1`은 노드, `/vm-folders/x`는 모든 VM(폴더 모양), `/security-groups/web`은 방화벽, `/imports/x`는 가져오기,
  `/vmware-migrations/x`·`/vmware-migrations/-new`는 VMware 이전, `/remotes/dr`(원격 클러스터의 VM)은 원격 클러스터·복제,
  `/apply-sets/web`은 코드로 관리(YAML)다. 콘솔(`/vms/web/console`)만 화면 안 탭 없이 전체 폭이다.
- **원격.** 백업·복구 › 원격 클러스터·복제의 "원격 복제" 탭은 원격 클러스터의 상태 카드, 원격 대상이 있는 백업 일정, 원격 VM
  보기다. 주소·토큰의 추가·고치기·지우기는 같은 항목의 "원격 클러스터" 탭(admin)이다.
- **관리 › 일반·업데이트**는 업데이트 채널·호스트 종료·HA 용량·텔레메트리·Prometheus·CPU(클러스터 CPU 기준과 숨김 목록) 칸이다.
  구독은 따로 항목이다.
- **이동 경로.** 머리줄 왼쪽에 `묶음 › 항목 › 리소스`(화면 안 탭이면 `묶음 › 항목 › 탭`)가 있다. 묶음 이름은 링크가 아니고 항목은
  링크다. 768px보다 좁으면 마지막 둘만 보인다.
- **옛 주소.** 예전 메뉴의 주소는 그대로 열린다(항목 이름만 바뀌었다). 화면이 없어진 주소는 넘긴다: `/users` → `/settings/users`,
  `/realms` → `/settings/realms`, `/tokens` → `/settings/tokens`, 예전 영역 주소 `/infra` → `/nodes`(노드를 못 읽으면 스토리지·네트워크의 보이는 첫 항목), `/protect` → `/backups`,
  `/activity` → `/tasks`, 예전 설정 › 원격 클러스터 `/settings/remotes` → `/remotes/-manage`(설정 읽기 권한 없이도 넘어간다). 쿼리와 해시는 지킨다
  (`/tokens?x=1#a` → `/settings/tokens?x=1#a`). 표는 `web/src/layout/nav.ts`의 `GROUPS`·`LEGACY_REDIRECTS` 한 곳이다.

## 명령 팔레트

`⌘K`(맥)·`Ctrl+K` 또는 머리줄의 검색 상자로 연다. 메뉴를 거치지 않고 모든 화면, 리소스, 동작으로 간다. 새 API를 부르지 않고
화면이 이미 받은 목록에서 찾는다.

- **찾는 것.** VM·노드·스토리지 풀·볼륨·네트워크·보안 그룹·백업 작업·HA 그룹의 이름, 모든 메뉴 항목·화면 안 탭·폴더 모양("클러스터·가용성 › 노드", 예전 메뉴 이름으로도),
  명령(만들기, 테마, 밀도, 단축키 도움말, 로그아웃), 즐겨찾기와 최근 항목. 빈 칸으로 열면 즐겨찾기·최근·이동·명령만 보이고
  리소스는 치면 보인다.
- **순위.** 정확히 같음 > 앞부분 > 낱말 앞부분 > 가운데 부분이다. 점수가 같으면 즐겨찾기와 최근 것이 앞이다. 종류마다
  8개까지 보인다. 여러 낱말(`create pool`)은 통째로 맞지 않으면 낱말마다 맞아야 한다.
- **IP 찾기.** IP를 치면 노드(API 주소), VM의 cloud-init 고정 IP와 NIC MAC, 이미 게스트 정보를 받은 VM의 게스트 IP를
  앞부분부터 맞춘다. `10.0.0.0/24`처럼 CIDR을 치면 그 범위 안의 VM 주소를 찾는다.
- **동작.** `{동사} {VM} [to {노드}]` 꼴이고 동사는 앞이나 뒤에 둔다. 한국어 별칭과 조사(`을`·`를`, `로`·`으로`·`에`)도 받는다.

  | 동사 | 별칭(예) |
  |---|---|
  | start | 시작, 켜기, 켜 |
  | stop | 정지, 끄기, 종료 |
  | reboot | 재시작, 재부팅 |
  | force-stop | 강제 정지, 강제종료, kill |
  | migrate | 옮기기, 이동, 마이그레이션, move |
  | snapshot | 스냅샷 |
  | console | 콘솔 |
  | open | 열기, 보기, go |

  예: `migrate web to node2`, `web을 node2로 옮겨`, `stop db`, `콘솔 web`. VM은 이름 앞부분으로, 노드도 이름 앞부분으로 찾는다.
- **확인.** 팔레트가 바로 하는 것은 확인이 필요 없는 시작·콘솔·열기뿐이고, 시작은 친 이름이 VM 이름과 **정확히 같을 때만**
  바로 한다(`start db`에 `db`가 없고 `db-prod`만 있으면 "db-prod을(를) 시작할까요?"를 묻는다). 정지·재시작·강제 정지·옮기기·스냅샷은
  VM 화면과 **같은 확인 대화상자**를 미리 채워 연다(옮기기는 대상 노드를 골라 둔다. 그 노드가 그 사이 후보에서 빠졌으면 다른 노드를
  골랐다고 알린다). 한글 입력을 끝내는 `Enter`는 항목을 실행하지 않는다. 권한이나 지금 상태로 할 수 없는 동작은 흐리게 이유와
  함께 보인다. viewer에게는 동작 항목이 없고 이동과 열기만 있다.
- **키.** `↑`·`↓` 고르기, `Enter` 실행, `⌘Enter`·`Ctrl+Enter` 새 탭에서 열기, VM 위에서 `Tab`은 그 VM의 동작 묶음 보기,
  `Esc` 닫기(연 단추로 포커스가 돌아간다).

## 머리줄

왼쪽부터 이동 경로, **+ 만들기**, 클러스터 전환, 종, 실시간 표시, 사용자 메뉴다.

- **찾기·명령**(팔레트, `⌘K`)은 768px 이상에서 사이드바 맨 위에 있고, 그보다 좁으면 머리줄의 아이콘 단추다.
- **+ 만들기**(`c`)는 가상 머신·VM 가져오기(OVA 올리기)·스토리지 풀·네트워크·백업 작업·ISO 올리기 메뉴다. 쓰기 권한이 있는
  것만(루트든 어느 폴더든) 보이고 viewer에게는 단추가 없다. VM 만들기는 권한 있는 폴더를 골라 두고, 노드 목록을 읽지 못하는 폴더
  사용자에게는 노드 칸을 숨긴다(머신 종류는 서버가 고른다). VM은 `/vms/-new`로 가고 나머지는 그 화면을 `?create=1`로 열어 만들기 대화상자를
  띄운다(이 주소를 북마크해도 된다).
- **클러스터 전환**(1024px 이상)은 이 클러스터와 원격 클러스터 목록이다. 원격을 고르면 `/remotes/{이름}`(원격 VM 보기)으로,
  이 클러스터를 고르면 홈으로 간다. 원격 목록은 메뉴를 열 때만 읽는다.
- **종**은 [알림 센터](#알림-센터)를 연다.
- **사용자 메뉴**에 언어(한국어·English), 테마(시스템·밝게·어둡게), 밀도(편안하게·촘촘하게), 단축키, 내 API 토큰, 내 2단계 인증,
  내 비밀번호 변경, 로그아웃이 있다.
- 실시간 연결(`/watch`)이 끊기면 본문 위에 "실시간 연결이 끊겼습니다 – 다시 연결하는 중입니다" 띠가 보인다.

## 알림 센터

머리줄 종을 누르거나 `Shift+N`으로 오른쪽 서랍을 연다. 종의 숫자는 **끝나지 않은 작업 + 울리는 critical·warning 경보**다
(info 경보는 세지 않는다). 경보가 울리면 숫자가 빨강, 작업뿐이면 강조색이다.

- **진행 중**: 도는 작업과 진행률(옮긴 바이트와 단계).
- **최근**: 끝난 작업 10개와 실패 이유. 실패한 VM 시작·정지·강제 정지·재시작에는 **다시 하기**가 있고(시작은 바로 다시 보내고,
  정지·재시작·강제 정지는 다른 곳과 같은 확인을 거친다. 지금 상태로 할 수 없으면 흐리고 이유, 그 뒤 같은 VM에 새 전원 작업이
  있었으면 단추가 없다), 실패한 백업 작업 실행에는 **작업 다시 실행**이 있다. 파라미터가 필요한
  작업(옮기기 등)은 다시 하기가 없고 설명 자체가 대상 화면 링크다(VM 스냅샷 작업 → 그 VM의 스냅샷 탭 등).
- **경보**: 울리는 경보(심각도 순)와 대상 링크.
- 아래에 "모든 작업 보기"(기록 › 작업 기록)와 "모든 경보 보기"(개요 › 경보)가 있다.
- 서랍이 열려 있으면 작업 성공 알림을 띄우지 않는다. 실패 알림에는 서랍을 여는 "보기"가 있다. 경보는 화면 알림으로 띄우지
  않는다. VM 정지·강제 정지 성공 알림에는 10초 동안 **다시 켜기**가 있다.

## 목록

VM·노드·스토리지 풀·볼륨·백업·작업·감사 로그 목록은 같은 표를 쓴다.

- **주소에 남는 거름.** 검색(`?q=`), 정렬(`?sort=memory`, 내림은 `?sort=-memory`), 거름(VM `phase`·`node`·`template`, 볼륨
  `iso`)이 주소에 남는다. 그래서 거른 목록을 링크로 나눌 수 있다(예: `/vms?phase=failed&node=node2`). 작업·감사 로그는
  페이지로 나뉘어 검색·정렬이 없다.
- **저장 보기.** "보기" 메뉴에서 지금 검색·정렬·거름에 이름을 붙여 저장하고 다시 고른다. VM 목록에는 기본 보기
  실행 중·실패·이 노드(접속한 노드)가 있다. 저장 보기를 지우면 10초 동안 되돌릴 수 있다.
- **열.** "열" 메뉴에서 열을 숨기고 보인다(순서는 바꾸지 않는다). 좁은 화면에서는 덜 중요한 열이 저절로 숨는다.
- **밀도.** 사용자 메뉴의 밀도가 모든 표·단추 높이를 바꾼다(편안하게 40px 행, 촘촘하게 32px 행).
- **일괄 동작(VM 목록).** 체크박스로 고르고 `Shift`+누르기로 범위를 고른다. 거름이 바뀌어 보이지 않게 된 행은 고르기에서 빠진다.
  아래 막대에 시작·정지·강제 정지·재시작·스냅샷·옮기기·지우기가 "정지 (가능 3, 불가 1)"처럼 보이고, 가능한 VM이 없으면 막힌다.
  - 확인 대화상자가 영향받는 VM 표(이름·노드·상태, 불가면 이유)를 지금 상태로 보인다(열린 동안 누가 VM을 켜면 바로 바뀐다).
    **지우기와 강제 정지는 실제로 할 수(가능 수)를 입력해야** 한다("고른 VM 3개 중 2개에 합니다"). 그 수가 바뀌면 다시 입력한다.
  - 스냅샷 이름은 `bulk-YYYYMMDD-HHMM`이고 디스크만 담는다. 옮기기는 대상 노드 하나를 고르고 VM마다 갈 수 있는지 미리 보인다.
    스냅샷이 있는 VM은 일괄 지우기에서 빠진다(VM 화면에서 스냅샷과 함께 지운다).
  - 요청은 4개씩 동시에 보내고 대화상자의 결과 칸에 VM마다 요청함·성공·실패(이유)를 보인다. 대화상자를 닫아도 이어지고, 끝나면
    알림 하나("정지: 8개 중 7개 성공, 1개 실패.")로 묶는다. 실패가 있으면 알림이 남고 "작업 보기"가 있다.
- **미리 보기 서랍.** VM·노드 목록에서 행의 눈 아이콘이나 `Space`로 오른쪽 서랍을 연다. VM은 노드·vCPU·메모리·고정 IP와
  시작·정지(확인)·콘솔·열기, 노드는 상태·주소·버전·CPU·메모리·VM 수와 열기다. 서랍이 열린 채 `j`·`k`로 행을 옮기면 내용이 바뀐다.
- **목록 키.** `j`·`k` 행 옮기기, `x` 고르기, `Space` 미리 보기, `Enter` 상세 열기, `/` 검색 상자. 입력 칸·메뉴·대화상자
  안에서는 받지 않는다.
- **즐겨찾기 ★.** VM·노드 상세 머리, 스토리지 풀 행, 미리 보기 서랍에 있다. 즐겨찾기는 홈과 팔레트 맨 위에 모인다. 빼면 10초
  동안 되돌릴 수 있다. VM·노드·보안 그룹 상세를 열면 최근 항목(20개)에 들어간다.

## 상세 화면과 파괴 동작

- **상세 머리.** VM·노드·보안 그룹·가져오기·원격 상세는 이름, 상태, ★, 주 동작 단추, 나머지 동작의 **⋯ 메뉴**("{이름} 동작"),
  그 아래 요약 카드 줄이다. 그 아래는 `?tab=` 탭이다.
  - **VM**: 단추는 시작·정지·콘솔 열기·마이그레이션이다. 재시작·강제 정지·편집·복제(템플릿이면 배포)·템플릿으로 바꾸기(VM으로
    되돌리기)·삭제는 ⋯ 메뉴에 있다. 할 수 없는 항목은 막힌 채 이유를 읽어 준다. 요약 카드는 노드·vCPU·메모리·고정 IP다.
  - **노드**: 단추는 유지보수·비우기이고 업데이트·인터페이스·디스크·레이블·펜싱·얼림 풀기·지우기는 ⋯ 메뉴에 있다(노드 목록의 행
    메뉴와 같다). 요약 카드는 API 주소·CPU·메모리·VM 수다.
- **바뀐 값 강조.** 실시간으로 상태가 바뀐 칩은 잠깐 테두리가 빛난다.
- **영향 목록.** 되돌릴 수 없는 동작의 확인 대화상자는 무엇이 함께 영향받는지 보인다: VM 삭제(남는 디스크 볼륨·스냅샷·백업 수),
  네트워크 삭제(쓰는 VM), 풀 삭제(안의 볼륨·백업), 노드 지우기(배정된 VM).
- **입력 확인.** 하나를 지울 때는 이름을, 여럿(일괄 지우기·강제 정지)은 고른 수를 입력해야 확인 단추가 열린다. 기본 포커스는
  취소이고 위험 단추는 오른쪽 끝이다.
- **되돌리기**(10초 알림의 "되돌리기"): 즐겨찾기 빼기, 저장 보기 지우기, 노드 레이블 저장, 보안 그룹 저장. 레이블·보안 그룹은 그
  사이 다른 곳에서 바뀌었으면 되돌리지 않고 알린다. 서버 작업이 지운 것(VM·볼륨 등)은 되돌리지 못한다.
- 노드 유지보수 켜기·끄기와 레이블은 서버 응답 전에 화면에 먼저 보이고, 실패하면 되돌린다.

## 홈과 첫 걸음

홈은 위에서부터 첫 걸음 → 건강 띠(노드 온라인, VM 실행·정지·실패 — 실패 수를 누르면 `/vms?phase=failed`, 울리는 경보, 리더)
→ 혼합 버전 경고 → **운영자 대시보드**(계획 75 — 아래 [운영자 대시보드](#운영자-대시보드)) → 경보·상위 VM → 클러스터 부하 차트 →
최근 작업·즐겨찾기다. 즐겨찾기 줄에는 VM 전원 단추가 있다. 구독 안내는 제목 아래에 보인다. 차트·위젯은
[클러스터 운영](cluster.md#웹-화면)에 있다.

**지난 홈.** 루트 `cluster.read`가 있지만 클러스터가 섞인 판이면(옛 노드가 기능 `operator-dashboard`를 모름 — `GET /capacity`가 409
`cluster_upgrading`) 대시보드 대신 "모든 노드를 업그레이드하면 운영자 대시보드(지도·자세히 판·노드별 할당)가 보입니다." 한 줄과
계획 74까지의 홈(경보·용량·풀 사용률 → 클러스터 부하 차트 → 노드 부하·상위 VM)이다. 용량은 온라인이고 위트니스가 아닌 노드의
코어·메모리 가운데 도는 VM에 나눠 준 몫이고 85 %를 넘으면 경고색이다. 어느 홈인지는 첫 `/capacity` 답으로 정하고, 그때까지는
건강 띠 아래가 "읽는 중"이다(두 홈 사이를 오가며 위젯을 다시 올리지 않게). 루트 `cluster.read`가 없으면(폴더 사용자) 지금처럼
지도·표·판·차트를 숨기고 자기 VM·경보만 보이며 한 줄로 알린다.

**첫 걸음**은 VM이 하나도 없고 VM을 만들 권한이 있을 때 홈과 VM 목록 위에 보인다: ① 스토리지 풀 만들기 → ② ISO 올리기 또는
이미지 받기 → ③ VM 만들기. 끝난 단계는 ✓이고 각 단계는 그 화면의 만들기로 간다. VM이 생기면 카드째 사라진다.

### 운영자 대시보드

홈 한 화면에서 클러스터가 어떻게 돌아가는지 본다(계획 75, [설계](../superpowers/specs/2026-11-26-operator-dashboard-design.md)).
새 사이드바 항목은 없다. 대시보드는 늦게 읽는 조각이고(지도·판·문구를 처음 쓸 때 받음), `GET /capacity`와 `GET /topology/physical`을
15초마다 읽는다([클러스터 운영](cluster.md#용량-요약), [네트워크](network.md#물리-네트워크-포트본딩lldp)).

```
┌ 물리 장애 n · 링크 경보 ───────────────────────────────────────────────┐
│ ┌ 인프라 지도(2.5D) ────────────────────────────┐ ┌ 자세히 ──────────┐ │
│ │ 노드 블록 · VM 타일 · 포트 줄 · 네트워크 레일 │ │ 고른 것 없음:    │ │
│ └───────────────────────────────────────────────┘ │  클러스터 요약   │ │
│ ┌ 노드별 할당·사용 (CPU / 메모리 / 스토리지) ───┐ │ 노드: CPU·메모리·│ │
│ └───────────────────────────────────────────────┘ │ 스토리지·네트워크│ │
│ 경보 · 상위 VM · 클러스터 부하 차트 · 최근 작업 · 즐겨찾기          │ │
└────────────────────────────────────────────────────────────────────────┘
```

- **물리 장애 배지.** 링크·본딩 장애(아래 "네트워크" 칸의 영향)나 노드에 없는 네트워크에 붙은 VM NIC가 하나라도 있으면 맨 위에 "물리 장애
  n"이다(오프라인 노드의 마지막으로 본 장애는 세지 않고 판의 목록에 "마지막으로 본 값"으로 남는다). 본딩 구성 포트의 장애는 본딩 하나로
  센다(경보와 같은 수 — 판 목록은 "bond0 on node-a · eno1 down, eno2 사라짐"). 유지보수 노드의 장애는 배지에 "유지보수 n"으로, 목록에
  "유지보수"로 적는다(그 노드의 경보는 조용하다). 누르면 첫 장애 포트를 고른다(본딩이면 끊긴 구성 포트, 관리자가 내린 브리지면 노드) — 지도가 그
  노드로 옮겨 포트를 밝히고 판이 그 노드의 네트워크 칸이 된다(같은 장애를 다시 누르면 다시 옮긴다). 주소만 가진 포트(스토리지·클러스터 링크망)의
  장애는 VM 수 대신 쓰임·주소("클러스터 링크 · 10.10.0.11")다. 물리 관계(`/topology/physical`)를 받지 못하면 "장애 없음"이라 하지 않는다:
  배지는 "? 물리 상태 모름"(누르면 다시 묻기), 판은 "물리 링크 상태를 모릅니다"와 "다시 시도", 표의 문제 열은 "? 링크 상태 모름"(첫 답을
  기다리는 동안은 "링크 확인 중")이다. 한 번 받은 뒤에 다시 읽다 실패하면 마지막 값을 보이되 배지 줄·판·지도에 "다시 읽지 못해 마지막 답을
  보입니다."를 적고 판은 "장애 없음"이라 하지 않는다.
- **사라진 포트 잊기.** 노드가 기억하는 포트가 사라지면(NIC 장애·제거) 판 목록·사슬도 포트 표·지도 포트 카드에 "사라짐"으로 남는다. NIC를
  교체·뺐으면 **"잊기"**(확인 대화상자, 노드를 바꿀 수 있는 사용자)로 지운다 — 그 포트의 링크 경보가 풀린다([링크 경보](cluster.md#링크-경보)).
- **링크 경보 카드.** 경보 규칙을 바꿀 수 있는 사용자(admin)에게, 링크 조건(`node_link_down`·`bond_degraded`) 규칙이 하나도 없을 때만
  "업링크·서비스 포트와 본딩을 보는 규칙이 아직 없습니다."와 **"링크 경보 켜기"**가 보인다(링크 경보를 모르는 옛 노드가 남았으면 — 꺼진
  노드 포함 — 단추를 막고 "옛 판 노드가 있습니다(svc03). 업그레이드하거나, 없어진 노드는 지우면 …"을 보인다). 알림 대상을 고르면 권하는 규칙 둘을 만든다(서버
  `POST /alert-rules/link-defaults` — CLI `alert rule add-link-defaults`와 같음, [링크 경보](cluster.md#링크-경보)). 이미 있는 이름은 건너뛰고
  만든 수·있던 수를 알린다. 규칙이 생기면 카드가 사라진다.
- **인프라 지도.** 개요 › 인프라 지도와 **같은 컴포넌트**를 "홈 모드"로 그린다: 높이 고정, 범례는 지도 화면처럼 "범례·조작 안내" 단추로 펼침, 도구 띠 대신 작은
  "보기 설정", 레이어 기본은 부하 + 네트워크(지도 화면과 따로 기억), 서랍 없음 — 누르면 그 원소를 **고르고** 자세히 판이 따라간다.
  한 손가락 세로 쓸기는 쪽 스크롤로 넘긴다(휴대폰에서 묻힌 지도가 쪽을 막지 않게 — 휴대폰은 높이도 낮음).
  "지도 열기"가 `/cluster/map`으로 간다. 포트 줄·레일은 [클러스터 지도 화면](#클러스터-지도-화면)의 네트워크 레이어와 같다.
- **노드별 할당·사용 표.** 행 = 노드, 열 = CPU·메모리·스토리지. 칸마다 같은 막대 하나다: 바탕 = 전체, 테두리 칸 = 할당, 진한 칸 =
  사용. 할당이 전체를 넘으면 빨간 빗금 넘침 꼬리가 붙고 수치 글이 따로 있다(색만으로 알리지 않음).

  | 열 | 전체 | 할당 | 사용 |
  |---|---|---|---|
  | CPU | 공유 스레드(스레드 − 예약 − 전용) | 공유 정책 VM의 vCPU(오버커밋 ×n 글), 글에 전용 할당(잡힌 전용 / 전용) | 막대에 없음 — 글로 지난 1분 노드 전체 사용률(전용 VM·호스트 몫이 들어 있어 공유 풀의 눈금이 아니다) |
  | 메모리 | 노드 메모리 | 자리 잡은 VM의 메모리 합(시작·실행·정지 중·옮기는 중) | 실제 사용 |
  | 스토리지 | 이 노드의 로컬 풀 크기 합 | 프로비전(풀 볼륨 `size_bytes` 합 — 씬 할당) | 쓴 양(전체 − 남은 양) |

  CPU 글은 "공유 vCPU 14 / 스레드 7 · ×2.0 · 전용 2 / 8 · 노드 사용 40 %"다. 메모리 오버커밋은 hugepages VM과 hugepages 풀을 뺀 보통 메모리의
  비다. 머리를 누르면 노드·CPU·메모리·스토리지로 정렬하고, **"문제만"**은 오프라인·오버커밋(공유 vCPU가 ×4를 넘음 — KVM에서 2~4배는 흔한
  정상 운영이다 — 이나 메모리가 ×1을 넘음)·90 % 넘음(CPU·메모리·로컬 풀)·준비 안 된 풀·링크 장애·노드에 없는 네트워크가 있는 노드만 남긴다. 행을 누르면 그 노드를 고른다(지도·판이 따라감). 공유 풀(NFS·RBD·공유 LVM)은
  표 아래 한 줄("ceph 사용 … / …, 프로비전 … (노드 2/3)")이다. 휴대폰에서는 카드 목록이다.
- **자세히 판.** 넓은 화면(1024px 이상)은 지도·표 오른쪽 열(24rem, 스크롤해도 따라 내려옴), 좁은 화면은 고르면 열리는 서랍이다.

  | 고른 것 | 판 |
  |---|---|
  | 없음 | 클러스터 요약 — 온라인 노드의 합(같은 막대 셋), 물리 장애 목록(누르면 그 포트), 레일 요약("네트워크 n개, 저하·끊긴 노드가 있는 것 m개") |
  | 노드 | 한 열의 네 칸(탭이 아님). **CPU**: 호스트 NUMA 노드별 스레드 격자(빗금 = 호스트 예약, 채움 = 전용 — 도는 VM이 고정하면 진함, 테두리 = 공유), "공유 vCPU n개가 스레드 m개 위 — 오버커밋 ×k", 이 노드의 VM마다 "vCPU n개, 2-3에 고정"·"공유 스레드 위"(VM을 가리키면 그 스레드가 밝아짐). **메모리**: NUMA 노드별 묶임/전체, hugepages(크기마다 사용/전체, 떼어 둔 양), 메모리가 큰 VM. **스토리지**: 로컬 풀·공유 풀 막대, 씬 비율(프로비전 ÷ 전체 "씬 ×1.8"), 준비 여부. **네트워크**: 사슬도(아래) |
  | 포트 | 그 노드의 네트워크 칸만, 그 포트에서 오른쪽 영향 경로를 강조. "노드 전체"로 네 칸 |
  | VM | VM 미리 보기 + **"이 VM의 경로"**: vCPU → 스레드(고정이면 그 CPU, 아니면 공유), 메모리 → NUMA 노드, 디스크 → 풀, NIC → 네트워크 → 브리지 → 포트(상태) |
  | 레일 | 그 레일(브리지·physnet·underlay)을 쓰는 네트워크마다 노드와 상태(정상·저하·끊김·없음·모름 — 오프라인 노드, underlay 주소의 인터페이스를 모름) |

  **네트워크 사슬도**는 평면 그림이다: 왼쪽 물리 포트(속도, carrier, LLDP 스위치·포트) → 본딩 → VLAN → 브리지·physnet·underlay →
  네트워크 → VM 수. 장애 포트에서 오른쪽으로 영향 경로가 빨갛다(끊김은 ×, 저하는 빗금 — 모양이 따로 있음). 쓰지 않는 포트는 "쓰지 않는
  포트 n개는 보이지 않습니다."로 접는다. 포트 표에 본딩의 이상한 구성 포트("eno2 사라짐"·"LACP 어긋남"), 포트의 주소, 트래픽(rx/tx 바이트/초)과 오류·버림 증가가 있다 — 노드의 마지막 표본이라 실시간뿐이고
  기록은 없다. LLDP 이웃이 하나도 없으면 "노드에 lldpd를 설치하면 링크마다 스위치와 포트가 보입니다."다. 주소만 가진 포트(스토리지·클러스터
  링크·관리망)와 dummy 같은 그 밖의 장치도 물리 포트 열에 있다. underlay 주소의 인터페이스를 모르면 underlay 칸은 "모름"(정상이 아님)이다.
  오프라인 노드는 "오프라인 · 마지막으로 본 값", 이 노드에 없는 네트워크에 붙은 VM NIC는 "× node-a에 네트워크 lan이(가) 없음"이다. 옛 판
  노드(업그레이드하지 않은 채 꺼진 노드)는 "이 노드는 옛 판입니다 — 일부 정보가 없습니다."(MTU·LLDP가 없고 VLAN 아래 장치는 이름 `eno1.100`으로
  짐작). VM의 디스크 → 풀은 그 VM 디스크의 볼륨만 하나씩 묻는다(볼륨 목록 전체를 받지 않는다).

## 마법사

- **VM 만들기.** 그림 한 화면이다(계획 77-5 — [VM 만들기 화면](#vm-만들기-화면)). 첫 단계는 용도 카드이고, 고르면 VM 그림이
  채워진다. 폼(단계 목록·검토)은 **VM 고치기**(`/vms/<이름>/edit`)에만 남았다.
- **클러스터 합류**(클러스터·가용성 › 클러스터(멤버·CA)). 합류 토큰 대화상자와 명령 대화상자에 단계 표시(1 토큰 만들기 · 2 새 노드에서 명령
  실행 · 3 노드 기다리기)가 있다. 명령을 복사하면 3단계가 되고, 새 노드가 목록에 나타나면 "{이름}이(가) 클러스터에
  합류했습니다."를 알린다. 기다리지 않고 "완료"로 닫아도 된다.
- **Ceph**(스토리지 › Ceph). Ceph이 없으면 빈 상태 안내가 보이고 admin은 "Ceph 설정 시작"으로 설정 마법사를 연다
  ([스토리지](storage.md)).

## 휴대폰과 당직 보기

- **1280px 이상**: 펼친 2단 사이드바(240px). **768~1279px**: 아이콘 레일(56px) — 묶음 아이콘이 그 항목의 펼침 창을 연다. `[`나
  사이드바 아래 단추로 접고 펴며 브라우저가 기억한다. **768px 미만**: 사이드바 대신 머리줄 ☰가 같은 2단 메뉴를 서랍으로 연다
  ([메뉴](#메뉴2단-사이드바)).
- **당직 보기(768px 미만).** 목록은 카드(이름, 상태, 노드, 동작)가 되고 VM 카드에 전원 단추(꺼졌으면 시작은 바로, 켜져 있으면
  정지 확인, 40px)가 있다. 홈은 건강 띠 → 경보 → 물리 장애 배지 → 지도 → 노드별 할당·사용(카드) → 즐겨찾기(전원 단추) →
  최근 작업 순이고(자세히 판은 고르면 서랍), 차트·상위 VM은 그리지 않는다. 지난 홈이면 경보 → 건강 띠 → 즐겨찾기 → 용량 → 풀 →
  최근 작업이다. 밀도는 늘 편안하게다.
- VM 고치기 폼과 콘솔은 "이 화면은 넓은 화면에서 쓰기 좋습니다" 안내가 보인다(쓸 수는 있다). VM 만들기에는 이 안내가 없다 — 휴대폰에서는
  용도 카드 → 그림 → 요약 차례로 쌓이고 만들기는 아래 고정 띠다([VM 만들기 화면](#vm-만들기-화면)).

## 단축키

`?`나 사용자 메뉴의 "단축키"로 같은 표를 본다. 한 글자 키는 입력 칸, 열린 대화상자·메뉴 밖에서만 받고(팔레트 키는 입력 칸에서도
받는다), 콘솔 화면에서는 모든 키를 게스트에 보낸다. 한글 입력 상태여도 글쇠 자리(`g`·`j`·`k` 등)로 받는다. 전원·지우기에는 한 글자 키가 없다. `g` 다음 키는 1초 안에 누른다.

| 묶음 | 키 | 동작 |
|---|---|---|
| 일반 | `⌘K`(맥)·`Ctrl K` | 명령 팔레트 |
| 일반 | `?` | 단축키 도움말 |
| 일반 | `/` | 목록 검색 |
| 일반 | `c` | 만들기 메뉴 |
| 일반 | `[` | 사이드바 접기·펴기 |
| 일반 | `f` | 이 리소스 즐겨찾기(상세 화면) |
| 일반 | `⇧N`(맥)·`Shift N` | 작업·알림 센터 |
| 이동 | `g` `h` | 개요 |
| 이동 | `g` `v` | 가상 머신 |
| 이동 | `g` `i` | 이미지·이전 |
| 이동 | `g` `d` | 스토리지 |
| 이동 | `g` `n` | 네트워크 |
| 이동 | `g` `c` | 클러스터·가용성 |
| 이동 | `g` `b` | 백업·복구 |
| 이동 | `g` `a` | 기록 |
| 이동 | `g` `s` | 관리 |
| 목록 | `j` | 다음 행 |
| 목록 | `k` | 이전 행 |
| 목록 | `x` | 행 고르기 |
| 목록 | `Space` | 행 미리 보기 |
| 목록 | `Enter` | 행 열기 |
| 클러스터 지도 | `]` | 노드의 VM으로 들어가기 |
| 클러스터 지도 | `[` | 노드로 나오기 |
| 클러스터 지도 | `m` | VM을 다른 노드로 옮기기(끌기 대신) |
| 클러스터 지도 | `p` | 노드의 포트 줄로 들어가기(네트워크 층, `←` `→` 포트 사이) |
| 클러스터 지도 | `↓` | 포트에서 그 네트워크 레일로(`←` `→` 레일 사이) |
| 클러스터 지도 | `↑` | 레일에서 다시 포트로 |

`g` 키들은 그 묶음의 보이는 첫 항목으로 간다(`g c`는 클러스터 묶음, 홀로 누른 `c`는 만들기 메뉴). "클러스터 지도" 키는 지도 그림에 초점이 있을 때만 받는다 — 그림 밖의 `[`는
그대로 사이드바를 접는다(지도 안의 다른 키는 [클러스터 지도 화면](#클러스터-지도-화면)). 표는 `web/src/lib/shortcuts.ts`의 `SHORTCUTS`와 같다.
VM 빌더나 지도에서 무언가를 들고 있는 동안(끄는 중·누르기나 키보드로 든 채)은 한 글자 키와 팔레트 키를 받지 않는다(`<html data-dnd-held>`).
VM 만들기의 되돌리기 `⌘Z`·`Ctrl+Z`는 그 화면 안에서만 받는다([VM 만들기 화면](#vm-만들기-화면)).

## CPU 모델 화면

게스트 CPU 모델·플래그와 클러스터 CPU 기준(계획 63)은 사이드바 항목을 더하지 않고 아래 화면 안에 있다. 쓰는 법은 [CPU 모델과
플래그](vms.md#cpu-모델과-플래그)·[클러스터 CPU 기준](cluster.md#클러스터-cpu-기준)·[취약점 때문에 CPU 기능
숨기기](vms.md#취약점-때문에-cpu-기능-숨기기).

| 화면 | 있는 것 |
|---|---|
| VM 만들기·편집 › 일반 | "CPU 모델"(찾기 상자 + 묶음 목록: 기본·클러스터 기준·호환 수준·QEMU 모델(버전), "노드 n/m에서 켤 수 있음", 못 켜는 노드와 빠진 것), "CPU 플래그"(칩 — Enter·"숨기기"는 `-`, "켜기"는 `+`, 칩을 누르면 바뀜, 숨김 목록에 든 이름에 "클러스터 전체에서 숨김", 루트 `cluster.admin`이 아니면 켤 수 있는 이름과 까닭, 켠 `invtsc`에 "라이브 마이그레이션을 막음"), 실행 중이면 "다음 전원 껐다 켜기 때 적용" 안내 |
| 복제·템플릿 배포 대화상자, 가져오기 실행 | "CPU 모델과 플래그"(복제·배포는 접혀 있고 원본 값을 요약에 보임, 바꾼 칸만 보냄). 가져오기는 클러스터 기준이 있으면 `cluster`를 미리 고른다 |
| VM 상세 › 요약 | CPU 줄(스펙과 "지금 … (으)로 실행 중"), 보류 `cpu`의 "전원 껐다 켜기 필요" 띠와 "지금 전원 껐다 켜기" 단추(재시작 확인 대화상자) |

## SDN 화면

SDN(OVN, 계획 65~67) 화면은 **네트워크** 묶음의 항목이다: **라우터·유동 IP**(화면 안 탭: 라우터 `/routers` | 유동 IP
`/floating-ips`), **부하 분산**(`/load-balancers`), **SDN(가상 네트워크)**(`/sdn`), **토폴로지 그림**(`/networks/topology`).
SDN 항목은 루트 `cluster.read`가 있을 때만 보인다(폴더 사용자에게는 감춤). 쓰는 법은 [SDN (OVN)](network.md#sdn-ovn). 계획 67부터
라우터·유동 IP·부하 분산기·옮기기는 **watch**다: 사건이 오면 그 화면의 질의를 1초 모아 다시 읽는다(라우터 사건은 라우터·유동 IP·LB·주소
표·토폴로지를, 네트워크·VM 사건은 토폴로지와 유동 IP 상태를 — 다시 붙으면 그 질의도 다시 읽음). 사건이 없는 OVN 상태만 30초마다 읽는다:
연 라우터 서랍의 지금 게이트웨이, LB 목록의 멤버 건강, 토폴로지의 게이트웨이 주인·멤버 건강. 라우터·LB 보기는 `?open=<id>`로 그 서랍을 연
채 열린다(토폴로지와 경보 대상 링크가 쓴다).

| 네트워크 › SDN(가상 네트워크), 설정 전 | 빈 상태 "SDN이 설정되지 않음"과 admin의 "SDN 설정 시작"(시작하기 전에는 아무것도 설치하지 않음) |

"먼저 세움" 노드와 그 중앙 주소(선택 — 노드 주소나 클러스터 링크 주소, 루프백·링크 로컬은 안 됨). ② **설치**: 첫 노드의 Task 단계(노드 확인 → 꾸러미 설치 → TLS 파일 쓰기 → NB·SB 데이터베이스 만들기 → ovsdb-server·northd 시작 → 데이터베이스 리더 기다리기 → chassis 구성), 끝나면 나머지 중앙을 화면이 **하나씩** 더함(중앙 Task는 클러스터에서 한 번에 하나), 노드마다 기다리는 중·합류 중·중앙·실패. 실패하면 까닭과 "다시 하기"(첫 세우기는 같은 노드와 처음 준 주소로, 중앙 더하기는 그 노드로). 첫 노드가 꺼졌거나 지워졌고 아직 중앙이 없으면 마법사를 닫고 상태 화면의 "설정 옮기기"로 넘긴다. 단계가 바뀌면 초점이 새 단계로 가고, 지금 단계는 화면 읽기 프로그램에 한 줄로 알린다. 서버의 짝수 경고 토스트는 마지막 중앙을 더할 때만(셋을 고르면 둘째의 "2개" 경고는 보이지 않음). ③ **chassis**: 노드 표와 노드마다 "설치", "모든 노드에 설치"(나중에 합류한 노드에는 저절로 깔지 않음) |
| SDN 상태(설정 후) | 상태(설정 중·준비됨), OVN 판, 마지막 동기화 시각과 chassis 반영("모든 chassis가 반영했습니다" 또는 `hv_cfg` / `nb_cfg`), 동기화 오류, 진행 중인 SDN 작업 수, 마지막 설정 실패. 경고 띠: 중앙 수가 짝수, 투표 멤버가 아닌 중앙, 오프라인 중앙. 설정이 멈췄으면(설정 중이고 도는 작업이 없거나, 첫 노드가 꺼졌고 남은 작업이 모두 그 노드의 것 — 전원이 나간 노드의 작업은 "실행 중"으로 남는다) 그 노드가 온라인일 때 "{노드}에서 설정 다시 하기"(서버가 지난번 주소로 이어서 함), 그 노드가 꺼졌거나 지워졌고 아직 중앙이 없으면 "설정할 노드" 고르기와 "이 노드로 설정 옮기기" |

| "SDN으로 옮기기" 마법사 | ① **대상**: 있는 SDN 네트워크, 또는 "같은 서브넷으로 새 SDN 네트워크"(원본에는 CIDR이 없어 사용자가 쓴다, 폴더는 원본의 것), 방식(자동·꺼진 채·라이브·다시 켜기), 한 번에 옮길 수, "MTU가 줄어도 라이브", 다리 놓기와 다리 노드. ② **미리 보기 표**: VM NIC마다 방식·주소·출처·막힘·경고, 주소 고쳐 넣기, VM 빼기, 방식을 바꾸고 다시 계획(서버 계획 문장은 화면 말로). **cloud-init이 있는 VM은 표 위 경고 띠("cloud-init을 쓰는 VM이 있습니다: instance-id가 바뀌어 다음 켜기에 게스트가 인스턴스마다 하는 일(SSH 호스트 키 따위)을 다시 합니다.")와 굵은 줄.** VM마다 다른 방식은 없다 — 다른 방식이 필요한 VM은 빼고 끝낸 뒤 새 옮기기로. | 네트워크 서랍(계획 67) | 라우터 인터페이스인 네트워크에 **"라우터에서 떼기"**(그 네트워크의 `network.config`, 라우터 권한 없이 — 라우터를 읽을 수 없으면 "볼 수 없는 라우터"로). IP 주소 표의 `lb-vip`·`lb-monitor` 행은 LB 보기로 가는 링크. LB가 VIP를 둔 네트워크의 떼기는 서버의 409 `lb_in_use` 문장 |

## 백업 저장소 화면

백업 저장소(계획 68 — 중복 제거·암호화·S3·검증·라이브 복원)는 **백업·복구 › 백업 저장소** 항목
(`/backup-stores`)이고, 저장소를 읽을 수 있을 때(루트 `system.read`) 보인다. 화면 코드는 늦게 읽는 조각(`web/src/backupStores/`)이다.
저장소 목록은 비밀을 뺀 보기라 watch 사건이 오면 질의를 다시 읽는다. 쓰는 법은 [백업 저장소](backup.md#백업-저장소중복-제거암호화s3).

|---|---|
| 백업·복구 › 백업 저장소 › 목록 | 이름, 백엔드(풀 이름 / S3 버킷·접두사), 암호화 배지와 지문, 읽기 전용, 스냅샷 수, 저장 크기, dedup 배율, 마지막 GC·검증(깨진 청크 수), 상태. 빈 화면은 "저장소 만들기" 안내(axe 시험). `?open=<id>`로 서랍을 연다(경보의 저장소 링크가 씀) |

## 파일 찾아보기 화면

파일 단위 복원(계획 69)은 따로 된 항목·탭이 없다. **백업·복구 › 백업** 표와 VM 상세 › 백업 탭의 행 동작 **"파일 찾아보기"**가
백업 탭 아래 상세 화면 `/backups/<백업 id>/files`를 연다(이동 경로에는 백업 이름). 화면 코드는 늦게 읽는 조각(`web/src/fileRestore/`,
gzip 8.4 KB)이다. 쓰는 법과 보안 모형은 [파일 단위 복원](backup.md#파일-단위-복원).

| 내려받기 | 고른 것이 없으면 **"폴더 내려받기"**(지금 폴더 전체 zip — 볼륨 루트도), 일반 파일 하나면 그대로, 여럿·폴더면 zip, 메뉴에 tar.gz("권한·소유자·링크 보존"). 링크 두 걸음(`download-link` → `/api/v1` + `url`)을 숨은 `<a download>`로 눌러 화면을 떠나지 않는다(큰 zip도 브라우저 내려받기 관리자가 받음) |
| VM으로 복원 대화상자 | 고른 것이 있고 어딘가 `vm.config`가 있을 때. VM 고르기(실행 중이고 게스트 에이전트 채널이 있는 것만, "(원래 VM)"이 먼저), 고를 때마다 restore-caps를 물어 파일 쓰기가 막혔으면 막고 서버 까닭(RHEL `/etc/sysconfig/qemu-ga`), 폴더를 골랐는데 `guest-exec`가 없으면 막고 알림, "덮어쓰기"는 `guest-exec`가 없으면 비활성과 까닭. 게스트 안 폴더(기본 지금 폴더, Windows 게스트면 `C:\…`), 같은 이름이면 둘 다 두기·건너뛰기·덮어쓰기, 속도·한도 안내. 보내면 작업 알림 "백업의 파일을 <VM>에 되돌려 쓰기" — 결과 문구는 작업 센터 |
| 작업 | `file-restore-session`은 "백업 <백업>의 파일 찾아보기"(대상 링크는 이 화면, 진행 문구 "도우미 VM 시작 중"·"열림"·"닫는 중"), `file-restore-to-guest`는 대상 VM과 "게스트에 쓰는 중(N)" |
| 역할 편집기 | 권한 목록 끝에 `backup.file_restore`(내장 operator에 없음) |

세션을 여는 것은 화면이 열릴 때다(같은 사용자의 열린 세션은 서버가 다시 줌). 부팅 중 2초, 준비된 뒤 20초마다 세션을 다시 읽어 볼륨
상태·닫힐 시각을 맞춘다. **화면을 떠나도 세션을 닫지 않는다** — 진행 중인 내려받기·VM으로 복원 작업이 같은 세션을 쓰고, 돌아오면 다시
부팅하지 않아도 된다. 쓰지 않으면 서버가 15분 뒤 닫는다.

## DR 화면

DR 복구 계획(계획 76)은 **백업·복구 › DR(재해 복구)** 항목(`/dr-plans`, 실행 화면 `/dr-runs/<id>`도 이 항목)이고 화면 코드는
늦게 읽는 조각(`web/src/dr/`)이다. **목록**은 계획마다 운영 클러스터·VM 수·RPO 지킴 막대("2/3 RPO 지킴")·마지막 시험 RTO·도는 실행이고
"새 계획"은 루트 `cluster.admin`에게만 보인다. **계획 화면**은 탭 셋이다: 개요(보호 상태 표 — VM마다 복구 지점·만든 때·나이·상태 —,
최근 시험 셋, 지난 장애 조치), 계획(편집 — 운영 클러스터·복원 풀·폴더·RPO 목표(시간)·시간 초과 때 할 일, 부팅 그룹을 끌어 놓기 없이
위·아래 단추로, 그룹마다 준비된 때·시간 초과·다음 그룹 앞 쉼, "VM 더하기"는 운영 쪽 VM 목록(중계로 읽음 — 못 읽으면 알리고 이곳 사본만)과
이곳의 사본을 함께 보이고, VM마다 풀·노드·라이브 복원·IP 규칙, 네트워크·보안 그룹·시험 네트워크 맵 표 — 저장은 PUT 통째 `If-Match`,
어긋나면 "다시 읽기"), 실행(기록). 단추는 "시험", "장애 조치"(방식 계획된 이전·재해와 그 설명, 재해 경고, **계획 이름을 쳐야** 켜짐,
HA가 꺼져 있다는 안내), "뒷정리"(지울 시험 VM·네트워크 목록), "실행 취소", "다시 보호"(복제할 원격·원격 백업 풀·이곳 백업 풀·시각),
"계획 지우기"다. **실행 화면**은 그룹 띠, VM마다 단계 점(기다림·운영 쪽 준비·복원·시작·준비 기다림·준비됨·실패·시간 초과·건너뜀, 뒷정리는 지우는 중·지움), 새 VM·Task 링크·오류,
격리(거품) 네트워크, 도는 동안 흐르는 RTO 시계이고 watch(`recovery-plan`·`dr-run`)로 갱신된다. 기능 `dr-plans`를 모르는 노드가 있으면
띠로 알리고 쓰기·실행 단추를 막는다. 경보 `recovery_plan` 대상 링크는 그 계획 화면이다. 백업 복원 대화상자는 백업의 네트워크마다 이
클러스터의 네트워크를 고르게 한다(복원 맵). 쓰는 법은 [DR 계획](backup.md#dr-계획복구-계획).

## 클러스터 지도 화면

클러스터 지도(계획 70)는 노드와 VM을 **3D처럼 보이는 2D 그림**(아이소메트릭 SVG — WebGL·캔버스 없음) 한 장으로 보인다. 사이드바
메뉴는 **개요 › 인프라 지도**(`/cluster/map`)이고, 노드 목록처럼 루트에서 노드를
읽을 수 있을 때만 보인다. 이동 경로는 `개요 › 인프라 지도`이고 팔레트에서는 "지도"·"클러스터 보기"·"3d"·"map"으로 찾는다. 화면 코드는 늦게 읽는 조각이다(`web/src/clusterMap/`, 홈과 함께 쓰는
`InfraMap` 조각 gzip 약 24.2 kB(예산 24 KiB = 24,576바이트 — 계획 70에서 18.8 KB, 계획 75의 네트워크 층과 홈 모드로 24.4 KB, 글 층으로 24.8 KB였다가
계획 77-8에서 범례·가리키기 카드를 따로 받아 24.2 KB), 서랍·네트워크 층 카드(약 2.4 KB)·범례(펼칠 때)·가리키기 카드(그림을 그린 뒤)와 지도 문구 en·ko는
처음 쓸 때 따로 받음). 노드·VM·스토리지 풀 목록(watch — 사건은 1초 모아 다시 그림), `GET /placement`(부하·추천 — 최적 배치 화면과 같은
캐시, 15초), `GET /cluster`(리더, 30초), 경보, 마이그레이션 작업의 진행을 읽고, 네트워크 레이어를 켜면 `GET /topology/physical`(15초)도 읽는다.

| 그림 | 보이는 것 |
|---|---|
| 판 | 도구 띠의 **묶기**: "영역(그다음 랙)"(기본 — 노드 레이블 `zone` 값마다 판, 그 안에서 `rack`마다 줄), "랙", 노드들에 있는 다른 레이블 키("레이블 <키>"), "묶지 않음". 값이 없는 노드는 맨 끝 "영역 없음" 판이고, 어느 노드에도 그 레이블이 없으면 판 하나다. 판 앞 가장자리에 이름과 노드 수가 있다. 같은 입력이면 같은 그림이고 VM 타일 자리는 이름 순으로 고정이다(상태가 바뀌면 색만 바뀜). 위트니스 노드는 판 뒤쪽의 좁은 기둥, 노드가 없거나 모르는 노드를 가리키는 VM은 앞 왼쪽 "배치 안 됨" 판에 있다. 템플릿은 그리지 않는다(카드에 수만) |

| VM 타일 | 노드 윗면에 4 × 4칸씩 많아야 4층(64칸). **VM이 64칸을 넘는 노드**(계획 77-8)는 층을 쌓지 않고 윗면 한 층에 작은 칸으로 모두 그린다(많아야 1,024칸 — 넘으면 마지막 칸 "+N"). 그때 꺼진 VM은 윗면 앞쪽 띠 하나("꺼짐 66 ▸")로 접고, 띠를 누르거나 Enter면 펼쳐 칸으로 보이고 다시 누르면 접힌다(기억하지 않음). 작은 칸의 이름은 자세히 단계에서 칸 크기에 맞춘 글이라 더 확대하면 읽히고, 칸이 200개를 넘는 노드는 가리키면 카드로 본다. "배치 안 됨" 판도 노드 블록보다 커지지 않는다(칸이 작아지고 16대를 넘으면 꺼진 VM을 접음). 읽을 수 없는 VM은 회색 "+N 볼 수 없음"(수만 — `/placement`가 노드 읽기 권한자에게 주는 수, VM 읽기가 일부 폴더뿐인 사용자에게만). 색: 켜짐·꺼짐·켜는 중·끄는 중(맥박)·실패(×)·옮기는 중(테두리만). HA VM은 윗면 테두리가 밝다 |
| 라이브 마이그레이션 | 원본에서 대상으로 휜 화살표, 점선이 원본 → 대상으로 흐르고 가운데에 "web → n3 · 62%"(디스크 복사 진행 — 작업 센터와 같음), 메모리 단계면 "web → n3 · 메모리 옮기는 중". 대상 노드의 빈 칸에 점선 유령 타일. 끝나면 화살표가 사라지고 타일은 대상 노드의 이름 순 자리에 들어간다 |
| 요약 단계 | 멀리서는 노드 윗면 가운데 띠를 켜짐·바뀌는 중·실패·꺼짐 VM 수의 **비율**로 나눈다(조각마다 적어도 조금 — VM 1,000개 중 실패 하나도 보임). 수는 가리키기 카드·화면 읽기 이름에 |
| 범례 | 그림 아래 **"범례·조작 안내"** 단추로 펼친다(계획 77-8 — 그림 밑 두세 줄을 차지하지 않게): 타일 색, 꺼진 VM 띠, 부하 문턱, 빗금·줄무늬의 뜻, 켠 레이어의 색과 키보드 조작 안내. 색만으로 알리지 않는다 — 모양(빗금·줄무늬·테두리·꼬리표 글)이 따로 있다 |

**레이어**(도구 띠의 체크 상자, 기본은 부하만):

|---|---|

| 스토리지 | 블록 밑 받침 — 로컬 풀마다 한 조각(사용률 색, 준비 안 된 풀은 빨간 빗금). 공유 풀(NFS·RBD·공유 LVM)은 판 앞의 띠("공유: 이름들")이고, 공유 풀이 준비 안 된 노드는 받침 앞에 경고 눈금 |

| 추천 | 최적 배치 추천을 흐르지 않는 회색 점선 화살표로. `/placement`를 읽지 못하면 "(배치 요약을 읽지 못함)", 균형 조정기가 `off`면 "(균형 조정기 꺼짐)"과 함께 막힌다 |

**포트 줄과 네트워크 레일(계획 75).** 네트워크 레이어를 켜면 노드 블록 앞면 아래에 업링크·underlay 물리 포트가 작은 블록 줄로
놓이고(노드마다 8개까지, 넘으면 "+n" — 본딩 구성 포트는 붙여서 묶음 테두리), 지도 밑 바닥 판에 **레일**이 깔린다. 레일은 네트워크를
실어 나르는 것(브리지·physnet·VXLAN underlay)마다 하나이고(판마다 8개까지, 넘으면 "레일 +n") 그 위에 "vmbr0 · 네트워크 3"처럼 그
위 네트워크 수가 있다. 노드의 업링크 포트에서 레일로 짧은 세로 선이 내려간다. 포트 색은 연결됨·저하·끊김이고 모양이 따로 있다 —
저하는 빗금, 끊김은 ×, 레일에서 끊긴 노드의 선은 ×. 장애가 있는 노드에는 "링크 ✕ n" 꼬리표가 붙는다. 포트를 가리키면 카드(종류·속도·
MTU·본딩과 모드·LLDP 스위치와 포트 — 없으면 "lldpd를 설치하면 스위치 포트가 보입니다." — 와 영향 "네트워크 n개·VM m개 끊김"),
누르면 같은 내용의 서랍이다. 레일을 누르면 그 레일을 쓰는 노드·네트워크를 밝히고 서랍에 노드마다 상태다. 요약 단계에서는 포트 줄이
계획 70의 업링크 띠 하나로 접힌다. 포트·레일 그림과 카드는 네트워크 레이어를 켤 때 따로 받는 조각이다. 범례에 포트 연결됨·저하(빗금)·
끊김(×)·본딩(구성 포트 테두리)·네트워크 레일·레일에서 끊김(×)·링크 장애가 더해진다. 100노드 × 50VM에서 네트워크 층을 켜도 배치 + 경로가
30 ms 안이고 원소 예산 안이다(시험이 잰다 — 색·층마다 합친 경로 하나).

**자세히 보기 단계**는 배율에 따라 저절로 바뀌고 도구 띠 아래 한 줄로 알린다(문턱 둘레 15% 이력으로 깜박이지 않음).

| 요약 — "요약 — 확대하면 VM 타일." | 타일 한 칸이 화면에서 6px 밑, 또는 VM이 3,000개를 넘음 | 블록·열 색·꼬리표와 노드마다 상태별 막대 넷(켜짐·바뀌는 중·실패·꺼짐 — 높이가 수) |
| 타일 — "VM 타일 — 더 확대하면 이름." | 6~18px | 블록 채움과 VM 타일(층·색·면마다 합친 경로 하나 — 원소 수를 줄임) |
| 자세히 — "자세히." | 18px 이상이고 화면 안 타일이 300개 밑 | 블록 윗면의 "CPU 72% · 메모리 64%", 타일 윗면의 VM 이름(앞 8자), 배치 규칙을 어긴 VM의 경고 삼각형 |

- **가리키기·누르기.** 노드·타일·화살표를 가리키면 떠 있는 카드다(노드: 상태·CPU·메모리 %·크기·할당·VM 수·템플릿 수·로컬 풀,
  VM: 상태·vCPU·메모리·노드·옮기기 진행). 가리킨 노드와 이어진 것(그 노드의 화살표)만 남기고 나머지 노드를 흐린다. **누르면 서랍**이다.
  노드는 미리 보기(상태·주소·버전·CPU·메모리)와 "노드 동작"(노드 목록의 행 메뉴와 같은 유지보수·비우기·레이블 등 — 권한이 없으면
  숨김), "네트워크 토폴로지에서 보기", 그 노드의 VM 목록(실패 먼저), 그 노드에서 나가고 들어오는 화살표의 "마이그레이션과 추천"(누르면 그 화살표 서랍 —
  키보드로 화살표에 닿는 길). VM은 미리 보기와 **"옮기기…"**(VM 화면과 같은 마이그레이션
  대화상자 — 막히면 까닭), VM 동작 메뉴. 마이그레이션 화살표는 원본·대상·진행과 "작업 열기", 추천 화살표는 복사할 메모리·까닭과
  **"적용"**(확인 뒤 최적 배치 화면의 적용과 같은 요청 — 그 VM을 옮길 권한이 있을 때만). "+N"·"+N 볼 수 없음"·"배치 안 됨" 판은 이름 거르기가 있는 VM 목록 서랍이다.
  **더블클릭**이나 `Ctrl`·`⌘`+누르기는 서랍 없이 노드·VM 상세 화면으로 간다. 서랍을 닫으면 초점이 그림의 그 원소로 돌아온다. 그림을
  끌면(4px 넘게) 서랍을 열지 않는다 — 켜진 VM 타일에서 시작한 끌기는 아래 "끌어 옮기기", 그 밖은 보기 움직이기다. 터치에는 가리키기가
  없어 한 번 누르면 서랍이다.
- **보기 움직이기.** 타일이 아닌 곳(또는 끌 수 없는 타일)을 끌기, `Ctrl`+휠·두 손가락 확대, 그림 오른쪽 위 확대·축소·화면에 맞추기 단추.
  데이터가 바뀌어도 사용자가 움직인 적이 없을 때만 다시 맞춘다.
- **끌어 옮기기(계획 71).** 켜진 VM 타일을 눌러 4px 넘게 움직이면(터치는 타일 위 350 ms 길게 누른 뒤) VM 이름 알약이 포인터를 따라가고,
  노드마다 놓을 수 있는지를 밝힌다: 놓을 수 있음은 윗면 테두리 `--brand`, 경고(놓을 수 있지만 알아 둘 것)는 노란 테두리, 막힘은 흐린
  블록과 빗금. 원래 노드에는 "여기서" 알약. 포인터 아래 노드의 까닭은 카드 자리와 화면 읽기 알림 줄에 나온다. 판정은 **예상**이고 위에서부터
  첫 것이다: 같은 노드, 위트니스·오프라인·얼림·유지보수·아키텍처 다름, 그 노드에서 VM CPU 모델을 켤 수 없음, 전용 CPU·hugepages·vNUMA가
  안 맞음, hard 배치 규칙을 어김(admin은 경고 — 대화상자에서 넘길 수 있음)은 막힘, 메모리 여유가 VM보다 적음과 로컬 디스크 복사("로컬
  디스크 20 GiB를 복사합니다")는 경고다. 그림 가장자리 48px 안으로 끌면 보기가 그쪽으로 옮겨 간다(동작 줄이기면 0.6초마다 1/3씩 뛴다).
  놓을 수 있는 노드에 놓으면 **그 노드를 고른 옮기기 대화상자**가 열린다(VM 서랍의 "옮기기…"와 같은 대화상자·API — 로컬 디스크 복사·대상
  풀·규칙 넘기기·확인은 대화상자가 정한다). **놓기만으로 옮기지 않는다.** 막힌 노드·빈 곳·원래 노드에 놓으면 아무것도 하지 않고 알림
  줄이 까닭을 읽는다. 끌 수 있는 타일은 켜진 VM이고 그 VM에 `vm.migrate` 권한이 있으며 다른 작업 중이 아닐 때다 — 꺼진 VM·권한 없는
  VM의 타일은 끌면 보기가 움직인다. 요약 단계에는 타일이 없어 끌기도 없다(확대하거나 `m`). 끄는 동안 노드 블록은 다시 그리지 않는다.
- **거르기.** "보일 판"(판이 둘 이상일 때 — 판 하나만 다시 배치), "꺼진 VM 감추기", "문제만"(오프라인·유지보수·부하 90% 이상·경보·실패 VM이
  있는 노드만 진하게, 나머지를 흐림). 노드가 200개를 넘으면 "판 하나만 보면 읽기 쉽습니다" 띠.
- **주소로 가리키기.** `/cluster/map?focus=node:<이름>` 또는 `?focus=vm:<이름>`은 그 원소로 맞추고 초점을 준다(서랍은 열지 않음).
  `?focus=port:<노드>/<포트>`(예: `port:svc01/eno1`)와 `?focus=rail:<운반자>`(브리지·physnet 이름, VXLAN은 `underlay`)는 네트워크
  레이어를 (기억하지 않고) 켜고 그 노드로 옮겨 포트·레일을 밝힌다 — 경보 알림에서 그 포트로 가는 길이다(링크 경보의 알림 본문
  `Map:` 줄·웹훅 `subject.map`, 경보 목록·종 서랍의 대상 링크가 이 주소다). 레일 선의 회색 점선은 "모름"이다.

**키보드.** 그림은 탭 차례 하나다(`Tab`은 그림을 떠난다). 초점은 노드 단계와 그 노드의 VM 단계 둘이다. 키는 그림에 초점이 있을 때만
받고(`Esc`는 VM 단계에서만 — 노드 단계면 화면의 `Esc` 그대로), 그림 아래 한 줄 안내와 `?` 도움말의 "클러스터 지도" 묶음에 같은 것이 있다.

| 키 | 노드에서 | VM 타일에서 |
|---|---|---|
| `←` `→` `↑` `↓` | 이웃 노드(판 격자의 열·줄, 판 끝에서는 옆 판) | `←` `→` 이름 순 앞뒤 타일, `↑` `↓` 위·아래 층 |
| `]` | 그 노드의 첫 VM 타일로 들어가기(요약 단계면 그 노드의 VM 목록 서랍) | — |
| `[` 또는 `Esc` | — | 노드로 나오기 |
| `Home` `End` | 첫·끝 노드 | 그 노드의 첫·끝 타일 |
| `Enter`·`Space` | 서랍 열기 | 서랍 열기 |
| `Shift+Enter` | 노드 상세 화면 | VM 상세 화면 |
| `m` | — | 그 VM 옮기기 모드(아래) |
| `p` | 그 노드의 포트 줄 첫 포트로(네트워크 레이어 — 포트에서는 `←` `→` 포트 사이, `Home` `End` 첫·끝, `↓` 그 포트의 레일, `[`·`Esc` 노드로) | — |
| `+` `-` `0` | 확대·축소·맞추기(초점 원소를 화면 안에 둠). `Ctrl`·`⌘`와 함께면 브라우저의 쪽 확대 그대로 | 같음 |

레일에서는 `←` `→`가 같은 판의 앞뒤 레일, `↑`가 그 노드에서 이 레일로 오는 포트(없으면 노드), `[`·`Esc`가 노드로 나온다.
타일 단계에서도 화면 초점은 노드 원소에 있고, 원소마다 화면 읽기 이름("노드 n3, 판 rack-a, 온라인, CPU 72%, 메모리 64%, VM 3개(켜짐 1,
바뀌는 중 1, 실패 1), 경보 2", "VM web, 마이그레이션 중, 노드 n3, HA, n5(으)로 옮기는 중 62%")을 초점이 옮겨 갈 때 `aria-live` 줄이 읽는다.

**`m` — 끌지 않고 옮기기(계획 71).** VM 타일 단계(`]`로 들어간 뒤)에서 `m`을 누르면 그 VM의 옮기기 모드다. 알림 줄이 "web 옮기기.
화살표로 노드를 고르고 Enter로 놓고 Esc로 취소합니다. 놓을 수 있는 노드 2개."를 읽고, 화살표·`Home`·`End`가 노드 단계 이웃으로 옮기며
노드마다 판정을 읽는다("n2 위. 놓을 수 있습니다. 메모리 여유 12 GiB.", "n4 위. 놓을 수 없습니다: n4는 유지보수 중입니다"). `Enter`·`Space`는 놓을 수 있는 노드면 끌어 옮기기와 같은
옮기기 대화상자를 열고, 막힌 노드면 까닭을 다시 읽는다. `Esc`는 취소("취소했습니다.")이고 초점이 그 노드로 돌아온다. `Tab`은 취소하고
그림을 떠난다. 놓을 수 있는 노드가 없으면 "web 옮기기: 놓을 수 있는 노드가 없습니다. Esc로 취소합니다.", 꺼진 VM이면 "꺼진 VM은 편집에서
노드를 바꿉니다.", 권한이 없으면 그 까닭만 읽는다. 판정 함수는 서랍 조각과 함께 받으므로 지도를 연 직후 잠깐은 끌기·`m`이 없다(그림은
기다리지 않음). 세 번째 길은 그대로 VM 서랍의 "옮기기…"다.

- **목록 보기.** 도구 띠의 그림 | 목록에서 "목록"은 같은 모델을 나무 목록(판 → 노드의 상태·부하 글 → VM의 상태)으로 보인다. 화면 읽기
  프로그램·인쇄용이고 노드·VM 이름을 누르면 같은 서랍이다. 그림의 화살표(진행 중 마이그레이션, 레이어를 켠 추천)는 "마이그레이션과 추천"
  절의 단추이고 누르면 같은 화살표 서랍("작업 열기"·"적용")이다. 그림으로 돌아오면 그림의 초점을 지킨다. 정렬·숫자 비교는 보기 "노드"(노드 표)가 맡는다.
- **휴대폰(768px 미만).** 도구 띠가 그림 | 목록과 **"보기 설정"** 단추 하나(아래에서 오는 서랍 — 묶기·보일 판·레이어·거르기)로 접힌다.
  그림 높이는 `min(70vh, 560px)`이고 맞추기 배율이 작아 대개 요약 단계로 그린다. 서랍도 아래에서 온다. 가로 스크롤은 없다(그림 안만 끌기).
- **동작 줄이기.** 운영체제의 "동작 줄이기"를 켜면 화살표 흐름과 맥박을 끈다(점선은 멈추고 진행률 글은 남음). 밝음·어둠 테마는 같은
  색 토큰에서 셈한다(상태 색·꼬리표는 두 테마의 `--card` 위 3:1을 시험이 잰다).
- **기억.** 그림 | 목록, 묶기, 켠 레이어, 거르기를 사용자마다 브라우저에 기억한다(`opl.<사용자>.clusterMap.mode`·`group`·`layers`·`filter`).
  휴대폰과 넓은 화면이 같은 기억을 쓴다.

## VM 만들기 화면

VM 만들기(`/vms/-new`)는 **그림 한 화면**이다(계획 77-5 — 계획 71의 끌어 놓기 빌더와 폼을 합침). 값은 VM 고치기 폼과 같은 `VmFormValues`라
검사·요청이 같고, 만들기 요청도 같은 API다(`POST /volumes` → `POST /placement-rules` → `POST /vms`, 템플릿은 `POST /vms/{key}/clone`). 서버에
더한 것은 아무것도 바꾸지 않는 미리 확인 `POST /vm-checks` 하나다([만들기 전 미리 확인](vms.md#만들기-전-미리-확인)) — 꺼진 채 만들 VM에는
"켜면 놓일 노드"(`start_node`)도 준다. 옛 빌더 주소 `/vms/-new/builder`는 `/vms/-new`로 넘긴다(쿼리 그대로). 화면 코드와 문구는 늦게 읽는
조각이다.

- **1단계 — 용도 카드** "무엇을 돌릴 VM인가요?": 리눅스 서버(vCPU 2·4 GiB·디스크 20 GiB, 첫 부팅 자동 설정·게스트 에이전트), 웹 서버(1·2 GiB·
  16 GiB — 들어오는 tcp 80·443을 받는 보안 그룹이 있으면 NIC에 건다), 데이터베이스(4·16 GiB·디스크 32 + 100 GiB), Windows 11·서버(4·8 GiB·
  64 GiB, UEFI·보안 부팅·TPM·SATA·e1000e + 설치 ISO를 넣을 빈 CD 드라이브가 먼저 부팅), ISO로 설치(2·4 GiB·32 GiB + 빈 CD 드라이브가 먼저
  부팅), 템플릿에서(카드 안에서 템플릿을 고름 — 없으면 흐림), 이미지 라이브러리(받는 화면으로 — 받은 이미지는 템플릿이 되어 "템플릿에서"로
  만든다), 빈 VM(전문가). 카드마다 그림·한 줄 설명·기본 크기가 있다. 새 디스크는 첫 공유 풀(없으면 첫 풀), NIC는 첫 네트워크(없으면 `user`)에
  붙는다. 카드가 OS 프리셋을 놓을 수 없으면 **흐리고 까닭**을 보인다 — 놓기 규칙(`accepts`)과 같은 검사다(Windows는 TPM을 켤 노드가 없거나
  "이 클러스터는 Arm(virt) 노드뿐이라 Windows VM을 만들 수 없습니다"). 풀·볼륨·네트워크·VM 목록을 다 읽기 전에는 카드를 누를 수 없고("…읽는 중"),
  새 디스크를 둘 풀이 없으면 크기 줄이 "디스크 없음(풀 권한 없음)"이다. 카드가 약속한 디스크·NIC(쓸 네트워크가 없어 NAT)를 붙이지 못하면 검사
  경고로 알린다. VM을 만들 수 있는 폴더가 없으면 카드 위에 그렇다고 알린다. 고른 용도는 주소(`?purpose=linux`, 템플릿은 `&template=<id>`)에
  남아 뒤로 가기가 카드로 돌아가고, 제목 옆 "용도: … 바꾸기"도 카드로 간다(지난 카드에 초점, 쳐 둔 이름·폴더는 다음 카드가 이어 받는다). 주소의
  용도를 쓸 수 없으면(막힌 카드·없는 템플릿) 카드 화면과 까닭을 보인다. 카드를 고르면 그 틀이 되돌리기의 바닥이고, 초점은 그림의 첫 칸(CPU·
  메모리)으로 가며 알림 줄이 "리눅스 서버로 시작합니다."를 읽는다. 새 틀의 CPU 모델은 클러스터 CPU 기준이 있으면 `cluster`다(서랍을 열지 않아도).
- **OS 고르기.** 카드는 디스크에 OS를 넣지 않는다. 리눅스·웹·DB 카드는 고른 직후 그림 위에 "OS 고르기" 카드가 열린다(초점도 거기): 템플릿·이미지
  (이미지 라이브러리에서 받은 이미지는 템플릿이 된다 — 고르면 템플릿 배포가 되고 카드의 vCPU·메모리는 지킨다)나 설치 ISO(CD 드라이브, 먼저
  부팅). Windows 카드는 설치 ISO(첫 CD)와 선택으로 virtio 드라이버 ISO(둘째 CD)다. 고르지 않아도 된다 — 디스크가 모두 새 빈 볼륨이고 CD에도 ISO가
  없으면 검사가 "부팅할 OS가 없습니다 — 이미지나 ISO를 붙이세요"라고 경고하고(만들기는 막지 않음), 그림 위 "OS 고르기(이미지·ISO)" 단추로 다시 연다.
- **2단계 — VM 그림.** 1280px 이상에서는 머리줄·본문 여백을 뺀 높이에 세 칸이 들어간다(1440×900·1280×720 모두 문서 스크롤 없음, 그림 칸도
  스크롤 없음 — 부품 상자와 요약의 검사 결과만 안에서 스크롤):
  - **왼쪽 부품 상자**(14rem): 짧은 여섯 묶음(디스크·설치 매체·네트워크·첫 부팅 자동 설정·배치·보호), 묶음마다 넷까지 보이고 "n개 더". 부품을
    **누르면 붙는다**(그 부품을 받는 첫 칸 — 풀은 디스크 목록 끝, ISO는 빈 CD 드라이브가 있으면 그것, 보안 그룹·주소는 그것을 받는 첫 NIC).
    끌어 원하는 칸에 놓아도 되고 키보드로 들어도 된다(아래 표). "⋯"은 붙일 곳 고르기다. 배치 묶음은 자동·장애 영역을 노드보다 먼저 보인다.
    크기·OS는 용도 카드와 그림의 칩, CPU 모델은 고급 서랍, 템플릿은 용도 카드, 폴더는 요약에 있다.
  - **가운데 VM 그림**: 위에 CPU·메모리 포트(vCPU 1·2·4·8·16과 메모리 1·2·4·8·16·32 GiB 칩 — 지금 값이 눌린 칩, 노드 메모리에 넉넉함·빠듯함·
    모자람), 가운데 VM 본체(머리 줄에 이름·OS, 디스크 칸(위가 먼저 부팅)·CD 칸·부팅 순서 "부팅 순서: CD 1 → 디스크 1"), 오른쪽 포트에 NIC와
    첫 부팅·보호(제목 옆 ⓘ 한 줄 설명). 긴 문제 글(서버의 원문 오류)은 두 줄로 줄이고 "자세히"로 펼친다. 칸마다 "+"(새 디스크·CD 드라이브·
    NIC — 기본 부품)와 연필("… 고치기")이 있다. 블록(디스크·CD·NIC 한 줄)은 손잡이·누르면 **그림 위 카드**(살피기 — 밀대·숫자 칸·버스·
    MAC 등, 닫기)·`⋮`(위로·아래로·빼기)다. 블록을 들면 그림 아래에 **빼기** 칸이 나온다.
  - **오른쪽 고정 요약·검사**(19rem): 이름(칸 설명 그대로), 폴더, **배치 칸**(ⓘ, 놓는 칸이기도 하다 — 노드 고르기: 자동·장애 영역·노드, 못
    쓰는 노드는 흐림, 노드를 읽지 못하면 "VM을 둘 곳은 서버가 정합니다." — 와 **놓일 노드의 여유 막대**: 고른 노드, 아니면 서버 미리 확인이 고른
    노드(켜진 채 `node`, 꺼진 채 `start_node`). 서버가 답했는데 노드가 없으면 막대 대신 "지금 이 VM을 놓을 수 있는 노드가 없습니다"(꺼진 채면
    "지금 켜면 놓을 수 있는 노드가 없습니다", 다른 오류 때문이면 그렇다고)이고, 메모리가 가장 많이 남은 노드(어림)는 답을 기다리는 동안만이다.
    막대는 서버 배치와 같은 기준이다 — 그 노드에서 켜기로 된 VM(`spec.node`·`spec.power: running`)의 vCPU와 할당 메모리, 새 디스크가 가장 많이
    가는 풀(다른 풀이 더 있으면 "외 n개 풀"), 이미 쓴 것 + 이 VM, 넘치면 경고색. vCPU를 노드 스레드보다 많이 나눠 주면 오버커밋 경고), 펌웨어·
    보안 한 줄(UEFI·보안 부팅·TPM·게스트 에이전트 — "고급 설정에서 바꾸기"), 검사(서버 확인 상태와 문제 셋까지 + "n개 더" — 1280px 이상은 이
    부분만 안에서 스크롤, 누르면 그 칸. 고급 서랍에서만 고치는 칸(보안 부팅·vTPM·예약 스냅샷·복제·최대 vCPU/메모리·NUMA·CPU 플래그·HA 세부·
    부팅 순번·QoS)의 문제는 서랍을 열고 그 칸으로), 만든 뒤 시작, **만들기**(늘 보임). 고급 설정·요청 보기(JSON·CLI) 단추는 화면 머리줄에 있다.
- **오류는 건드린 뒤에.** 이름을 넣기 전에는 빨간 오류가 없다 — 이름 칸을 떠났거나 만들기를 누른 뒤에 이름 문제(와 이름을 따라갈 새 디스크의
  빈 볼륨 이름)가 보인다. 만들기는 늘 누를 수 있고, 막는 문제가 있으면 보내지 않고 모든 문제와 "아직 만들 수 없습니다: …"(누르면 그 칸)를
  보인다. 이름이 없으면 검사 줄은 "이름을 넣으면 서버가 만들 수 있는지 미리 확인합니다."다.
- **고급 설정 서랍**(오른쪽): VM 고치기 폼의 섹션 그대로(칸 설명·ⓘ 포함) — CPU 모델·플래그·최대 vCPU/메모리·펌웨어·가상 메인보드·NUMA·
  전용 CPU·hugepages·재시작 정책·노드 고정·HA 세부, 보안 부팅·vTPM·게스트 에이전트, 장치 세부(디스크·NIC — QoS·MAC·부팅 순번, CD), 첫 부팅
  세부(cloud-init), 부팅 순서, 예약 스냅샷, 복제. 그림·요약에 있는 이름·코어(소켓이 하나일 때)·메모리·폴더·노드는 없다. 기본값은 손대지 않아도
  되고, 오류는 서랍의 칸을 떠난 뒤나 만들기를 누른 뒤에 보인다. 고친 칸은 그림 위 칩 "고급 설정에서 고친 칸 n개(…)"로 알린다. 템플릿 바탕이면
  "템플릿 배포는 이 설정을 싣지 못합니다"만 보인다.
- **좁은 화면(1280px 밑)·휴대폰.** 한 칸으로 쌓인다(이름·폴더 → 그림 → 요약). 부품 상자는 그림 위 "부품 더하기" 단추가 여는 아래 서랍이고
  부품을 누르면 붙고 서랍이 닫힌다. 그림 안 포트는 640px 밑에서 세로로 쌓인다. 만들기 줄(만든 뒤 시작·만들기)은 페이지 아래 고정 띠(한 줄,
  안전 영역 여백)이고, 입력 칸은 초점을 받으면 띠 위로 올라온다. 가로 스크롤은 없다. 모양에는 키프레임·전환 움직임이 없다.

**살아 있는 확인**(오른쪽 요약의 "검사"):

1. **브라우저 검사는 즉시**: 폼과 같은 `validate()`, 놓은 뒤 바뀐 세상(지운 풀·네트워크, 못 쓰게 된 노드), 용량·할당량 경고. 문제는 그
   칸의 테두리(오류 빨강·경고 노랑 — 아이콘과 "오류:/경고:" 글이 함께)와 요약의 목록에 있고, 목록을 누르면 그 칸으로 초점이 간다. 이름
   문제는 이름 칸을 떠나거나 만들기를 누른 뒤에 보인다.
2. **서버 확인**: 브라우저 오류가 없을 때만, 마지막 바뀜 0.6초 뒤 `POST /vm-checks`를 보낸다(하나만 날고 앞 요청은 끊는다, 비밀번호 평문은
   보내지 않는다). 상태 줄은 "서버에 확인하는 중…" → "서버 확인: 통과." / "서버 확인: 문제 n개."이고, 통과하면 **"node1에서 돕니다"**(지금
   클러스터에서 고를 노드의 예상 — 꺼진 채 만드는 VM도 보일 수 있고, 켤 때 스케줄러가 다시 고른다)·CPU 모델·머신·NIC마다 받을 SDN 주소(예상)를
   보인다. 서버 문제는 브라우저 문제와 같은 칸에 붙는다(자리가 정해지지 않은 할당량·`spec`·복제 문제는 VM 틀 전체). 그 사이 값이 바뀌었으면
   지난 답을 흐리게 두고 "값이 바뀌어 다시 확인합니다."를 붙인다(지난 답은 만들기를 막지 않음). 결과가 바뀌면 알림 줄이 "서버 확인: 문제 2개."를
   읽는다(초점은 옮기지 않음).
3. **서버 확인을 할 수 없을 때**: 노드 하나라도(위트니스 빼고) 기능 `vm-check`가 없으면 묻지 않고, 409 `cluster_upgrading`과 옛 노드의 404(길이
   없음 — `no API at …`)면 "서버 미리 확인은 모든 노드를 올린 뒤에 됩니다. 만들 때 서버가 확인합니다.", 403이면 "이 폴더에 VM을 만들 권한이
   없습니다.", 그 밖 실패(볼 수 없는 폴더의 404 등)는 "서버에 확인하지 못했습니다. 그래도 만들 수 있습니다."와 서버의 까닭, "다시 확인" 단추다.
   지난 시도가 남긴 배치 규칙을 아직 지우는 중이거나 지우지 못했으면 묻지 않고 "지난 시도가 남긴 배치 규칙을 지운 뒤에 서버 확인을 합니다."다.
   **어느 것도 만들기를 막지 않는다.** 템플릿 바탕은 서버 미리 확인이
   없다("템플릿 배포는 만들 때 서버가 확인합니다.").

**만들기** 단추는 늘 누를 수 있다. 브라우저 오류나 **지금 값에 대한** 서버 오류가 있으면 보내지 않고 첫 까닭("아직 만들 수 없습니다: …")을
보인다. 경고는 막지 않는다. 폴더 할당량은 브라우저 어림 경고와 서버 확인(`quota_exceeded`)으로 보인다.

- **JSON·CLI 미리 보기**(요약의 "요청 보기(JSON·CLI)" 서랍). "JSON" 탭은 만들기가 보낼 요청을 차례대로 `# POST /api/v1/volumes`·`# POST /api/v1/placement-rules`·`# POST
  /api/v1/vms`(템플릿은 `# POST /api/v1/vms/<id>/clone`) 머리와 본문으로 보인다(만들기와 같은 함수). cloud-init 비밀번호는 `********`로 가리고
  바꾸라는 줄을 붙인다. "CLI" 탭은 같은 일을 하는 `orbivisorctl volume create <이름> --pool <풀> --size 20G`,
  `orbivisorctl placement-rule create <vm>-zone --kind node-affinity --vm <vm> --node-tag zone=<값>`, `orbivisorctl vm create <이름> …`
  (템플릿은 `orbivisorctl template deploy …`)이고, 비밀번호는 `--ci-password-prompt`, 직접 쓴 user-data는 `cat > … <<'EOF'` 파일과
  `--ci-user-data`다. 플래그가 없는 값(디스크마다 다른 버스·NIC마다 다른 모델·고정 MAC·NUMA·스냅샷 예약·배포의 폴더와 보안 그룹)은 "… CLI 플래그가
  없습니다 — JSON 요청을 쓰세요." 주석 줄이다. 두 탭 모두 복사 단추가 있고 고른 탭을 기억한다(`vmBuilder.panel`). 웹의 CLI 줄을 진짜 CLI가 풀어 같은
  `POST /vms` 본문을 만드는지를 시험이 본다(개발 안내).
- **만들기.** "만든 뒤 시작" 체크와 만들기 단추. 폼과 같은 차례다: 새 디스크마다 `POST /volumes`(볼륨 Task를 기다림) → 영역을 놓았으면 배치
  규칙 `POST /placement-rules`(`<vm>-zone`, `node-affinity`·`node_tag: zone=<값>` — 아직 없는 VM 이름을 받고 스케줄러가 켤 때 따름, soft면
  `soft-node-affinity`) → `POST /vms`(성공하면 `/vms/<이름>`) 또는 템플릿 배포 Task(작업 센터에서 따라가고 VM 목록으로). 화면을 떠나면 기다림을
  끊는다. 중간에 실패하면 "이미 만든 것: web-disk0, web-zone. <오류>"로 남은 것을 알리고, 만든 볼륨은 "있는 볼륨"으로 바뀌고 만든 규칙은 기억해
  **다시 만들기를 눌러도 또 만들지 않는다**. 그 뒤 영역(값·hard/soft)을 바꾸거나 빼거나 노드·자동으로 바꾸거나 VM 이름을 바꾸면 이 화면이 만든
  영역 규칙을 곧 지운다(남은 hard 규칙이 확인과 만들기를 막지 않게 — 지우지 못하면 "지난 시도가 남긴 배치 규칙 …을 지우지 못했습니다"를 보이고
  다음 만들기가 먼저 다시 지운다). 만들기는 언제나 남은 지난 규칙(VM 이름을 바꾸기 전의 것도)을 먼저 다시 지우고, 못 지우면 아무것도
  보내지 않고 "지난 시도가 남긴 배치 규칙 <이름>을 지우지 못했습니다: …"로 멈춘다. 만든 볼륨은 지우지 않는다(되돌리기로 앞 상태로 가도 "있는
  볼륨"이라 다시 만들지 않는다).
- **템플릿 바탕.** 용도 카드 "템플릿에서"로 고른 템플릿은 배포(`clone`)가 된다: 디스크·NIC·CD는 템플릿 것(잠금 — 더하기는 "만든 뒤 고치기에서"),
  계산·네트워크 바꾸기·디스크 늘리기("늘릴 크기")·cloud-init 덮어쓰기(비면 템플릿 것)·노드·풀·디스크 복사 방식(되면 연결 복제·연결 복제·전체
  복사)을 고친다. 보안 그룹은 배포 본문에 칸이 없어 막힌다. HA·HA 그룹·NIC 모델·노드 고정도 배포 본문에 없어 고를 수 없다(템플릿을 놓으면
  HA·노드 고정이 꺼지고, 보호 칸은 "템플릿 배포는 HA를 정하지 않습니다. 만든 뒤 켭니다.") — 만든 뒤 VM 고치기에서 바꾼다. 폼에서 고친
  칸 가운데 배포 본문이 싣지 못하는 것(복제·스냅샷 예약·재시작 정책·펌웨어·NUMA·최대 vCPU/메모리·게스트 에이전트 얼리기/끄기)은 템플릿을 놓을 때
  처음 값으로 비우고 틀 위 칩 "폼에서 고친 칸 n개(…)를 비웠습니다 — 템플릿 배포가 싣지 못합니다. 만든 뒤 고치세요."로 알린다. 살피기의 "빈 VM으로 돌아가기"·되돌리기로 돌아가고 "배포 대화상자에서 더
  고치기…"가 템플릿 화면의 배포 대화상자를 연다.

## VMware 이전 화면

계획 72. 메뉴는 **이미지·이전** 묶음이다: **가져오기(OVA·ESXi)**(`/imports`, 한 대씩 — 계획 29·30) · **VMware 이전(켠 채 복사)**(화면 안 탭:
이전 계획 `/vmware-migrations`(루트 `system.read`) | 원본 연결 `/vmware-sources`(루트 `cluster.read`)) · **내보내기**
(`/vm-exports`). 팔레트에서
"vmware"·"vcenter"·"cutover"·"ova"로 찾는다. 안내와 손 확인 절차는 [vCenter 일괄 이전](backup.md#vcenter-일괄-이전과-따뜻한-이전)에.

- **원본.** "원본 더하기" 대화상자(이름·호스트·포트·사용자·비밀번호·데이터센터 힌트·VDDK) → "연결" → 처음 보는 인증서면 SHA-256 지문과
  SHA-1 썸프린트(VDDK)를 보이고 "믿고 연결"로 다시 보낸다(계획 30 ESXi 대화상자와 같은 흐름). 표는 주소·제품·판·지문 앞부분·디스크
  읽는 길·상태(연결됨·실패·읽기 전용(무료 ESXi))이고 행마다 고치기(바뀐 칸만, 비밀번호는 비우면 그대로)·다시 확인·지우기. 비밀번호는
  컴포넌트 상태와 요청 본문에만 있고 브라우저 저장소·질의 캐시에 남지 않는다.
- **새 이전 마법사**(`/vmware-migrations/-new`). ① 원본·이름·방식(따뜻한·차가운) ② 인벤토리 나무 — "VM과 폴더" | "호스트와
  클러스터", 마디마다 VM 수, 찾기(이름·경로·OS·호스트·Tools IP)·전원 거르기, 다른 계획에 든 VM은 흐리게 고를 수 없음(까닭은 설명),
  "다시 읽기"(노드 캐시 60초) ③ 매핑 — 고른 VM이 쓰는 네트워크·데이터스토어만, 같은 이름 네트워크는 미리 고름, 기본 풀·폴더(한 폴더 |
  VMware 폴더 다시 만들기)·노드·장치 종류·드라이버 ISO·MAC 유지·IP 예약·"전환 뒤 켜기" ④ 한도(동시 수·호스트당·노드당·대역)와 동기화
  주기·전환 정책(게스트 종료 기다림·마지막 델타 한도·예약 전환·원본 보호) ⑤ 확인 — 여기서 초안 계획을 만들어 서버 미리 확인을
  돌리고 VM마다 판정 칩과 문제(자리·까닭)를 보인다. 뒤로 갔다 오면 새로 만들지 않고 초안을 고친다(이름·원본·방식은 잠김).
  "VM n대 시작"은 막힌 VM을 계획에서 빼고 시작하고, "초안으로 두기"는 상세로 간다.
- **이전 상세**(`/vmware-migrations/<이름>`). 머리에 단계 칩·방식·원본·상태별 수와 동작(확인·시작·멈춤·이어 가기·취소·지우기). VM 표는
  상태 칩(전환 중이면 걸음, 되돌림이 실패했으면 "되돌림 실패: <걸음>")·회차·복사 막대·마지막 델타·예상 내릴 시간(끝난 VM은 실제
  "4m 12s(실제)")·다음 동기화·대상 VM 링크다. 고른 VM을 한꺼번에 전환·취소한다. watch(`vmware-migration`·`vmware-vm`)로 바로 바뀐다.
- **VM 서랍.** 원본(호스트·전원·Tools·게스트 IP), 전환 요청·원본 끈 시각·내린 시간, 원본 NIC 보호, 경고·오류(자동 되돌림이 실패했으면
  "손으로 하거나 되돌림을 다시 하세요" 머리와 서버가 적은 손으로 할 일), 디스크별 진행·마지막 델타, 최근 기록, 동작(전환·되돌리기·
  마무리·다시 하기("되돌림 다시 하기")·취소).
- **전환 대화상자.** 고른 VM마다 예상 내릴 시간과 마지막 델타, 여럿이면 합, 원본 처리(게스트 종료와 기다림 또는 전원 끄기, 원본 보호면
  NIC 끊김, 새 VM 켜기/꺼진 채, 원본은 지우지 않음)를 보이고 VM마다 차례로 요청한다(일부 실패는 알림). 서버가 원본을 새로 읽고
  막으면(`preflight_blocked`) 까닭을 줄마다 덧붙인다. **되돌리기**는 대상 VM의 지금 이름을 그대로 적어야 진행한다(대상에서 쓴 데이터는
  원본으로 가지 않는다).
- **내보내기.** 내보내기 표(VM·풀·OVA 크기·상태·경고 수·내려받기·지우기). VM 상세 ⋯의 "OVA로 내보내기…"(꺼진 VM, 그 VM의
  `vm.export` — 켜져 있으면 막힌 항목과 까닭)는 대화상자를 그 자리에서 열지 않고 이 보기(`/vm-exports?export=<VM>`)로 가서 연다 — 진행과
  내려받기가 여기 있다. 내려받기는 10분짜리 서명 링크로 브라우저가 받는다(`{VM}.ova`).
- **묶음.** VMware 보기 넷은 늦게 읽는 조각 하나(`vmware/pages`, gzip 약 15 KB), 내보내기는 `exports/pages`(약 3 KB), 문구는 늦게 받는
  묶음이다. 첫 화면 묶음 증가는 1 KB 밑이다.

## 설정 기록·선언 묶음·인증서 화면

계획 73. 메뉴는 **기록** 묶음의 **변경 기록**(`/history`, 누구나 — 서버가 읽을 수 있는 리소스의 줄만 준다)·**코드로 관리(YAML)**
(`/apply-sets`, 루트 `system.read` — 화면 이름은 "선언 묶음")·**감사 로그**(`/audit`, admin)이고, **관리 › 보안·인증서**의 화면 안 탭이
**보안**(`/settings/security`, admin — 2단계 인증 정책) | **인증서**(`/settings/certificates`, 루트 `cluster.read`)다. operator·viewer가
보안·인증서를 누르면 보이는 첫 탭(인증서)으로 간다. 팔레트에서 "설정
기록"·"history"·"drift"·"인증서"·"ACME"로 찾는다. 안내는 [선언형 운영](declarative.md)과 [API 인증서(ACME)](cluster.md#api-인증서acme)에.

- **설정 기록.** 거르기 줄(종류·사용자·출처·기간 — 지난 1시간·24시간·7일·30일·남은 기록 모두, 폴더·선언 묶음) 아래 날짜로 묶은 시간 줄
  목록이다. 줄마다 시각·"만듦/바꿈/지움 종류 이름"·사용자·출처 칩(웹·CLI·API·적용·Terraform·Task·시스템)·사유·되돌린 줄 표시,
  "더 오래된 바뀜"으로 더 읽는다. 자동으로 다시 읽지 않는다(열 때·새로고침·되돌리기 뒤).
- **바뀜 서랍.** 줄을 누르면 오른쪽 서랍: 언제·누가·revision·사유·되돌린 줄·**감사 줄 id**(복사 단추 — 감사 로그 보기가 id로 거르지
  못해 링크는 없다), 비교할 것(바로 앞 바뀜 | 지금 리소스), 바뀐 칸만의 전·후 표, 펼치면 그 revision의 전체 설정. 비밀은 "(비밀 바뀜)"
  같은 표시뿐이다.
- **되돌리기 대화상자.** 서랍의 "이 revision으로 되돌리기…"(지운 리소스는 "…다시 만들기…")가 서버 계획(요약·단계·바뀌는 칸·경고
  `secret_not_restored` 등)을 보이고, "되돌리기"를 누르면 **그 계획을** 적용한다(그사이 바뀌었으면 오류 문구). 막힘이 있거나 이미 같으면
  단추가 꺼진다. 사유를 적으면 사유와 함께 다시 계획해 단계가 같을 때만 적용하고, 다르면 새 계획을 보이고 다시 묻는다. 지운 리소스의
  이름이 그새 쓰이면 새 이름 칸이 나온다(새 id). 비밀·이름·전원은 되돌리지 않는다고 대화상자가 알린다.
- **한 시점으로 되돌리기.** 설정 기록 보기의 단추 → 대화상자: 시점(시각 또는 revision), 범위(폴더·선언 묶음·종류 가운데 하나 이상 — 있어야
  "계획 보기"가 켜짐), "그 뒤 지운 리소스를 다시 만들기"(기본 켬)·"그 뒤 만든 리소스를 지우기"·"그 뒤 만든 VM·볼륨·백업 저장소도
  지우기"(지우기를 골랐을 때만). 무엇이든 바꾸면 본 계획을 버린다.
- **선언 묶음.** 목록(이름·객체 수·마지막 적용·누가·드리프트 칩 — 같음·N개 다름·아직 견주지 않음·마지막 적용 실패), 상세
  `/apply-sets/<이름>`(객체 표 — 상태 칩 같음·다름·없음·관리 밖, 다른 칸 펼침과 "누가 바꿨나"(시각·사용자·출처·revision), 고른 것 또는
  모두 "실제를 선언으로 받아들이기", 묶음의 "YAML로 내보내기", 그 묶음으로 거른 설정 기록 링크).
- **⋯ 메뉴 두 줄.** VM·보안 그룹·폴더 상세 머리의 ⋯와, 볼륨·네트워크·백업 작업·라우터·부하 분산기·배치 규칙·HA 그룹 목록의 줄 ⋯
  ("{이름} 더 보기")에 **"설정 기록…"**(그 리소스로 거른 서랍 "{이름}의 설정 기록")과 **"YAML로 내보내기"**(`GET /manifests/{kind}/{key}`를
  YAML로 — 복사·내려받기, 비밀은 `secretRef`, `orbivisorctl apply -f`가 그대로 읽는다)가 있다. 네트워크·백업 작업·배치 규칙·HA 그룹은 동작
  칸이 쓰기 권한이 있을 때만 있어 읽기 사용자는 줄 ⋯이 없다(설정 기록 보기에서 종류로 거른다). VM 케밥은 이제 viewer에게도 보인다.
  원격·HA 검사·ACME에는 없다.
- **Terraform 칩.** 레이블 `orbivisor.io/managed-by=terraform`인 VM·보안 그룹의 머리에 "Terraform이 관리" 칩이 있다 — 여기서 바꾸면
  다음 `terraform apply`가 되돌린다.
- **인증서.** ACME 계정·DNS 공급자·인증서 목록(노드마다 만료·다음 갱신·오류 칩, "지금 갱신"), 만들기 대화상자 셋: 계정(디렉터리 고르기·
  약관 동의 필수·EAB), DNS 공급자(종류마다 칸, 비밀은 비밀번호 칸이고 저장 뒤 다시 보이지 않음), 인증서(이름·노드마다/공유·도전·키
  P-256/P-384·프로필, HTTP-01이면 `http_listen`이 없는 노드 경고, 와일드카드는 DNS-01만). 쓰기 단추는 루트 `cluster.admin`일 때만 보인다.
- **링크·실시간.** 경보의 대상 링크는 인증서 → `/settings/certificates`, 적용 묶음 → `/apply-sets/<이름>`이고, Task `apply`·`acme-order`의
  대상도 링크다. 선언 묶음·인증서 목록은 watch 사건이 오면 다시 읽는다. 되돌리기·adopt 단추는 그 종류의 쓰기 권한이 있을 때만
  보인다(서버가 단계마다 다시 본다).
- **묶음.** 네 보기는 늦게 읽는 조각 하나(`history/pages`), 문구는 늦게 받는 묶음 셋이다. 첫 화면 묶음 증가는 868 B(gzip)다.

## 접근성과 모양

- **테마**: 시스템(기본)·밝게·어둡게. **밀도**: 편안하게(기본)·촘촘하게. 둘 다 사용자 메뉴에 있고 브라우저에 남는다.
- **움직임 줄이기**: 운영체제의 "동작 줄이기"(`prefers-reduced-motion`)를 켜면 서랍 미끄러짐, 스켈레톤 맥박, 바뀐 값 강조 같은
  움직임을 끈다.
- 상태는 색만으로 알리지 않고 글과 점(칩)으로 함께 보인다. 글·상태 칩의 대비는 4.5:1, 포커스 링·차트 선은 3:1 이상이다(시험이
  색 토큰을 확인한다).
- 첫 Tab에 "본문으로 건너뛰기"가 있다. 화면이 바뀌면 포커스가 제목으로 가고 화면 읽기 프로그램이 이동 경로를 읽는다. 대화상자·
  서랍·팔레트는 포커스를 가두고 닫으면 연 단추로 돌아간다. 표의 체크박스·정렬 머리·일괄 막대에는 이름과 상태가 있다.
- 화면 글은 한국어와 영어 모두 있다.

## 한계

- **즐겨찾기·최근 항목·저장 보기·열 설정·마지막 탭·레일 접기는 그 브라우저에만 있다**(localStorage, 사용자마다 따로). 다른
  브라우저나 기기로 옮겨 가지 않고, 브라우저 저장소를 지우면 사라진다.
- **팔레트의 IP 찾기는 게스트 정보를 받은 VM만** DHCP 주소를 찾는다. 게스트 IP를 모든 VM에서 미리 모으지 않으므로, 그 브라우저에서
  VM 상세의 게스트 탭(또는 게스트 정보가 보이는 화면)을 연 VM만 맞는다. cloud-init 고정 IP·MAC·노드 주소는 늘 찾는다.
- 다시 하기는 파라미터가 필요 없는 작업(VM 전원 넷, 백업 작업 실행)만 된다. 작업에 요청 파라미터가 남지 않아서다.
- 일괄 동작은 VM 목록에만, 미리 보기 서랍은 VM·노드 목록에만 있다. 열 순서 바꾸기, 표 CSV 내보내기, 셀 안 편집, 사용자 정의
  대시보드, 여러 클러스터를 한 표로 보기는 없다.
- 오른쪽에서 왼쪽으로 쓰는 언어와 고대비 테마는 없다.
- 설정 기록·선언 묶음(계획 73): 웹에 YAML 편집기(붙여 넣어 적용)가 없고, 목록에서 여러 줄을 골라 한꺼번에 YAML로 내보내지 못한다(선언 묶음 상세가
  묶음 전체를 낸다). 서랍의 감사 줄은 id 복사뿐이다(감사 로그 보기로 가는 링크 없음). 설정 기록은 실시간으로 바뀌지 않는다. 인증서 만들기
  대화상자에 노드 고르기·`preferred_chain`·갱신 정책·`install`이 없다(CLI·매니페스트로).
- 폴더 트리는 가상 스크롤이 없고(펼친 노드만 그린다) 템플릿 탭에는 트리가 없다. 끌어 놓기는 확인 없이 바로 옮긴다. 토큰 범위를
  정하는 화면은 없다(CLI). 볼륨·ISO·이미지·가져오기·백업 복원·템플릿 배포 단추는 그 권한이 어디에든 있으면 보이고, 그 객체에서
  되는지는 서버가 정한다.
- CPU 모델 목록에는 별칭(`Icelake-Server`)이 없다 — 버전 모델만 고른다(별칭 이름으로 찾으면 버전 모델이 나온다). 노드 목록에 "CPU
  모델" 열은 없고(노드마다 따로 읽어야 해서) 노드 상세에서 본다. CPU 화면에서 이 안내 문서로 가는 도움말 링크는 없다.
- 노드 "NUMA 토폴로지" 격자에는 소켓 층이 없다(토폴로지가 CPU마다 소켓 번호를 갖지 않아 호스트 노드 › L3 › 코어 › 스레드로
  그린다). VM 폼의 "들어갈 노드"는 노드마다 남은 전용 CPU·hugepages 수만 보는 어림이고(`isolate`의 형제는 빼지 않는다), 노드마다
  직접 나누는 표는 VM 폼에만 있다(복제·배포·가져오기는 노드 수까지).
- 주소가 있는 NIC의 빠진 체계를 채우는 단추는 없다(CLI `orbivisorctl network ips NAME --fill` — 주소가 없는 NIC는 서브넷을 더할 때
  서버가 채운다). "10초 안에 포트가 바인딩되지 않음"은 orbivisord 로그에만 있고 VM 화면에 없다.
- 게이트웨이 표에 chassis 상태 칸이 없다(SDN 보기의 chassis 표). 유동 IP 붙이기는 유동 IP 보기에만 있다(떼기는 VM 상세에도). 유동 IP를
  읽을 수 없는 VM 주인은 화면에서 그 유동 IP를 찾을 길이 없다(CLI·API로 키를 알아야 함).
- 토폴로지는 네트워크 200·VM 2000이면 SVG 원소가 약 11,400개라 느려질 수 있다(폴더 거르기·VM 감추기를 권하는 띠). 그림에서 끌어 놓아
  잇기(라우터 인터페이스 만들기 따위)는 없다. 옮기기 마법사는 VM마다 다른 방식을 고르지 않는다.
  SDN NIC의 보안 그룹 고르기는 기능 판정 없이 늘 열려 있다(섞인 클러스터는 저장할 때 409).
- 백업 저장소 마법사에는 **만들기 전 연결 확인이 없다**(만든 뒤 서랍의 "연결 확인" — 미리 볼 수 있는 키·주인 오류는 만들기 요청이
  알림). S3 끝점은 `https://`만 받는다(`insecure_http`는 CLI). 복원 대화상자에서 라이브 복원 노드를 고르지 못한다. 풀 백업에는 검증
  배지가 없다(풀 백업 검증 없음).
- 파일 찾아보기 화면에는 이름 검색(카탈로그)·파일 미리 보기·백업 사이 차이가 없다. 거르기는 이미 읽은 쪽만 본다. VM으로 복원 작업을
  화면에서 취소하지 못한다(서버에 Task 취소가 없음). RHEL 에이전트 설정은 대화상자에 서버 까닭 문구로만 보이고 안내 링크는 없다.
- 클러스터 지도의 끌어 옮기기(계획 71)는 **켜진 VM 하나를 노드로**만 끈다 — 꺼진 VM 끌기(노드 바꾸기는 편집에서), 여러 VM 끌기, 영역 판으로
  끌기는 없다. 놓을 자리 판정은 웹의 **예상**이다(hard 규칙·메모리 여유는 웹이 셈하고, CPU·NUMA는 든 VM의 질의를 받은 뒤에야 본다) — 최종은
  옮기기 대화상자와 서버(409 `placement_rule` 등)다. 그림에서 여러 개 고르기·일괄 동작, 노드 사이 네트워크 선, 시간 되감기, 랙 안 자리(U)는 없다. 부하는 리더가 모은 `/placement` 요약이라 15초마다 바뀌고, 리더에 묻지 못하면 "부하 모름"이다.
  합친 경로라 타일마다 DOM 초점이 없다(초점 테두리를 덧그리고 화면 읽기는 `aria-live` 줄). 끝난 마이그레이션 타일의 나타남 움직임은 없다.
  노드 200을 넘으면 판 하나 보기를 권하고(Web Worker·화면 밖 그리지 않기 없음), 다른 화면에서 지도로 가는 "지도에서 보기" 링크는 아직 없다.
- VM 만들기 화면은 **새 VM 만들기만** 한다(고치기는 폼 — VM 상세 › 하드웨어를 같은 그림으로 바꾸는 일은 남김). 한 번에 VM 하나이고,
  이미지 라이브러리에서 받으며 만들기는 없다(받아 템플릿으로 만든 뒤 "템플릿에서"). 용도 카드는 웹 고정 목록이다(관리자가 더하는 용도
  프리셋·"web-03처럼" 설정 복사는 없음). GPU·PCI 장치 슬롯은 없다(제품에 장치 넘기기가 없음). 서버 미리 확인은 **그 순간의 답**이다 — 잡아 두지 않으므로 확인과 만들기 사이 다른 사람이 바꾸면 만들기가 알린다. 고를 노드·SDN 주소는
  예상이고, 서버의 준비 단계(`prepare`) 문제는 첫 하나만 온다(독립 검사 — 이름·첨부 권한·만들 볼륨·만들 규칙·할당량 — 는 모두 모음). 템플릿
  배포에는 서버 미리 확인이 없고 디스크·NIC·CD 수를 바꾸지 못한다. 만들기가 중간에 실패하면 이미 만든 볼륨은 알리기만 하고 지우지 않는다(영역 규칙은
  영역·이름을 바꿀 때만 지운다 — VM 요청이 서버에서는 성공했는데 답이 끊긴 뒤 바꾸면 그 VM의 규칙을 지울 수 있다, 드묾). 이미 있는 볼륨과 이름이 겹치는 새 디스크는 브라우저 검사가 먼저 잡아 서버 확인을 하지 않는다(서버의 `name_taken`은 API·CLI에서
  보인다). VoiceOver·TalkBack 손 확인은 아직이다(알림 줄 문구는 자동 시험이 본다). 폴더 보기의 끌어 놓기는 그대로 HTML5 끌기다(터치 없음).
