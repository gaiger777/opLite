## 영역과 탭

**왼쪽 사이드바에는 최상위 영역만 있다.** 홈·가상 머신·인프라·보호·활동 다섯 개가 위에, 설정이 맨 아래에 있다. 펼치는 트리나
둘째 단계 항목은 없다. 영역에 들어가면 본문 위의 **영역 탭**에서 하위 화면을 고르고, 탭 안에서 다시 나뉘는 곳은 탭 아래의
**보기 전환**에서 고른다. 탭과 보기도 모두 주소가 있는 링크다.

| 영역 (영역 주소) | 탭 → 주소 (보기 전환) |
|---|---|
| 홈 `/` | 없음(한 화면) |
| 가상 머신 `/vms` | VM(목록 `/vms` \| 폴더 `/vm-folders`) · 템플릿 `/templates` · 이미지·ISO(이미지 라이브러리 `/images` \| ISO 이미지 `/isos`) · 가져오기 `/imports` |
| 인프라 `/infra` | 노드(노드 `/nodes` \| 클러스터 `/cluster`) · 스토리지 풀(목록 `/storage-pools` \| 폴더 `/storage-folders`) · 볼륨 `/volumes` · Ceph `/ceph` · 네트워크(목록 `/networks` \| 폴더 `/network-folders` \| 라우터 `/routers` \| 유동 IP `/floating-ips` \| 부하 분산 `/load-balancers` \| 토폴로지 `/networks/topology` \| SDN `/sdn`) · 보안 그룹 `/security-groups` |
| 보호 `/protect` | 백업 `/backups` · 백업 작업 `/backup-jobs` · 백업 저장소 `/backup-stores`(계획 68) · 원격 복제 `/remotes`(원격 읽기 권한) · HA 그룹 `/ha-groups` · HA 검사 `/ha-checks` · 배치(배치 규칙 `/placement-rules` \| 최적 배치 `/placement`) |
| 활동 `/activity` | 작업 `/tasks` · 경보 `/alerts` · 감사 로그 `/audit`(admin) |
| 설정 `/settings` (아래 고정) | 일반 `/settings` · 사용자 `/settings/users`(사용자 읽기 권한) · 인증 영역 `/settings/realms`(영역 읽기 권한) · 권한 `/settings/permissions`(admin) · 역할 `/settings/roles`(admin) · 그룹 `/settings/groups`(그룹 읽기 권한) · 보안 `/settings/security`(admin, 2단계 인증 정책) · API 토큰 `/settings/tokens`(모두, 자기 토큰) · 2단계 인증 `/settings/account`(모두, 자기 요소) · 원격 클러스터 `/settings/remotes`(admin) · 알림 대상 `/settings/notifications`(admin) · 구독 `/settings/subscription` |

- **권한.** 화면은 `/permissions/mine`(전역 역할과 폴더·객체 grant를 합친 내 권한)으로 **객체마다** 할 수 있는 동작만 보인다.
  루트에서 읽을 수 없는 종류의 탭(노드·Ceph·보안 그룹·백업 작업·HA·배치·설정 › 일반·구독 등)은 숨기고, 보이는 탭이 하나도 없는
  영역도 숨긴다. 폴더 권한만 있는 사용자는 목록·트리·팔레트에 자기 폴더의 것만 본다. 서버가 실제로 막는 것은 그대로다
  ([폴더와 권한](folders.md)).
- **폴더 보기.** VM·스토리지 풀·네트워크 탭의 보기 전환 `목록 | 폴더`는 왼쪽 트리와 그 폴더의 표("하위 포함" 칩)다. 폴더
  상세(`/vm-folders/:id` 등)는 `내용 | 할당량 | 권한` 탭이다. 행을 트리로 끌어 놓거나 일괄 막대의 "폴더로 옮기기…"로 옮긴다.
  VM 상세에는 "권한" 탭이, 풀·네트워크 행에는 같은 내용을 서랍으로 여는 방패 단추가 있다([폴더와 권한](folders.md#웹-화면)).
- **상세 화면은 그 탭에 속한다.** `/vms/web`·`/vms/-new`·`/vms/web/edit`은 VM 탭, `/nodes/node1`은 노드 탭,
  `/vm-folders/x`는 VM 탭의 폴더 보기, `/security-groups/web`은 보안 그룹 탭, `/imports/x`는 가져오기 탭, `/remotes/dr`(원격 클러스터의 VM)은 원격 복제 탭이다.
  콘솔(`/vms/web/console`)만 영역 탭 없이 전체 폭이다.
- **원격.** 보호 › 원격 복제는 원격 클러스터의 상태 카드, 원격 대상이 있는 백업 작업, 원격 VM 보기다. 주소·토큰의
  추가·고치기·지우기는 설정 › 원격 클러스터(admin)에 있다.
- **설정 › 일반**은 업데이트 채널·호스트 종료·HA 용량·텔레메트리·Prometheus·CPU(클러스터 CPU 기준과 숨김 목록) 칸이다. 구독은 따로 탭이다.
- **마지막 탭 기억.** 영역은 마지막으로 본 탭(주소와 쿼리)을 기억한다. 사이드바에서 영역을 누르면 그 탭으로 간다. 상세 화면을
  봤으면 그 탭의 목록을 기억한다. 기억이 없거나 지금 권한으로 볼 수 없는 탭이면 보이는 첫 탭이다. 기억은 브라우저에 있다.
- **이동 경로.** 머리줄 왼쪽에 `영역 › 탭 › 리소스`가 있고 앞 칸은 링크다. 768px보다 좁으면 마지막 둘만 보인다.
- **옛 주소.** 예전 사이드바 26개 메뉴의 주소는 그대로 열린다. 설정으로 옮긴 셋은 넘긴다: `/users` → `/settings/users`,
  `/realms` → `/settings/realms`, `/tokens` → `/settings/tokens`. 쿼리와 해시는 지킨다(`/tokens?x=1#a` →
  `/settings/tokens?x=1#a`). 영역 주소 `/infra`·`/protect`·`/activity`는 기억한 탭으로 넘긴다.

## 명령 팔레트

`⌘K`(맥)·`Ctrl+K` 또는 머리줄의 검색 상자로 연다. 메뉴를 거치지 않고 모든 화면, 리소스, 동작으로 간다. 새 API를 부르지 않고
화면이 이미 받은 목록에서 찾는다.

- **찾는 것.** VM·노드·스토리지 풀·볼륨·네트워크·보안 그룹·백업 작업·HA 그룹의 이름, 모든 탭과 보기("인프라 › 노드"),
  명령(만들기, 테마, 밀도, 단축키 도움말, 로그아웃), 즐겨찾기와 최근 항목. 빈 칸으로 열면 즐겨찾기·최근·이동·명령만 보이고
  리소스는 치면 보인다.
- **순위.** 정확히 같음 > 앞부분 > 낱말 앞부분 > 가운데 부분이다. 점수가 같으면 즐겨찾기와 최근 것이 앞이다. 종류마다
  8개까지 보인다. 여러 낱말(`create pool`)은 통째로 맞지 않으면 낱말마다 맞아야 한다.
- **IP 찾기.** IP를 치면 노드(API 주소), VM의 cloud-init 고정 IP와 NIC MAC, 이미 게스트 정보를 받은 VM의 게스트 IP를
  앞부분부터 맞춘다. `10.0.0.0/24`처럼 CIDR을 치면 그 범위 안의 VM 주소를 찾는다.
- **동작.** `{동사} {VM} [to {노드}]` 꼴이고 동사는 앞이나 뒤에 둔다. 한국어 별칭과 조사(`을`·`를`, `로`·`으로`·`에`)도 받는다.

  | 동사 | 별칭(예) |
  |---|---|
  | start | 시작, 켜기, 켜 |
  | stop | 정지, 끄기, 종료 |
  | reboot | 재시작, 재부팅 |
  | force-stop | 강제 정지, 강제종료, kill |
  | migrate | 옮기기, 이동, 마이그레이션, move |
  | snapshot | 스냅샷 |
  | console | 콘솔 |
  | open | 열기, 보기, go |

  예: `migrate web to node2`, `web을 node2로 옮겨`, `stop db`, `콘솔 web`. VM은 이름 앞부분으로, 노드도 이름 앞부분으로 찾는다.
- **확인.** 팔레트가 바로 하는 것은 확인이 필요 없는 시작·콘솔·열기뿐이고, 시작은 친 이름이 VM 이름과 **정확히 같을 때만**
  바로 한다(`start db`에 `db`가 없고 `db-prod`만 있으면 "db-prod을(를) 시작할까요?"를 묻는다). 정지·재시작·강제 정지·옮기기·스냅샷은
  VM 화면과 **같은 확인 대화상자**를 미리 채워 연다(옮기기는 대상 노드를 골라 둔다. 그 노드가 그 사이 후보에서 빠졌으면 다른 노드를
  골랐다고 알린다). 한글 입력을 끝내는 `Enter`는 항목을 실행하지 않는다. 권한이나 지금 상태로 할 수 없는 동작은 흐리게 이유와
  함께 보인다. viewer에게는 동작 항목이 없고 이동과 열기만 있다.
- **키.** `↑`·`↓` 고르기, `Enter` 실행, `⌘Enter`·`Ctrl+Enter` 새 탭에서 열기, VM 위에서 `Tab`은 그 VM의 동작 묶음 보기,
  `Esc` 닫기(연 단추로 포커스가 돌아간다).

## 머리줄

왼쪽부터 이동 경로, 검색 상자, **+ 만들기**, 클러스터 전환, 종, 실시간 표시, 사용자 메뉴다.

- **검색 상자**는 팔레트를 연다(`⌘K` 표시). 1024px보다 좁으면 아이콘 단추다.
- **+ 만들기**(`c`)는 가상 머신·VM 가져오기(OVA 올리기)·스토리지 풀·네트워크·백업 작업·ISO 올리기 메뉴다. 쓰기 권한이 있는
  것만(루트든 어느 폴더든) 보이고 viewer에게는 단추가 없다. VM 만들기는 권한 있는 폴더를 골라 두고, 노드 목록을 읽지 못하는 폴더
  사용자에게는 노드 칸을 숨긴다(머신 종류는 서버가 고른다). VM은 `/vms/-new`로 가고 나머지는 그 화면을 `?create=1`로 열어 만들기 대화상자를
  띄운다(이 주소를 북마크해도 된다).
- **클러스터 전환**(1024px 이상)은 이 클러스터와 원격 클러스터 목록이다. 원격을 고르면 `/remotes/{이름}`(원격 VM 보기)으로,
  이 클러스터를 고르면 홈으로 간다. 원격 목록은 메뉴를 열 때만 읽는다.
- **종**은 [알림 센터](#알림-센터)를 연다.
- **사용자 메뉴**에 언어(한국어·English), 테마(시스템·밝게·어둡게), 밀도(편안하게·촘촘하게), 단축키, 내 비밀번호 변경,
  로그아웃이 있다.
- 실시간 연결(`/watch`)이 끊기면 본문 위에 "실시간 연결이 끊겼습니다 – 다시 연결하는 중입니다" 띠가 보인다.

## 알림 센터

머리줄 종을 누르거나 `Shift+N`으로 오른쪽 서랍을 연다. 종의 숫자는 **끝나지 않은 작업 + 울리는 critical·warning 경보**다
(info 경보는 세지 않는다). 경보가 울리면 숫자가 빨강, 작업뿐이면 강조색이다.

- **진행 중**: 도는 작업과 진행률(옮긴 바이트와 단계).
- **최근**: 끝난 작업 10개와 실패 이유. 실패한 VM 시작·정지·강제 정지·재시작에는 **다시 하기**가 있고(시작은 바로 다시 보내고,
  정지·재시작·강제 정지는 다른 곳과 같은 확인을 거친다. 지금 상태로 할 수 없으면 흐리고 이유, 그 뒤 같은 VM에 새 전원 작업이
  있었으면 단추가 없다), 실패한 백업 작업 실행에는 **작업 다시 실행**이 있다. 파라미터가 필요한
  작업(옮기기 등)은 다시 하기가 없고 설명 자체가 대상 화면 링크다(VM 스냅샷 작업 → 그 VM의 스냅샷 탭 등).
- **경보**: 울리는 경보(심각도 순)와 대상 링크.
- 아래에 "모든 작업 보기"(활동 › 작업)와 "모든 경보 보기"(활동 › 경보)가 있다.
- 서랍이 열려 있으면 작업 성공 알림을 띄우지 않는다. 실패 알림에는 서랍을 여는 "보기"가 있다. 경보는 화면 알림으로 띄우지
  않는다. VM 정지·강제 정지 성공 알림에는 10초 동안 **다시 켜기**가 있다.

## 목록

VM·노드·스토리지 풀·볼륨·백업·작업·감사 로그 목록은 같은 표를 쓴다.

- **주소에 남는 거름.** 검색(`?q=`), 정렬(`?sort=memory`, 내림은 `?sort=-memory`), 거름(VM `phase`·`node`·`template`, 볼륨
  `iso`)이 주소에 남는다. 그래서 거른 목록을 링크로 나눌 수 있다(예: `/vms?phase=failed&node=node2`). 작업·감사 로그는
  페이지로 나뉘어 검색·정렬이 없다.
- **저장 보기.** "보기" 메뉴에서 지금 검색·정렬·거름에 이름을 붙여 저장하고 다시 고른다. VM 목록에는 기본 보기
  실행 중·실패·이 노드(접속한 노드)가 있다. 저장 보기를 지우면 10초 동안 되돌릴 수 있다.
- **열.** "열" 메뉴에서 열을 숨기고 보인다(순서는 바꾸지 않는다). 좁은 화면에서는 덜 중요한 열이 저절로 숨는다.
- **밀도.** 사용자 메뉴의 밀도가 모든 표·단추 높이를 바꾼다(편안하게 40px 행, 촘촘하게 32px 행).
- **일괄 동작(VM 목록).** 체크박스로 고르고 `Shift`+누르기로 범위를 고른다. 거름이 바뀌어 보이지 않게 된 행은 고르기에서 빠진다.
  아래 막대에 시작·정지·강제 정지·재시작·스냅샷·옮기기·지우기가 "정지 (가능 3, 불가 1)"처럼 보이고, 가능한 VM이 없으면 막힌다.
  - 확인 대화상자가 영향받는 VM 표(이름·노드·상태, 불가면 이유)를 지금 상태로 보인다(열린 동안 누가 VM을 켜면 바로 바뀐다).
    **지우기와 강제 정지는 실제로 할 수(가능 수)를 입력해야** 한다("고른 VM 3개 중 2개에 합니다"). 그 수가 바뀌면 다시 입력한다.
  - 스냅샷 이름은 `bulk-YYYYMMDD-HHMM`이고 디스크만 담는다. 옮기기는 대상 노드 하나를 고르고 VM마다 갈 수 있는지 미리 보인다.
    스냅샷이 있는 VM은 일괄 지우기에서 빠진다(VM 화면에서 스냅샷과 함께 지운다).
  - 요청은 4개씩 동시에 보내고 대화상자의 결과 칸에 VM마다 요청함·성공·실패(이유)를 보인다. 대화상자를 닫아도 이어지고, 끝나면
    알림 하나("정지: 8개 중 7개 성공, 1개 실패.")로 묶는다. 실패가 있으면 알림이 남고 "작업 보기"가 있다.
- **미리 보기 서랍.** VM·노드 목록에서 행의 눈 아이콘이나 `Space`로 오른쪽 서랍을 연다. VM은 노드·vCPU·메모리·고정 IP와
  시작·정지(확인)·콘솔·열기, 노드는 상태·주소·버전·CPU·메모리·VM 수와 열기다. 서랍이 열린 채 `j`·`k`로 행을 옮기면 내용이 바뀐다.
- **목록 키.** `j`·`k` 행 옮기기, `x` 고르기, `Space` 미리 보기, `Enter` 상세 열기, `/` 검색 상자. 입력 칸·메뉴·대화상자
  안에서는 받지 않는다.
- **즐겨찾기 ★.** VM·노드 상세 머리, 스토리지 풀 행, 미리 보기 서랍에 있다. 즐겨찾기는 홈과 팔레트 맨 위에 모인다. 빼면 10초
  동안 되돌릴 수 있다. VM·노드·보안 그룹 상세를 열면 최근 항목(20개)에 들어간다.

## 상세 화면과 파괴 동작

- **상세 머리.** VM·노드·보안 그룹·가져오기·원격 상세는 이름, 상태, ★, 주 동작 단추, 나머지 동작의 **⋯ 메뉴**("{이름} 동작"),
  그 아래 요약 카드 줄이다. 그 아래는 `?tab=` 탭이다.
  - **VM**: 단추는 시작·정지·콘솔 열기·마이그레이션이다. 재시작·강제 정지·편집·복제(템플릿이면 배포)·템플릿으로 바꾸기(VM으로
    되돌리기)·삭제는 ⋯ 메뉴에 있다. 할 수 없는 항목은 막힌 채 이유를 읽어 준다. 요약 카드는 노드·vCPU·메모리·고정 IP다.
  - **노드**: 단추는 유지보수·비우기이고 업데이트·인터페이스·디스크·레이블·펜싱·얼림 풀기·지우기는 ⋯ 메뉴에 있다(노드 목록의 행
    메뉴와 같다). 요약 카드는 API 주소·CPU·메모리·VM 수다.
- **바뀐 값 강조.** 실시간으로 상태가 바뀐 칩은 잠깐 테두리가 빛난다.
- **영향 목록.** 되돌릴 수 없는 동작의 확인 대화상자는 무엇이 함께 영향받는지 보인다: VM 삭제(남는 디스크 볼륨·스냅샷·백업 수),
  네트워크 삭제(쓰는 VM), 풀 삭제(안의 볼륨·백업), 노드 지우기(배정된 VM).
- **입력 확인.** 하나를 지울 때는 이름을, 여럿(일괄 지우기·강제 정지)은 고른 수를 입력해야 확인 단추가 열린다. 기본 포커스는
  취소이고 위험 단추는 오른쪽 끝이다.
- **되돌리기**(10초 알림의 "되돌리기"): 즐겨찾기 빼기, 저장 보기 지우기, 노드 레이블 저장, 보안 그룹 저장. 레이블·보안 그룹은 그
  사이 다른 곳에서 바뀌었으면 되돌리지 않고 알린다. 서버 작업이 지운 것(VM·볼륨 등)은 되돌리지 못한다.
- 노드 유지보수 켜기·끄기와 레이블은 서버 응답 전에 화면에 먼저 보이고, 실패하면 되돌린다.

## 홈과 첫 걸음

홈은 위에서부터 첫 걸음 → 건강 띠(노드 온라인, VM 실행·정지·실패 — 실패 수를 누르면 `/vms?phase=failed`, 울리는 경보, 리더)
→ 혼합 버전 경고 → 경보·용량·풀 사용률 → 클러스터 부하 차트 → 노드 부하·상위 VM → 최근 작업·즐겨찾기다. 용량은 온라인이고
위트니스가 아닌 노드의 코어·메모리 가운데 도는 VM에 나눠 준 몫이고 85 %를 넘으면 경고색이다. 즐겨찾기 줄에는 VM 전원 단추가
있다. 구독 안내는 제목 아래에 보인다. 차트·위젯은 [클러스터 운영](cluster.md#웹-화면)에 있다.

**첫 걸음**은 VM이 하나도 없고 VM을 만들 권한이 있을 때 홈과 VM 목록 위에 보인다: ① 스토리지 풀 만들기 → ② ISO 올리기 또는
이미지 받기 → ③ VM 만들기. 끝난 단계는 ✓이고 각 단계는 그 화면의 만들기로 간다. VM이 생기면 카드째 사라진다.

## 마법사

- **VM 만들기.** 폼 위에서 프리셋을 고른다.
  - **빈 VM**: 기본값.
  - **Linux 서버**: 코어 2개, 2048 MiB, 게스트 에이전트와 cloud-init 켬.
  - **Windows 11**: Secure Boot UEFI, TPM 2.0, SATA 디스크, e1000e(옛 "Windows 11용으로 채우기" 단추를 대신한다).
  - **템플릿에서**: 폼 대신 템플릿 목록을 보이고 템플릿 화면과 같은 배포 창을 연다.

  프리셋을 바꿔도 이름과 이미 고른 디스크·NIC·CD-ROM은 남는다. 넓은 화면(1024px 이상)에서는 왼쪽 단계 목록(일반·디스크·
  네트워크·CD/DVD·부팅 순서·보안·게스트 에이전트·cloud-init·스냅샷·복제·검토)이 그 절로 옮기고, 오류가 있는 단계에 표시와 수를
  보인다. 보내기가 실패하면 오류가 있는 첫 단계로 간다. 절은 모두 펼쳐 둔다. 맨 아래 **검토**가 보낼 값을 요약한다.
- **클러스터 합류**(인프라 › 노드 › 클러스터). 합류 토큰 대화상자와 명령 대화상자에 단계 표시(1 토큰 만들기 · 2 새 노드에서 명령
  실행 · 3 노드 기다리기)가 있다. 명령을 복사하면 3단계가 되고, 새 노드가 목록에 나타나면 "{이름}이(가) 클러스터에
  합류했습니다."를 알린다. 기다리지 않고 "완료"로 닫아도 된다.
- **Ceph**(인프라 › Ceph). Ceph이 없으면 빈 상태 안내가 보이고 admin은 "Ceph 설정 시작"으로 설정 마법사를 연다
  ([스토리지](storage.md)).

## 휴대폰과 당직 보기

- **1280px 이상**: 펼친 사이드바(224px). **768~1279px**: 아이콘 레일(56px, 마우스·포커스에 이름). `[`나 사이드바 아래 단추로
  접고 펴며 브라우저가 기억한다. **768px 미만**: 사이드바 대신 머리줄 ☰가 영역 목록 서랍을 열고 영역 탭은 가로로 스크롤한다.
- **당직 보기(768px 미만).** 목록은 카드(이름, 상태, 노드, 동작)가 되고 VM 카드에 전원 단추(꺼졌으면 시작은 바로, 켜져 있으면
  정지 확인, 40px)가 있다. 홈은 경보 → 건강 띠 → 즐겨찾기(전원 단추) → 용량 → 풀 → 최근 작업 순이고 차트·노드 부하·상위 VM은
  그리지 않는다. 밀도는 늘 편안하게다.
- VM 만들기·편집과 콘솔은 "이 화면은 넓은 화면에서 쓰기 좋습니다" 안내가 보인다(쓸 수는 있다).

## NUMA 화면

NUMA·전용 CPU·hugepages(계획 64)도 사이드바 항목을 더하지 않고 아래 화면 안에 있다. 쓰는 법은 [NUMA·전용
CPU·hugepages](vms.md#numa전용-cpuhugepages)·[호스트 준비](cluster.md#호스트-준비-예약전용-cpu와-hugepages).

| 화면 | 있는 것 |
|---|---|
| VM 만들기·편집 › 일반 | 접힌 "CPU 배치와 NUMA": 소켓(1·2·3·4·6·8·12·16), CPU 정책(공유·전용), 전용이면 SMT 스레드(형제 먼저·코어 독점·형제 짝 필수)와 에뮬레이터 스레드(공유 CPU에서·전용 CPU 하나 더), 게스트 NUMA 노드(없음·자동·개수 — 소켓 수의 약수만 — ·노드마다 직접 표), 호스트 메모리 묶기(기본·엄격·선호), Hugepages(없음·2 MiB·1 GiB·아무것 — 메모리 핫플러그 VM은 2 MiB). 소켓은 vCPU 수와 vCPU 상한을 모두 나누는 수만 고른다. 노드마다 직접 표의 메모리는 켤 때 나눔이라 메모리 상한이 있는 VM은 합이 메모리 이하이고, 남는 메모리는 노드마다 고르게 더해진다(실행 중 메모리를 늘려도 표를 고치지 않는다). `vm.dedicated`가 없으면 전용·hugepages를 새로 고를 수 없고 까닭(만들 때는 고른 폴더, 고칠 때는 그 VM에서 본다). "이 VM의 전용 CPU·hugepages가 들어갈 노드"(어림), 실행 중이면 "Orbivisor가 전원을 껐다 켤 때 적용" |

## SDN 화면

SDN(OVN, 계획 65~67)도 사이드바 항목을 더하지 않는다. **인프라 › 네트워크** 탭의 보기는 네트워크 | 네트워크 폴더 | **라우터**
(`/routers`) | **유동 IP**(`/floating-ips`) | **부하 분산**(`/load-balancers`) | **토폴로지**(`/networks/topology`) | **SDN**(`/sdn`)이고,
SDN 보기는 루트 `cluster.read`가 있을 때만 보인다(폴더 사용자에게는 감춤). 쓰는 법은 [SDN (OVN)](network.md#sdn-ovn). 계획 67부터
라우터·유동 IP·부하 분산기·옮기기는 **watch**다: 사건이 오면 그 화면의 질의를 1초 모아 다시 읽는다(라우터 사건은 라우터·유동 IP·LB·주소
표·토폴로지를, 네트워크·VM 사건은 토폴로지와 유동 IP 상태를 — 다시 붙으면 그 질의도 다시 읽음). 사건이 없는 OVN 상태만 30초마다 읽는다:
연 라우터 서랍의 지금 게이트웨이, LB 목록의 멤버 건강, 토폴로지의 게이트웨이 주인·멤버 건강. 라우터·LB 보기는 `?open=<id>`로 그 서랍을 연
채 열린다(토폴로지와 경보 대상 링크가 쓴다).

| VM 만들기·편집 › 네트워크(QoS, 계획 67) | NIC 줄의 접는 칸 "QoS": 보내기·받기 Mbit/s, 버스트 kbit, DSCP(0~63). 단순 NIC는 DSCP 칸이 막히고 까닭("SDN 네트워크만 됩니다."), `user` 네트워크 NIC에는 칸이 없다. 켜진 VM에서도 바꾼다(서버가 곧바로 적용). 폼 검사는 서버와 같다(속도 없이 버스트만, 범위) |
| VM 상세 › 하드웨어(계획 67) | QoS가 있는 NIC가 있으면 "QoS" 칸의 칩(`↑ 100 Mbit/s`·`↓ 200 Mbit/s`·`DSCP 46`). 유동 IP 칸의 **"떼기"**(VM의 `vm.config` 또는 유동 IP의 `network.config` — 유동 IP를 읽을 수 없으면 행이 없다) |
| 네트워크 서랍(계획 67) | 라우터 인터페이스인 네트워크에 **"라우터에서 떼기"**(그 네트워크의 `network.config`, 라우터 권한 없이 — 라우터를 읽을 수 없으면 "볼 수 없는 라우터"로). IP 주소 표의 `lb-vip`·`lb-monitor` 행은 LB 보기로 가는 링크. LB가 VIP를 둔 네트워크의 떼기는 서버의 409 `lb_in_use` 문장 |
| 네트워크 폴더 상세(계획 67) | 할당량 대화상자와 사용량 막대에 네트워크·부하 분산기, 내용 탭에 부하 분산기(끌어 놓기·"폴더로 옮기기") |

## 백업 저장소 화면

백업 저장소(계획 68 — 중복 제거·암호화·S3·검증·라이브 복원)도 사이드바 항목을 더하지 않는다. **보호 › 백업 저장소** 탭
(`/backup-stores`)이고, 저장소를 읽을 수 있을 때(루트 `system.read`) 보인다. 화면 코드는 늦게 읽는 조각(`web/src/backupStores/`)이다.
저장소 목록은 비밀을 뺀 보기라 watch 사건이 오면 질의를 다시 읽는다. 쓰는 법은 [백업 저장소](backup.md#백업-저장소중복-제거암호화s3).

| 화면 | 보이는 것 |
|---|---|
| 보호 › 백업 저장소 › 목록 | 이름, 백엔드(풀 이름 / S3 버킷·접두사), 암호화 배지와 지문, 읽기 전용, 스냅샷 수, 저장 크기, dedup 배율, 마지막 GC·검증(깨진 청크 수), 상태. 빈 화면은 "저장소 만들기" 안내(axe 시험). `?open=<id>`로 서랍을 연다(경보의 저장소 링크가 씀) |
| 만들기 마법사 | ① **백엔드**: 백업 풀 고르기 / S3(끝점 `https://`만 — 시험용 `http`는 CLI만, 리전, 버킷, 접두사, 경로 방식, 접근 키·비밀 키, CA PEM), "읽기 전용으로 붙이기"(다른 클러스터의 저장소 — 풀 안이면 저장소 id). ② **암호화**: 끔 / 새 키 / 복구 키로 열기 / escrow 암호 문구로 열기, 새 키·복구 키면 "저장소 안에도 키 보관(escrow)" 암호 문구(8자 이상) — 읽기 전용이면 새 키 없음. ③ **일정**: GC(기본 매일 05:00 UTC), 예약 검증(기본 일요일 06:00, 다시 검증 날 수, full·metadata, 새 백업 곧바로 검증). ④ **복구 키**(새 키일 때만): 키 글·QR·복사·인쇄 창, **"안전한 곳에 보관했습니다"를 누르기 전에는 Esc·닫기가 막히고** 경고가 뜬다 |
| 만들기 뒤 연결 확인 | 만들기 전에 저장소에 닿아 보는 API는 없다. 대신 만들기 요청이 API 노드에서 미리 읽어 본 오류(`store_key_required`·`store_key_mismatch`·`store_owned_elsewhere`·`store_target_in_use`)를 마법사 위에 화면 말로 보이고, 만든 뒤에는 서랍의 **"연결 확인"**(`actions/check` — 이 노드의 결과와 노드마다 보고한 닿음·까닭)으로 본다. 초기화 Task가 끝날 때까지 상태는 "초기화 중" |
| 저장소 서랍 | 설정(일정·동시 요청 수·S3 자격 증명·CA 바꾸기 — 백엔드·암호화는 바꿀 수 없음), **키 카드**(지문, escrow 쓰기, 복구 키 다시 보기 — admin, 확인 대화상자, 감사에 남음), 노드별 닿음 표, 마지막 GC(지운 청크·바이트)·검증(깨진 청크), "지금 GC"·"지금 검증", 읽기 전용이면 "scan"·"넘겨받기"(하트비트가 새로우면 force 확인). operator 이하에게는 쓰기 단추를 감춘다 |
| 보호 › 백업 › 표 | "풀" 열이 **"대상"**(풀 이름 / 저장소 이름 + "백업 저장소")이 되고 **"검증"** 열(확인됨·깨진 청크 n개·안 함, 풀 백업은 "—"). 저장소 백업의 크기는 "새 데이터 / 논리", 종류는 "청크" + base 링크 + 전체로 읽은 까닭. 동작: 저장소 백업 "지금 검증"·"저장소로 복사"(다른 준비된 쓰기 저장소가 있을 때), 풀 백업 "저장소로 옮기기" |
| 백업 만들기(VM 상세 › 백업, 지금 백업) | 저장소가 있으면 대상 고르기(백업 풀 \| 저장소) |
| 복원 대화상자 | **"라이브 복원(바로 켬)"** 스위치 — 새 VM 폴더의 `vm.power`가 어딘가 있을 때만. 켜면 설명(곧바로 켜고 뒤에서 옮김, 끝나기 전 막히는 동작, HA는 끝난 뒤, 저장소에 닿는 노드에서). 노드 칸은 없다(서버가 고름) |
| VM 상세 머리 띠 | 라이브 복원 중인 VM: 단계 칩·진행 막대(`done_bytes`/`total_bytes`)·멈춤·실패 까닭, **취소**(VM 이름을 써서 확인 → `live-restore/cancel {discard: true}`, 새 VM의 `vm.delete`). 정지·지우기·옮기기 단추는 까닭 "라이브 복원 중"과 함께 막히고(강제 정지는 됨), VM 백업 탭의 "지금 백업"도 막힌다. 스냅샷·디스크 바꾸기는 서버의 409 `vm_restoring` 문장 |
| 보호 › 백업 작업 폼 | 저장소가 있으면 "대상"(풀 \| 저장소), 저장소 작업이면 "다른 저장소로 복사"(저장소·사본 보존 — 비면 작업의 보존). 풀 ↔ 저장소로 바꾸면 그 뒤의 백업만 바뀐다 |
| 경보·할당량·작업 | 경보 규칙 조건의 "백업 저장소" 묶음 둘(검증 실패·저장소에 닿지 않음 — 노드·VM 거르기 없음), 경보 대상 `backup_store`는 저장소 서랍으로. 폴더 할당량 대화상자의 "백업(GiB)"과 사용량 막대. 새 작업 일곱(저장소 초기화·GC·검증·scan, 옮기기, 복사, 라이브 복원)의 문구와 대상 링크 |

## 접근성과 모양

- **테마**: 시스템(기본)·밝게·어둡게. **밀도**: 편안하게(기본)·촘촘하게. 둘 다 사용자 메뉴에 있고 브라우저에 남는다.
- **움직임 줄이기**: 운영체제의 "동작 줄이기"(`prefers-reduced-motion`)를 켜면 서랍 미끄러짐, 스켈레톤 맥박, 바뀐 값 강조 같은
  움직임을 끈다.
- 상태는 색만으로 알리지 않고 글과 점(칩)으로 함께 보인다. 글·상태 칩의 대비는 4.5:1, 포커스 링·차트 선은 3:1 이상이다(시험이
  색 토큰을 확인한다).
- 첫 Tab에 "본문으로 건너뛰기"가 있다. 화면이 바뀌면 포커스가 제목으로 가고 화면 읽기 프로그램이 이동 경로를 읽는다. 대화상자·
  서랍·팔레트는 포커스를 가두고 닫으면 연 단추로 돌아간다. 표의 체크박스·정렬 머리·일괄 막대에는 이름과 상태가 있다.
- 화면 글은 한국어와 영어 모두 있다.

## 한계

- **즐겨찾기·최근 항목·저장 보기·열 설정·마지막 탭·레일 접기는 그 브라우저에만 있다**(localStorage, 사용자마다 따로). 다른
  브라우저나 기기로 옮겨 가지 않고, 브라우저 저장소를 지우면 사라진다.
- **팔레트의 IP 찾기는 게스트 정보를 받은 VM만** DHCP 주소를 찾는다. 게스트 IP를 모든 VM에서 미리 모으지 않으므로, 그 브라우저에서
  VM 상세의 게스트 탭(또는 게스트 정보가 보이는 화면)을 연 VM만 맞는다. cloud-init 고정 IP·MAC·노드 주소는 늘 찾는다.
- 다시 하기는 파라미터가 필요 없는 작업(VM 전원 넷, 백업 작업 실행)만 된다. 작업에 요청 파라미터가 남지 않아서다.
- 일괄 동작은 VM 목록에만, 미리 보기 서랍은 VM·노드 목록에만 있다. 열 순서 바꾸기, 표 CSV 내보내기, 셀 안 편집, 사용자 정의
  대시보드, 여러 클러스터를 한 표로 보기는 없다.
- 오른쪽에서 왼쪽으로 쓰는 언어와 고대비 테마는 없다.
- 폴더 트리는 가상 스크롤이 없고(펼친 노드만 그린다) 템플릿 탭에는 트리가 없다. 끌어 놓기는 확인 없이 바로 옮긴다. 토큰 범위를
  정하는 화면은 없다(CLI). 볼륨·ISO·이미지·가져오기·백업 복원·템플릿 배포 단추는 그 권한이 어디에든 있으면 보이고, 그 객체에서
  되는지는 서버가 정한다.
- CPU 모델 목록에는 별칭(`Icelake-Server`)이 없다 — 버전 모델만 고른다(별칭 이름으로 찾으면 버전 모델이 나온다). 노드 목록에 "CPU
  모델" 열은 없고(노드마다 따로 읽어야 해서) 노드 상세에서 본다. CPU 화면에서 이 안내 문서로 가는 도움말 링크는 없다.
- 노드 "NUMA 토폴로지" 격자에는 소켓 층이 없다(토폴로지가 CPU마다 소켓 번호를 갖지 않아 호스트 노드 › L3 › 코어 › 스레드로
  그린다). VM 폼의 "들어갈 노드"는 노드마다 남은 전용 CPU·hugepages 수만 보는 어림이고(`isolate`의 형제는 빼지 않는다), 노드마다
  직접 나누는 표는 VM 폼에만 있다(복제·배포·가져오기는 노드 수까지).
- 주소가 있는 NIC의 빠진 체계를 채우는 단추는 없다(CLI `orbivisorctl network ips NAME --fill` — 주소가 없는 NIC는 서브넷을 더할 때
  서버가 채운다). "10초 안에 포트가 바인딩되지 않음"은 orbivisord 로그에만 있고 VM 화면에 없다.
- 게이트웨이 표에 chassis 상태 칸이 없다(SDN 보기의 chassis 표). 유동 IP 붙이기는 유동 IP 보기에만 있다(떼기는 VM 상세에도). 유동 IP를
  읽을 수 없는 VM 주인은 화면에서 그 유동 IP를 찾을 길이 없다(CLI·API로 키를 알아야 함).
- 토폴로지는 네트워크 200·VM 2000이면 SVG 원소가 약 11,400개라 느려질 수 있다(폴더 거르기·VM 감추기를 권하는 띠). 그림에서 끌어 놓아
  잇기(라우터 인터페이스 만들기 따위)는 없다. 옮기기 마법사는 VM마다 다른 방식을 고르지 않는다.
  SDN NIC의 보안 그룹 고르기는 기능 판정 없이 늘 열려 있다(섞인 클러스터는 저장할 때 409).
- 백업 저장소 마법사에는 **만들기 전 연결 확인이 없다**(만든 뒤 서랍의 "연결 확인" — 미리 볼 수 있는 키·주인 오류는 만들기 요청이
  알림). S3 끝점은 `https://`만 받는다(`insecure_http`는 CLI). 복원 대화상자에서 라이브 복원 노드를 고르지 못한다. 풀 백업에는 검증
  배지가 없다(풀 백업 검증 없음).
